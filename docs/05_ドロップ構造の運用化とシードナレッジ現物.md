# 05. ドロップ構造の運用化とシードナレッジ現物（v0）

**元データ**: 別スレ分析（CSV×DX投稿ボックス 2025-2026 全1,680件 / ドロップ理由535件精読 / テーマ研究161件分析）。本書はその分析結果を**リスク提案ナビのシードナレッジと製品機能に変換**したもの。分析の原本は統合レポート・別冊・161件分析（Word）を正とする。

---

## 1. 「なぜドロップされるのか」——答えはもう出ている

> **投稿が通る/落ちるを分けているのは課題の重要度ではなく、当社の既存の箱（種目分掌・保険事故の定義・加入経路）に載るかどうか。起案者の力量による棄却は多く見積もって2割、残り8割は受け側の構造。**

つまり「みんな何でドロップか分かってない」のは当然で、**落ちる理由の大半は投稿の中ではなく受け方の側にある**。だから投稿者に「もっと良いアイデアを」と言っても無駄打ちは減らない。減らす方法は2つだけ：①判定の物差しを投稿者に見える化する ②物差しへの適合をAIが投稿時点で診断・補強する。両方とも本製品で機械化できる。

### 判定の物差し＝「生存の文法」4条件（分析が実証済み）
| # | 条件 | 意味 |
|---|---|---|
| a | 既存アセットに載る | cmap・テレマ・DXSP（SparkEye、ウェルガードE等）と接続できる |
| b | 引受判断（UW）に変換されている | 「事故を止める」でなく「引受条件・料率に使える」形になっている |
| c | 当社の支払データで損害が語れる | 支払実績がある領域は損害額を語れる（雪災・雹災が典型） |
| d | 保険料を払う法人・自治体が特定できる | 個人被保険者のままだと「個人分野は検討不可」で落ちる |

### 落ちる構造＝棄却10類型（出現率）
T1 種目・所管の縦割りミスマッチ 42% ／ T2 既存商品・サービスで対応済み 27% ／ T3 重複・過去検討済み 13% ／ T5 保険事故・被保険利益の不成立 10% ／ T6 DX要素の欠如 9% ／ T7 座組・実装主体の不在 9% ／ T4 保険原理との衝突（逆選択・高ロス等）8% ／ T8 制度・認可の壁 7% ／ T9 市場規模不足 6% ／ T10 課題設定の不備 5% ／ T0 理由記載なし（主因10%）

### 壁を越える3手（ドロップの出口は3方向しかない）
**加入経路を変える**（エンベデッド／団体／自治体契約）・**給付形態を変える**（役務提供／パラメトリック）・**引受主体を変える**（業界プール／共同組成）

## 2. 製品機能への変換: 「投稿プリフライト診断」（受信箱の入口AI）

投稿の無駄打ちを入口で止める機能。運営施策1〜9（別冊）のうち機械化可能なものをRPNの受信箱に実装する。**これが「生むエンジン」の前段**になる。

```
投稿（受信箱に1件入る）
  ↓ AI診断（1コール）
  ① 保険原理チェック5問の自動判定
     … 誰が被保険者か／どんな偶然の事故か／損害は誰にいくらか／
        客観トリガーは何か／加入者は予兆を知っているか（逆選択）
  ② 生存文法4条件（a-d）との適合判定＋不足の指摘
  ③ 既存アセット・既存研究との照合（カタログ＋研究中テーマ一覧と突合）
     … T2(27%)・T3(13%)の空振りを投稿前に検知
  ④ 予測される棄却類型（T1〜T10）と、3手（経路/給付/主体）による回避案
  ⑑ 出力: 「このままだと T4(逆選択) で落ちる見込み。自治体契約への
     組み替え案: …。既存のSparkEyeとの差分を明記すれば T2 回避。」
  ↓
  投稿者が補強 → 判定へ（判定側は統制語彙 T0〜T10 で理由を必須選択）
  ↓
  同一テーマ集中は「棄却」でなく関心度スコアに集計（熊58件型の損失防止）
  条件付きドロップは「化ける条件」タグ（技術/制度/座組/データ/市場）で
  棚卸しキューへ → 年次で条件成就をAIがチェック
```

データ設計への反映（13章に追加する）:
- 受信箱シート: `idea_id / 起案G / テーマ / 本文 / 診断結果JSON / 予測類型 / 状態`
- 判定の統制語彙: `drop_type` enum = T1〜T10・T0（自由記述は補足に降格）
- `化ける条件` タグ: `tech / regulation / partner / data / market` ＋ 監視期日

## 3. シード現物v0-1: 判断基準スターター（ナレッジブック「判断基準」シート初期30行）

形式: `基準ID / 類型 / 基準（1行）/ 根拠・出典`。**BID・高ロスプレイの種であり、プリフライト診断の判定辞書**。以下は投稿ボックス判定コーパスから抽出した初版（実装時にナレッジブックへ転記）。

| ID | 類型 | 基準 |
|---|---|---|
| J-01 | 偶然性 | 確実に到来する状態変化（高齢化・後継者不在・価格高騰・移行コスト）は保険化しない。偶発事故（転倒・失踪・置き去り・中断）へ翻訳できれば検討可 |
| J-02 | 偶然性 | 自己都合・自己決定に帰着する損害（乗り過ごし・結婚出産等）は補償対象外 |
| J-03 | 逆選択 | 当事者が予兆を保険会社より先に知る構造（予防型商品全般）は単品販売不可。エンベデッド／団体／自治体プールへの組み替えで検討可 |
| J-04 | 実損てん補 | 定額給付・一時金・見舞金型は「焼け太り」懸念で原則不可。役務提供（代替人材・復旧サービス）への転換で回避可 |
| J-05 | 実損てん補 | パラメトリックは現行認可・システム上不可。制度・統合環境の変化を監視対象とする（旗艦候補: 渇水・天候） |
| J-06 | 大数の法則 | 母集団が小さい新領域（フィジカルAI・核融合等）は汎用商品不可。案件別個別引受または業界プール・共同組成へ |
| J-07 | 大数の法則 | 巨大・相関損害（コンテナ電池火災等）は単社引受不可。基金・再保険・共同組成の座組から検討 |
| J-08 | 被保険利益 | 「対人対物事故が想定できない」無形損害（評判・環境負荷・機会損失）は現行体系で不成立。物理損害への接地か費用・休業への転位が必要 |
| J-09 | 高ロス | 発生率が1に近い事象（ペット高齢疾患等）は保険化しない |
| J-10 | トリガー | 客観・機械可読で測れないトリガー（ストーカー被害等の主観事象）は不成立。公的認定・警報・センサー値へ接地する |
| J-11 | 経路 | 個人が被保険者のままの組成は原則不可（新種）。契約者を法人・自治体・PFに置き換える |
| J-12 | 種目境界 | 複数種目にまたがる課題（熊・災害・置き去り）は種目分解せず、課題単位で束ねて合議（トリアージ）にかける |
| J-13 | 重複 | 既存アセット（cmap/テレマ/SparkEye/ウェルガードE/DXSP群）・MS側商品との重複は不可。ただし「差分」が明記されれば改良提案として検討可 |
| J-14 | 重複 | 研究中テーマ（AI・雪災・落雷等）への個別投稿は統合。投稿者には統合先と関心度を通知（黙殺しない） |
| J-15 | スコープ | DX要素なし・社内業務改善・啓蒙のみはPJスコープ外。補償設計が成立するのにDXが無い案件は「DX探索待ち」タグで保留（機会損失防止） |
| J-16 | 高ロス対応 | （※既存UW暗黙知の言語化枠。エキスパートインタビューで追記——増率/クローズ/縮小特約/ロス改善伴走の選択条件） |

※J-16以降の「引受・プライシング系」基準は各Gヒアリング（docs/04 §5のアジェンダ4）と案件判断台帳から追記していく。投稿ボックス由来の基準は「商品開発の可否」寄りであることに注意（提案・引受の判断基準はこれから貯める）。

## 4. シード現物v0-2: スキーム型ライブラリ候補（初期22件）

形式は13章の型スキーマ（型名/構造/成立条件/適用シグナル/実例/状態）。ここでは一覧のみ。**実績8＋研究テーマ9＋逆張り5**。

### 実績型（会社の既存実績から）
1. **見守りヤモリ型**（検知パートナー×有事補償バンドル）— ASTERRA衛星×水道管。横展開先: WOTA等
2. **セレンディ／めるくーるリンク型**（センサー内蔵機器へのエンベデッド付帯）
3. **NOZOMI型**（OTセキュリティ×サイバー保険）
4. **じゃぱん21連携型**（外部サービスの保険裏受け）
5. **裏受け型・個人向け**（慰謝料・養育費の履行保証）
6. **セーフタウン型**（自治体を契約者とした住民プール化）
7. **行動変容還元型**（テレマ等のデータで予防→保険料還元）
8. **災害対策支援型**（災害時の民間資産公共転用の補償整理）

### 研究テーマ型（投稿分析 S/A/B から）
9. **電池分散発火型**: 予兆検知（SparkEye）×廃棄/充電/保管/輸送の横断引受【S-1】
10. **走行データ地域還元型**: テレマ観測網×自治体の点検・危険地点スクリーニング【S-2】
11. **預かる場包括型**: 保育・介護・送迎の検知デバイス×賠償+傷害+費用パッケージ【S-3】
12. **トリガー型物損なき損失**: 警報・避難・中止の客観トリガー×包括契約【A-4】
13. **鳥獣害地域包括型**: 出没検知×自治体契約×物損・休業・対策費用【A-5】
14. **担い手消失対応型**: 雪の除排雪等、作業の担い手不在リスクの役務+補償【A-6】
15. **スポットワークPF型**: PF契約者のエンベデッド労働セーフティネット（役務給付）【B-7】
16. **事故車EVバッテリー残価型**: 損保が二次電池流通の起点になる【B-8】
17. **AI賠償・AI詐欺型**: 法制・ログ標準化の条件成就を監視【B-9】

### 逆張り型（判定者が「化ける条件」を書き残した案件から）
18. **SMEサプライチェーン診断型**: 可視化SaaSの診断データでCBIを引受可能にする
19. **群集事故エンベデッド型**: 混雑可視化SaaS×イベント傷害（組み手候補は判定コメントに既出）
20. **高年齢労働者DX細分型**: ウェアラブル細分で「保険料が高すぎる」を直接解く
21. **認証ドライブ型**: 無資格役務に保険会社が認証基準を提供し料率優遇で制度を駆動
22. **詐欺検知連動型**: 通信・金融への自動付帯で個人分野の壁を回避

## 5. 追加分析（第2弾・第3弾）からのシード追補

### 5.1 裏受けパートナー候補8社 → 「適用先候補」シートの初期データ現物（docs/04 資産8）
第2弾分析が、選定基準（①社内ニーズ実証 ②既存商品・提携なし ③客観トリガー定義可 ④他損保の空きを明示）つきで8社を特定済み。**トリガー案まで書かれているため、そのまま型ライブラリの「適用先」行になる**：
スマート修繕（修繕見積査定×マンション総合）／クラッソーネ（特定空家の行政処分をトリガーに条文化可）／ハコベル・CBcloud（緊急配送×物流。改正物流効率化法が追い風）／ウェザーニューズ（降雹アラート×実費補償型＝他損保は定額給付のみで空白）／日本カーシェアリング協会（全損認定→現物給付で代車費用圧縮）／SOZOW・フローレンス（文科省の不登校定義・いじめ重大事態認定という法定トリガー）／メンタルヘルステクノロジーズ（労安法の高ストレス判定トリガー）／メディフォン（医療機関側を被保険者とする外国人受入費用保険）。
また「裏受け成立条件4つ」（委員会コメント11件から抽出）は判断基準スターターに J-17〜J-20 として追記する。

### 5.2 法改正・市況変化による復活候補 → 「条件付きドロップ棚卸しキュー」の初期データ現物
第2弾第3部が復活候補を優先順で特定済み。§2の「化ける条件」タグ運用（技術/制度/座組/データ/市場）の初期投入データとしてそのまま使う。

### 5.3 掛け合わせ分析（第3弾）＝「生むエンジン」の手動実証
第3弾は、全2,472件から**手段提示型795件の「機構」を抽出してライブラリ化し、別領域の未解決リスクに掛け合わせて24案（うちS格付9案）を組成**した。これはまさに本製品「生むエンジン」のアルゴリズムを人力＋AIで一周回した実証であり、含意は3つ：
1. **機構ライブラリ（795件）は型ライブラリの下位素材**としてナレッジブックに保持する（機構=部品、型=完成品）
2. 掛け合わせの発見「**器（加入経路・被保険者の置き方）がすべてを決める**」は生存文法(d)と同一の結論——プリフライト診断・型生成プロンプトの中心制約にする
3. S格付9案（PF契約者型保証×労働データ、公的統計トリガー×段階補償、AIカメラ検知×ケーブル盗難、等）は型候補23〜31として型ライブラリに追加登録する

## 6. 運営側への含意（PJ・部長報告に載せるべき1枚）

- 投稿ボックス2年分の結論: **「発想力不足」ではなく「受け側の構造」が8割**。よって次の一手は投稿の呼びかけ強化ではなく、①課題単位トリアージ ②プリフライト診断 ③統制語彙 ④条件付きドロップの棚卸し ⑤通りやすさの事前開示（詳細9施策は別冊）
- リスク提案ナビの受信箱はこの5つを機械として実装する——**投稿ボックスの後継ではなく、投稿ボックスが本来やりたかったことの実装**
- 保険で解けない本物の課題（偶然性欠如系）はインターリスク総研・保険外事業への正式ルーティングを作る（毎年ドロップし続ける消耗を止める）
