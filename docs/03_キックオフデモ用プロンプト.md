# キックオフデモ用プロンプト（Gemini案 改良版）

**用途**: 9月キックオフでの30秒ライブデモ（春華堂の例）。社内AIチャットまたはOpenAI APIどちらでも使用可。
**位置づけ**: これはPhase 0のデモ素材。本番プロダクト（リスク提案ナビ）はdocs/02の多段パイプライン。デモの場では「プロンプトの型だけでもここまで出る。本番はナレッジと繋いでさらに上を狙う」と説明する。

## Gemini原案からの改良点

| 改良 | 理由 |
|---|---|
| リスク分類を4→6カテゴリに拡張（サイバー・情報 / 経営・戦略を追加） | 現代の提案で欠かせない領域。特にサイバーは中堅企業への提案の入り口になりやすい |
| 各リスクに「根拠（入力テキストのどの記述から導いたか）」を必須化 | 一般論の垂れ流しを防ぎ、「御社を調べてきた」感を担保 |
| 「わからないことは推測で埋めず要確認とする」規律を追加 | 幻覚防止。かつ要確認事項がそのままヒアリング項目になる |
| 出力に「初回訪問ヒアリングシート」を追加 | 提案書だけでなく商談の質を上げる。デモの意外性ポイント |
| 提案は「実在サービスと紐づけたい」旨を明示し、無根拠なサービス名の創作を禁止 | 実在しないメニューを幻覚するのが最大の業務リスク |
| スライド骨子を3→5枚に（事業理解・リスクマップ・事例・支援メニュー・次のステップ） | 実際の初回訪問の構成に合わせた |

## プロンプト本文（コピペ用）

```
# 役割
あなたは大手損害保険グループの経験豊富なリスクコンサルタントです。企業の公開情報から潜在リスクを分析し、初回訪問用の提案骨子を作成します。

# 厳守する規律
- 分析・提案は、下記【企業情報】に書かれている記述を根拠にすること。各リスクには「根拠」として、どの記述から導いたかを必ず添えること。
- 情報が不足していて判断できない事項は、推測で埋めず「要確認」と明記すること。
- 実在が確認できないサービス名・商品名を創作しないこと。提案は「リスク対策の方向性」として記述し、具体的なサービス名は（当社メニューと照合）と付記すること。

# 企業情報
【対象企業名】：
【業種】：
【HP等からの情報】：
（ここに会社概要・事業内容・工場や拠点情報などをそのまま貼り付け）
【営業メモ（任意）】：

# 出力フォーマット

## 1. 企業・事業特性のサマリー
主力事業、製造・販売プロセス、顧客層、拠点の特徴を簡潔に整理。情報が欠けている重要項目は「不明」と明記。

## 2. 潜在リスクの洗い出し（6カテゴリ）
以下の6観点で、この企業「特有」のリスクを抽出。各項目に：発生シナリオ／頻度(高・中・低)／影響度(大・中・小)／根拠（企業情報のどの記述から）／現場で確認すべき点。
①財物・自然災害（火災、地震、水災、設備老朽化 等）
②製造・品質・賠償（異物・アレルゲン混入、リコール、施設内事故 等）
③労務・人為（労災、人手不足、コンプライアンス 等）
④事業継続・サプライチェーン（調達寸断、物流停止 等）
⑤サイバー・情報（システム停止、情報漏えい、EC・生産システムへの攻撃 等）
⑥経営・戦略（事業承継、新規事業に伴うリスク、風評 等）

## 3. 提案ストーリー（初回商談の切り口3点）
各ストーリーに：顧客に響く問いかけ（顧客の言葉で）／対応するリスク／提案するリスク対策の方向性（当社メニューと照合）／想定される先方の反応と切り返し。

## 4. 提案スライド骨子（5枚構成）
スライド1：貴社の事業環境の理解（調べてきたことの証明）
スライド2：潜在リスクマップ（頻度×影響度の整理）
スライド3：同業種で実際に起きている事故・トラブルの類型
スライド4：当社がご支援できるリスク対策の方向性
スライド5：次のステップのご提案（詳細診断に向けて伺いたい事項）

## 5. 初回訪問ヒアリングシート
上記の「要確認」「現場で確認すべき点」を、初回訪問でそのまま使える質問文のリスト（10問以内）に整形。
```

## デモ運用メモ

1. 事前に春華堂の公式HP（会社概要・事業内容・工場ページ）のテキストをコピーしてメモ帳に用意しておく（当日のコピペ事故防止）。
2. 会議では貼り付け→送信→生成される様子を画面共有。「事前調査に丸1日かかっていた作業の初動がこの精度で数十秒」と内田部長の原体験に接続する。
3. 生成後に必ず言うこと：
   - 「これは汎用AIの一般論ベース。**本番は当社のコンサルメニュー・保険種目・過去の勝ち提案と接続**して、そのまま商談に持ち込めるレベルにする」（docs/02への布石）
   - 「皆さんのグループでも『コピペ＋型』で楽になる作業はないか」（課題出しへの接続）
4. 注意: デモで社内AI（ディープリサーチ）を使う場合は公開情報のみ入力する。顧客の非公開情報・個人情報は入れない。
