## この文書は誰のためのものか

**発注者ご本人が、ご自分の会社のWindowsパソコンと本物のExcelで「リスク提案ナビ」を動かし、合格・不合格をご自分の目で確かめるための手順書**である。プログラミングの知識は不要で、**黒い画面（ターミナル・PowerShell）は一度も使わない**。

書いてあるのは次の3つだけである。

1. **押す場所**（ボタンの名前は画面に出ているとおりに書いてある）
2. **何が出たら成功か**（画面に出る文字を1字単位で示す）
3. **うまくいかないときの対処**（§6）

分からない言葉は 操作ガイドタブの「⑥ 用語のミニ辞書」（本書§6の対処表と対で読む）を見ればよい。**判断に迷ったら先へ進まず、その画面のまま開発担当へ連絡する**のが正しい。

対象タスク: 17章 **T-48**（ブック内テスト実行）・**T-41**（実機2社完走）の2つ。**T-14b（ニセリボンちゃん配管検証）は開発側の作業**であり、利用者の合格判定には含めない（手順は §8.5。v3.1・裁定書17「配布物の見直し」）。

## 1. 受け取り方

会社PCではファイルをダウンロードしたりインストーラを実行したりできないので、**開発担当からチャットで受け取ったExcelファイルを、私物のPCからメールで会社アドレスへ送って、会社PCで保存するだけ**にする。

### 1.1 受け取るファイル（2つ）

| ファイル名 | 中身 |
|---|---|
| `リスク提案ナビ.xlsm` | 本番版。これが普段使うファイルである |
| `ナレッジブック.xlsx` | 社内の知識をまとめた台帳（マクロなし） |

**この2つ以外は受け取らなくてよい。** 開発版（`リスク提案ナビ_dev.xlsm`）は**開発専用**で、本物のAIを呼ばず決まった答えを返すため、実案件に使うと事故になる。開発側の配管検証（§8.5 ニセリボンちゃん）のときだけ開発担当が使う（v3.1・裁定書17「配布物の見直し」）。

**2つは同じフォルダへ入れる。** `ナレッジブック.xlsx` を `リスク提案ナビ.xlsm` と同じフォルダに置いておけば、起動時に自動で見つかる（設定をいじる必要はない。§3.1）。

### 1.2 手順

1. チャットで受け取った2つのファイルを、私物のパソコン（Mac可）へ保存する。
2. 私物のパソコンのGmailを開き、上の2つのファイルを**そのまま（zipにせず）添付**して、会社のメールアドレスへ送る。

   > **zipにしないこと。** 会社のメールは圧縮ファイル（zip）の添付をはじく設定になっている（実機で確認済み）。xlsmファイルはそのままの形で送れば届く。

3. 会社PCでそのメールを開き、2つの添付ファイルを保存する。**デスクトップに新しいフォルダを1つ作り（例:「リスク提案ナビ」）、その中へ2つとも保存する**（同じフォルダに入れておくと、ナレッジブックが自動で見つかる。§3.1）。

これで受け取りは完了である。次の§2から先は、**会社PCの中だけ**で完結する。

## 2. 開く前の設定2つ（初回だけ）

`リスク提案ナビ.xlsm` を開く**前**に、2つの設定を済ませておく。どちらも**初回の1回だけ**でよい。

### 2.1 設定(a): ファイルのブロックを外す

インターネットやメール経由で受け取ったファイルには、Windowsが「よそから来たファイル」という印を付けており、そのままでは中の機能が一部制限される。

1. 保存した `リスク提案ナビ.xlsm` を**右クリック** → [プロパティ]。
2. 「全般」タブのいちばん下に **[許可する]** というチェックボックスがあるので、チェックを入れる。
3. [OK] を押す。

`ナレッジブック.xlsx` にも同じ設定をしておく。

### 2.2 設定(b): VBAの信頼設定（必須）

このブックは、開いたときに自分で画面を組み立てる作りになっている。そのために次の設定が**必ず**要る（実機で確認済み。この設定をしていないと画面が組み上がらない）。

1. Excelを開く（空のブックでよい）。
2. [ファイル] → [オプション] → [トラストセンター] → [トラストセンターの設定] → [マクロの設定] と進む。
3. **「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」**にチェックを入れて [OK] を押す。
4. Excelをいったん全部閉じる。

> **英語で `Trust...` というメッセージが出たら、この設定(b)がまだ済んでいない合図である。** もう一度2.2をやり直す。

## 3. 開く

1. §1で保存した `リスク提案ナビ.xlsm` をダブルクリックで開く。
2. 画面の上に黄色い帯で「セキュリティの警告」が出たら、[**コンテンツの有効化**] を押す。
3. 少し待つと、はじめてこのブックを開いた人向けの案内カードが画面の真ん中に出る（3枚）。カードの右下の[次へ]で読み進め、最後は[はじめる]で閉じる。あとから「操作ガイド」タブの[ツアーをもう一度見る]で何度でも見返せる。
4. カードを閉じると **`HOME`** の画面が出る。上部に濃い緑色の大きなボタンが4つ横に並んでいれば成功である。

**成功の合図**: `HOME` が表示され、上に **[① 案件を作る] [② 一括実行] [③ レポートを出す] [④ ヒアリングシート]** の4つのボタンが横一列に並んでいる。

### 3.1 ナレッジブックの場所を教える

ナレッジブックは共有のフォルダではなく、**このパソコンの中**に置く運用でもよい（例: §1.2で作った「リスク提案ナビ」フォルダの中）。本体ブックにその場所を1回教える必要がある。

1. `HOME` の画面のまま、シート見出し（画面いちばん下のタブの並び）を**右クリック**し、[**再表示**] を選ぶ。
2. 一覧から **`config`** を選んで [OK]。`config` というシートが開く。
3. `name` 列に **`kb_path`** とある行を探し、その右の `value` 列のセルへ、`ナレッジブック.xlsx` を保存したフォルダのフルパスとファイル名を貼り付ける。
   - パスの調べ方: エクスプローラで `ナレッジブック.xlsx` を右クリック → [プロパティ] → 「場所」の値の末尾に `\ナレッジブック.xlsx` を足したものが、貼り付ける値である。
4. `config` シートのタブを**右クリック** → [**非表示**] に戻す。
5. `HOME` へ戻り、[ナレッジ再読込]（「くわしい操作」の区画にある）を押す。ナレッジ欄に「読込OK（メニューN/型N/事例N）」と出れば成功である。

## 4. 自動テスト（T-48・所要は数分）

会社PCではターミナルが使えないため、開発側の検問（`wintest\run_excel_tests.ps1`）と**同じ内容の検査**を、ブックの中の1ボタンで回せるようにしてある。**新しい版を受け取ったとき**と、**動きがおかしいと感じたとき**に押す。

### 4.1 やること

1. シート見出しの並びの中から緑色の「**操作ガイド**」タブを開く。
2. 章「**⑤ 自己テスト(このブックが正しく動くかを自分で確かめる)**」まで読み進める（目次のリンクから飛べる）。
3. [**テストを実行**] ボタンを押す。
4. 次の確認が出る。

   > **テストを実行します。数分かかり、実行中は操作できません。記録シート（err_log）に検査の行が残ります。よろしいですか。**

   [はい] を押す。（[いいえ]なら何も起きず中止する。）
5. **数分間、Excelを触らず待つ**。終わると合否がポップアップで1行出て、下の「テストの結果」欄にも同じ内容と詳細が入る。

### 4.2 合格の読み方

ポップアップとテスト結果欄の1行目に、次の形の文字が出る。

```
全PASS（FAIL 0 / SKIP 0 / 純層 N = 期待 N / 層(b) M 本）
```

（`N` と `M` は実行のたびの実際の数字が入る。）

**合格はこの4つが同時に成立したときだけ**である（開発側のPowerShell検問と同一の判定基準）。

| 見るところ | 合格の値 | 意味 |
|---|---|---|
| FAIL | **0** | 失敗した検査が1つも無い |
| SKIP | **0** | 飛ばした検査が1つも無い |
| 純層 = 期待 | **N = N** | 中身の計算の検査が、決められた本数とぴったり一致する |
| 層(b) | **1本以上** | 本物のExcelでしか確かめられない検査が実際に走っている |

### 4.3 不合格のとき

次の形で出る。

```
NG（FAIL 3 / SKIP 0 / 純層 N = 期待 N / 層(b) M 本）
```

**自分で直そうとしない。** 次を行う。

1. テスト結果欄（操作ガイドタブの下のほう。実行するたびに前回分は上書きされる）の**写真を撮る**か、そのままコピーする。
2. 開発担当へ送る。

期待本数がそもそも読み込めなかったときは「**期待本数が読めませんでした。開発担当へご連絡ください。**」と出る。これも自分で直さず開発担当へ連絡する。

## 6. うまくいかないときの対処

### 6.1 ブックを開いたら「はじめにお読みください」だけが見えて、他の画面が無い

**原因**: §2.2のVBA信頼設定（(b)）がまだ済んでいない、またはマクロが有効化されていない。

**対処**:

1. 画面の上のほうに黄色い帯で「セキュリティの警告」が出ていないか見る。出ていれば [**コンテンツの有効化**] を押す。
2. それでも直らないときは §2.2 をもう一度やり直す。**英語で `Trust...` と出るのは(b)がまだ済んでいない合図**である。

### 6.2 赤い帯で「信頼できないソース」と出て開けない、またはマクロが最初から無効

**原因**: §2.1の「ブロックを外す」設定がまだ済んでいない。

**対処**: §2.1をやり直す。ファイルを右クリック → [プロパティ] → [許可する] にチェック。

### 6.3 圧縮フォルダ（zip）の中から開こうとして開けない

**原因**: メールに直接添付されたxlsmファイルではなく、zipの中から直接開こうとしている。

**対処**: **zipのまま直接開かない。** 一度zipの外（デスクトップなど）へ取り出してから開く。そもそも本製品の配布経路ではzipを使わない（§1参照）。zip添付を受け取った場合は開発担当へ確認する。

### 6.4 `HOME` に「ナレッジブックが見つかりません。管理者にご連絡ください（操作ガイドの④ 困ったとき をご覧ください）。」と出る

**原因**: `config` の `kb_path` に書いたパスの場所にナレッジブックが無い。

**対処**: §3.1をもう一度やり直す。パスをコピーし直して貼り、[ナレッジ再読込] を押す。

### 6.5 `HOME` の警告欄に「本日のAI利用枠の上限です」と出た

**原因**: 社内AIリボンの1日の利用上限に達した。

**対処**:

- **起動も画面操作も止まらない**。翌日以降にやり直す。
- 途中まで通ったStepの結果は残っている。`案件一覧` の `status` を見て、続きのStepから押し直せばよい。

### 6.6 レポートを作り直したら前のファイルが消えていないか心配になった

**消えない**。同じ日に同じ案件でもう一度出力すると `_2` `_3` と連番の別ファイルが作られる。前回のHTMLはそのまま残る。**企業ファイル**（`_企業カルテ.xlsx`）だけは1社1ファイルで**同じファイルへ追記**するのが正しい動作であり、連番は作られない。

### 6.7 開くたびに毎回マクロの確認が出るのが煩わしい

**対処**: ブックを置くフォルダを1つ決めて「信頼できる場所」に登録する。

1. [ファイル] → [オプション] → [トラストセンター] → [トラストセンターの設定]。
2. 左の [**信頼できる場所**] を選び、[新しい場所の追加] を押す。
3. [参照] でブックを置いているフォルダ（例: デスクトップの「リスク提案ナビ」フォルダ）を選ぶ。
4. 「この場所のサブフォルダーも信頼する」にチェックを入れて [OK]。

> **注意**: 信頼できる場所に登録したフォルダのマクロは確認なしで動く。**そこには自分が中身を知っているファイルだけを置く**。

### 6.8 ほかのExcelファイルを開いていると動きがおかしい

**対処**: 本製品を使うときは**ほかのExcelファイルを全て閉じてから**、`リスク提案ナビ.xlsm` だけを開く。

### 6.9 `HOME` の赤帯（デモ／開発経路で動作中です）が消えない

**原因**: 練習用ファイル（`リスク提案ナビ_dev.xlsm`）を開いている。

**対処**: `_dev` が付かない `リスク提案ナビ.xlsm` を開く。それでも消えないときは開発担当へ連絡する。

### 6.10 §4の自動テストが不合格だった

**対処**: §4.3のとおり、テスト結果欄の写真かコピーを開発担当へ送る。**自分で直そうとしない。**

## 7. 実機観察メモ（開発側が知りたいこと）

会社PCで実際に動かしたときにだけ見える挙動は、以下をメモして開発担当へ伝えると助かる。

| 観察項目 | 見るところ |
|---|---|
| ナレッジブックの読込待ち | ネットワーク越し（社内共有フォルダ）にナレッジブックを置いた場合、読込に体感でどれくらい待つか（起動時・[ナレッジ再読込]時の両方） |
| 初回ツアーカードの位置 | 画面のズーム倍率（表示タブの拡大率）を変えたとき、案内カードが画面の中央からずれて見えないか |
| 自動テストの後始末 | §4の自動テストを初めて実行した直後、シートやボタンの見た目・動作に違和感が残らないか |
| 業種欄などの一覧の反応 | 業種欄のような一覧から選ぶ入力欄が、起動直後にどれくらいの時間で選べるようになるか |
| 主要動線ボタン4つ | 画面を最大化しない状態・拡大率100%で [④ ヒアリングシート] まで横スクロールせずに見えるか |

## 8. 開発側だけが使う手順（利用者は読まなくてよい）

**この章より下は、この文書の読者が実行する必要は無い。** 開発担当がLinux環境でブックを組み立て、出荷前の検問を回すときに使う手順を要約として残してある（詳細は姉妹文書・開発リポジトリを参照）。

### 8.1 ブックの組み立て（ビルド）

Python・git を使う開発環境で、次の順にリポジトリを取得しブックを組み立てる。

1. `git clone` でリポジトリを取得する。
2. `python -m pip install openpyxl olefile` で部品を入れる。
3. `python build/build_rpn.py --dev` / `--prod` / `--kb` で3つのファイル（開発版・本番版・ナレッジブック）を組み立てる（`dist` フォルダにできる）。

### 8.2 開発側の自動検問（`python3 tools/gate.py`）

出荷前に次の15ゲートを一括で回す。1つでも赤ければ配らない。

| コマンド | 何を見るか |
|---|---|
| `python3 tools/vba_lint.py` | 書き方の規約・CP932で表せない文字の混入 |
| `python3 tools/run_lo_tests.py` | 全部品が文法として通るか・純ロジックが動くか |
| `python3 tools/prompt_diff.py --strict` | 15章のプロンプト本文と実装が1字も違わないか |
| `python3 tools/validate_check.py` | 15章§11の検証ルールと実装・テストの件数一致 |
| `python3 tools/sheet_check.py` | 13章のシート定義と実物のブックの一致 |
| `python3 tools/ship_check.py` | 出荷前検問①②③（外部テキストの直書き・鍵の混入・成果物の除外） |

### 8.3 Windows実機での自動テスト（開発側のPowerShell実行）

開発オーナーが自分のWindows PC上で `wintest\run_excel_tests.ps1` を実行し、`modTestsPure` と `modTestsExcel`（層(b)）を自動で回す。本文書§4の[テストを実行]ボタンは、**この検問とまったく同じ4条件（FAIL0/SKIP0/純層=期待/層(b)≧1）を、利用者がターミナル無しでブックの中から回せるようにしたもの**である。両者は互いの代わりにならず、どちらも出荷前に緑が要る。詳しくは `wintest/README.md` を参照する。

### 8.5 ニセリボンちゃん（T-14b・**開発側**が個人のWindowsパソコンで行う）

**これは開発側の検証であり、利用者は行わなくてよい**（v3.1・裁定書17「配布物の見直し」で§5から本章へ移した）。会社PCではなく、個人のWindowsパソコンで行う。ターミナルは使わないが、VBE（VBAの編集画面）を手で操作する必要があり、社内の情報を扱わない検証用の作業だからである。**練習用の `リスク提案ナビ_dev.xlsm` を使うのもこの検証のときだけ**である。

#### 8.5.1 これは何を確かめるのか

本製品は、社内のAI「リボンちゃん」へ**12個の情報を決まった順番で**渡して答えをもらう。会社のPCでないとリボンちゃんは動かないので、**同じ形をした偽物（ニセリボンちゃん）**を個人PCに入れ、「渡す形そのもの」が正しいかを確かめる。AIの答えの良し悪しではなく、**渡し方**を確かめる検証である。

> **注意**: ニセリボンちゃんは**会社のパソコンに入れてはならない**。本物と名前が一部一致するため、取り違える原因になる。

#### 8.5.2 ニセリボンちゃんを作る（1回だけ・5分・VBE手動インポート＝ターミナル不要）

1. 個人PCでExcelを起動し、**空のブック**を開く。
2. `Alt` を押しながら `F11` を押す（VBEという編集画面が開く）。
3. 上のメニューから **ファイル → ファイルのインポート** を選ぶ。
4. 開発リポジトリの次のファイルを選ぶ（開発担当からチャットで個別に受け取る）。

   ```
   wintest\mock_ribbon\modMockRibbon.bas
   ```

5. `Alt` + `F11` でExcelの画面へ戻り、`F12`（名前を付けて保存）を押す。
6. **ファイルの種類**を「**Excel アドイン (\*.xlam)**」に変える。
7. **ファイル名**を次のとおりにする（「**リボンちゃん**」の6文字を必ず含める）。

   ```
   リボンちゃん(検証用).xlam
   ```

8. 保存先は既定のまま（`%APPDATA%\Microsoft\AddIns`）でよい。[保存] を押す。

#### 8.5.3 アドインを有効化する

1. Excelで [ファイル] → [オプション] → [アドイン] → 下の「管理: Excel アドイン」で [設定] を押す。
2. 一覧に出た **`リボンちゃん(検証用)`** にチェックを入れて [OK]。

#### 8.5.4 本番版を開いて確かめる

1. 個人PCへ持ってきた `リスク提案ナビ.xlsm`（本番版）を開く（§2の2つの設定を個人PCでも先に済ませておく）。
2. `HOME` の [**① 案件を作る**] を押し、企業名などを適当に埋めて [保存して戻る]。
3. `HOME` の「くわしい操作」区画にある [**S1**] を押す。
4. 実行後、シート見出しを右クリック → [**再表示**] で **`run_log`** シートを開く。

**見るところ**:

| 列 | 期待する値 | 意味 |
|---|---|---|
| `transport` | `ribbon` | ニセリボンちゃん経由で呼べた（アドイン名の部分一致で見つけた） |
| `model` | config の `recommended_model` の値（既定 `gpt-5.5`） | モデル名が正しく渡っている |
| `latency_ms` | 0より大きい数 | 実際に呼び出しが往復した |

5. 続いて `case_data` シートを開き、`data_key` が `s1_json_failed` の行の `content` を見る。ニセリボンちゃんはJSONを返さないので検証には落ちるが、**受け取った引数がそのまま書き戻されている**ので、渡した中身が正しいかを次の文字で確かめられる。

| 応答の中の文字 | 確認すること |
|---|---|
| `model=gpt-5.5` | モデル名が届いた |
| `tool=リスク提案ナビ:s1` | 呼び出しの名札が届いた |
| `temp=` / `maxTokens=` / `wait=` | 数値が届いた |
| `systemLen=` / `userLen=` | 文章の長さが届いた |
| `effort=` / `verbosity=` | 推論の調整値が届いた |

6. **AI利用枠が上限に達したとき（True側）の確認**:

   1. Excelで空のブックを開き、`Alt` + `F11` でVBEを開く。
   2. 左のツリーで `リボンちゃん(検証用).xlam` の下の `modMockRibbon` をダブルクリックする。
   3. `LimitCheck = False` と書かれた1行を `LimitCheck = True` に**書き換える**。
   4. `Ctrl` + `S` で保存し、Excelをいったん全部閉じる。
   5. `リスク提案ナビ.xlsm` を開き直す。

   **成功の合図**: ブックは**普通に開き**、`HOME` 画面が出る。そのうえで `HOME` の警告欄に「本日のAI利用枠の上限です」のようなAI利用枠の案内が出る。**「開かない」「エラーで止まる」は不合格**である。

   6. 確認できたら **必ず `LimitCheck = False` に戻して保存する**。

**結果の残し方**: 上の表の「期待する値」と「実際に見えた文字」を並べたメモを作り、開発担当へ送る。
