## この文書は誰のためのものか

**発注者ご本人が、ご自分の会社のWindowsパソコンと本物のExcelで「リスク提案ナビ」を動かし、合格・不合格をご自分の目で確かめるための手順書**である。プログラミングの知識は不要で、**黒い画面（ターミナル・PowerShell）は一度も使わない**。

書いてあるのは次の3つだけである。

1. **押す場所**（ボタンの名前は画面に出ているとおりに書いてある）
2. **何が出たら成功か**（画面に出る文字を1字単位で示す）
3. **うまくいかないときの対処**（§6）

分からない言葉は `使い方`タブの「⑤ 困ったとき」（本書§6の対処表と対で読む）を見ればよい。**判断に迷ったら先へ進まず、その画面のまま開発担当へ連絡する**のが正しい。

対象タスク: 17章 **T-48**（ブック内テスト実行）・**T-41**（実機2社完走）の2つ。**T-14b（ニセリボンちゃん配管検証）は開発側の作業**であり、利用者の合格判定には含めない（手順は §8.5）。

## 1. 受け取り方

会社PCではファイルをダウンロードしたりインストーラを実行したりできないので、**開発担当からチャットで受け取ったExcelファイルを、私物のPCからメールで会社アドレスへ送って、会社PCで保存するだけ**にする。

### 1.1 受け取るファイル（3つ）

| ファイル名 | 中身 |
|---|---|
| `リスク提案ナビ.xlsm` | 本番版。これが普段使うファイルである |
| `ナレッジブック.xlsx` | 社内の知識をまとめた台帳（マクロなし） |
| `リスク提案ナビを起動.bat` | **起動ボタン**（v3.5・裁定書28）。押すと本体を `D:` へ写して開く |

### 1.1b 使い方はこの1つだけ（v3.5・裁定書28）

**OneDrive の配布フォルダにある「リスク提案ナビを起動」をダブルクリックする。** これが利用者の手順のすべてである。押すと次のことが自動で起こる。

1. `D:\リスク提案ナビ` というフォルダを作る（`D` ドライブが無いパソコンでは一時フォルダで代用し、画面に警告が出る）。
2. OneDrive にある `リスク提案ナビ.xlsm` と `ナレッジブック.xlsx` を、**新しければ** `D:` へ写す。
3. 書きためたもの（案件・レポート・ログ）の置き場所として、OneDrive の `データ` フォルダを本体へ教える。
4. `D:` に写した本体を Excel で開く。

**なぜこの形なのか**: 会社PCの `D:` はシャットダウンで中身が消えるが、マクロを実行できる信頼された場所は `D:` だけである。逆に消えない場所は OneDrive だけだが、そこに置いた `.xlsm` は開くたびに確認が出る。**本体は毎回 `D:` へ写して使い、書きためたものは OneDrive に残す**——この2つを両立させるのが起動ボタンである。だから `.xlsm` を直接ダブルクリックしないこと（書きためたものの置き場所が本体へ伝わらない）。

**初回だけ: SmartScreen（「Windows によって PC が保護されました」）の解除**

受け取った `リスク提案ナビを起動.bat` を初めて押すと、青い画面で「Windows によって PC が保護されました」と出て実行できないことがある。次の手順で解除する（**初回の1回だけ**）。

1. `リスク提案ナビを起動.bat` を**右クリック** → [プロパティ]。
2. 「全般」タブのいちばん下の **[許可する]** にチェックを入れる。
3. [OK] を押してから、あらためてダブルクリックする。

**起動ボタンが動かないパソコンのとき（代替手順）**

会社の設定で `.bat` が実行できない端末では、次の手動の手順で同じことができる（開発担当へも一報を入れる）。

1. `D` ドライブに `D:\リスク提案ナビ` というフォルダを作る。
2. OneDrive の配布フォルダから `リスク提案ナビ.xlsm` と `ナレッジブック.xlsx` を、その中へコピーする（**更新版を受け取ったら毎回コピーし直す**）。
3. コピーした `リスク提案ナビ.xlsm` をダブルクリックで開く。
4. 書きためたものの置き場所は、この場合 `config` の `data_dir`（§3.1 と同じ要領で開く）が指す OneDrive のフォルダになる。

**この3つ以外は受け取らなくてよい。** 開発版（`リスク提案ナビ_dev.xlsm`）は**開発専用**で、本物のAIを呼ばず決まった答えを返すため、実案件に使うと事故になる。開発側の配管検証（§8.5 ニセリボンちゃん）のときだけ開発担当が使う。

**3つは同じフォルダへ入れる（v3.5・裁定書28 では、そのフォルダは OneDrive の「配布フォルダ」である。§1.1b）。** `ナレッジブック.xlsx` を `リスク提案ナビ.xlsm` と同じフォルダに置いておけば、起動時に自動で見つかる（設定をいじる必要はない。§3.1）。

**置き場所（v3.5・裁定書28 で変更）**: 3つは **OneDrive の配布フォルダ**（例: `…\リスク提案ナビ\`）へ置き、そこにある起動ボタンを押して使う（§1.1b）。`D:` へは起動ボタンが自動で写すので、手で置く必要は無い。**以下の枠内は v3.4 までの旧手順**であり、起動ボタンが動かない端末（§1.1b の代替手順）でだけ意味を持つ。

> **旧手順（v3.4まで）**: 置き場所は `D` ドライブにする。 `D` ドライブの中に新しいフォルダを1つ作り（例: `D:\リスク提案ナビ`）、**2つのファイルをそこへ一緒に入れる**。`D` ドライブは会社の設定で最初から信頼されているので、**こちらで設定することは何も無い**（マクロの確認も出ない）。

> **OneDrive（オンラインの保存場所）には置かないこと。** OneDrive のフォルダに置くと、開くたびにマクロの確認が出る（§6.7）。

### 1.2 手順

1. チャットで受け取った2つのファイルを、私物のパソコン（Mac可）へ保存する。
2. 私物のパソコンのGmailを開き、上の2つのファイルを**そのまま（zipにせず）添付**して、会社のメールアドレスへ送る。

   > **zipにしないこと。** 会社のメールは圧縮ファイル（zip）の添付をはじく設定になっている（実機で確認済み）。xlsmファイルはそのままの形で送れば届く。

3. 会社PCでそのメールを開き、2つの添付ファイルを保存する。**`D` ドライブに新しいフォルダを1つ作り（例: `D:\リスク提案ナビ`）、その中へ2つとも保存する**（同じフォルダに入れておくと、ナレッジブックが自動で見つかる。§3.1）。OneDrive のフォルダには置かない（§1.1の注意）。

これで受け取りは完了である。次の§2から先は、**会社PCの中だけ**で完結する。

### 3.1 ナレッジブックの場所（ふつうは何もしなくてよい）

**`ナレッジブック.xlsx` を `リスク提案ナビ.xlsm` と同じフォルダに置いてあれば、起動したときに自動で見つかる**。設定をいじる必要はない。

ナレッジ欄に「**ナレッジブック.xlsx を本体と同じフォルダに置いて[ナレッジを読み直す]を押してください（探した場所: <kb_pathの現在値>）。置いてあるのに読めないときは、そのファイルを右クリック→プロパティ→[許可する]にチェックを入れて開き直してください。**」と出たときは、まず2つのファイルが別のフォルダにある可能性を疑う。同じフォルダへ移してから、コーチ帯の[**ナレッジを読み直す**]を押す。**同じフォルダに置いてあるのに出るとき**は、メールで受け取った `ナレッジブック.xlsx` がブロックされている（§2.1 のブロック解除がされていない）。文中の「探した場所」に出るパスが、実際に置いた場所と同じかどうかもあわせて確かめる。

1. `ナビ` の画面のまま、シート見出し（画面いちばん下のタブの並び）を**右クリック**し、[**再表示**] を選ぶ。

## 4. 自動テスト（T-48・所要は数分）

会社PCではターミナルが使えないため、開発側の検問と**同じ内容の検査**を、ブックの中の1ボタンで回せるようにしてある。**新しい版を受け取ったとき**と、**動きがおかしいと感じたとき**に押す。

### 4.1 やること

1. シート見出しの並びの中から緑色の「**使い方**」タブを開く。
2. 章「**⑥ 自己テスト(このブックが正しく動くかを自分で確かめる)**」まで読み進める（目次のリンクから飛べる）。
3. [**テストを実行**] ボタンを押す。
4. 次の確認が出る。

   > **テストを実行します。数分かかり、実行中は操作できません。記録シート（err_log）に検査の行が残ります。よろしいですか。**

   [はい] を押す。（[いいえ]なら何も起きず中止する。）
5. **数分間、Excelを触らず待つ**。終わると合否がポップアップで1行出て、下の「テストの結果」欄にも同じ内容と詳細が入る。

### 4.2 合格の読み方

ポップアップとテスト結果欄の1行目に、次の形の文字が出る。

```
全PASS（FAIL 0 / SKIP 0 / 純層 N = 期待 N / 層(b) M 本）
```

（`N` と `M` は実行のたびの実際の数字が入る。）

**合格はこの4つが同時に成立したときだけ**である（開発側のPowerShell検問と同一の判定基準）。

| 見るところ | 合格の値 | 意味 |
|---|---|---|
| FAIL | **0** | 失敗した検査が1つも無い |
| SKIP | **0** | 飛ばした検査が1つも無い |
| 純層 = 期待 | **N = N** | 中身の計算の検査が、決められた本数とぴったり一致する |
| 層(b) | **1本以上** | 本物のExcelでしか確かめられない検査が実際に走っている |

### 4.3 不合格のとき

次の形で出る。

```
NG（FAIL 3 / SKIP 0 / 純層 N = 期待 N / 層(b) M 本）
```

**自分で直そうとしない。** 次を行う。

1. テスト結果欄（`使い方`タブの下のほう。実行するたびに前回分は上書きされる）の**写真を撮る**か、そのままコピーする。
2. 開発担当へ送る。

期待本数がそもそも読み込めなかったときは「**期待本数が読めませんでした。開発担当へご連絡ください。**」と出る。これも自分で直さず開発担当へ連絡する。

## 6. うまくいかないときの対処

### 6.1 ブックを開いたら「はじめにお読みください」だけが見えて、他の画面が無い

**原因**: マクロが有効化されていない。

**対処**:

1. 画面の上のほうに黄色い帯で「セキュリティの警告」が出ていないか見る。出ていれば [**コンテンツの有効化**] を押す。ファイルを `D` ドライブのフォルダ（§1.1）に置いていれば、この帯はふつう出ない。
2. **英語で `Trust the VBA project, then reopen.` と出るときは §6.11** を見る（v6.0 の配布物では出ないはずのメッセージである）。

### 6.2 赤い帯で「信頼できないソース」と出て開けない、またはマクロが最初から無効

**原因**: §2.1の「ブロックを外す」設定がまだ済んでいない。または、ファイルを `D` ドライブ以外（OneDrive など）に置いている。

**対処**:

1. §2.1をやり直す。ファイルを右クリック → [プロパティ] → [許可する] にチェック。
2. それでも出るときは、2つのファイルを `D` ドライブのフォルダ（例: `D:\リスク提案ナビ`）へ移してから開き直す。**`D` ドライブに置くのが正しい置き方**である（§1.1）。
3. どうしても `D` ドライブ以外を使わざるを得ないときの予備手順は §6.7 にある。ただし**会社はマクロを有効にする設定を勧めていない**ので、まず `D` ドライブへ移すことを試す。

### 6.3 圧縮フォルダ（zip）の中から開こうとして開けない

**原因**: メールに直接添付されたxlsmファイルではなく、zipの中から直接開こうとしている。

**対処**: **zipのまま直接開かない。** 一度zipの外（デスクトップなど）へ取り出してから開く。そもそも本製品の配布経路ではzipを使わない（§1参照）。zip添付を受け取った場合は開発担当へ確認する。

### 6.4 `ナビ` に「ナレッジブックが見つかりません。管理者にご連絡ください。」と出る

**原因**: 本体ブックと同じフォルダにも、`config` の `kb_path` に書いたパスの場所にも `ナレッジブック.xlsx` が無い。

**対処**: `ナレッジブック.xlsx` を `リスク提案ナビ.xlsm` と**同じフォルダ**へ置き、Excelをいったん閉じて開き直す（起動時に自動で見つかる）。開いたまま直したいときは帯の[ナレッジを読み直す]を押す。共有フォルダに置く運用のときだけ §3.1 の後半で `kb_path` を書き直す。

### 6.5 「お知らせ」欄に「本日のAI利用枠の上限です」と出た

**原因**: 社内AIリボンの1日の利用上限に達した。

**対処**:

- **起動も画面操作も止まらない**。翌日以降にやり直す。
- 途中まで通ったStepの結果は残っている。`案件一覧` の `status` を見て、続きのStepから押し直せばよい。

### 6.6 レポートを作り直したら前のファイルが消えていないか心配になった

**消えない**。同じ日に同じ案件でもう一度出力すると `_2` `_3` と連番の別ファイルが作られる。前回のHTMLはそのまま残る。**企業ファイル**（`_企業カルテ.xlsx`）だけは1社1ファイルで**同じファイルへ追記**するのが正しい動作であり、連番は作られない。

### 6.7 開くたびに毎回マクロの確認が出るのが煩わしい

**原因**: ファイルを `D` ドライブ以外（OneDrive など）に置いている。`D` ドライブのフォルダは会社の設定で最初から信頼されているので、そこに置いてあれば確認は出ない。

**対処**: まず2つのファイルを `D` ドライブのフォルダ（例: `D:\リスク提案ナビ`）へ移して開き直す（§1.1）。**これが正しい置き方**である。

**`D` ドライブ以外に置く必要があるときは、設定を変えずに情シス（端末サポート）へ相談してください。**

（v5.1・裁定書27 W9-C1: ここには以前「信頼できる場所」に自分で登録する予備手順を載せていたが、
利用者にセキュリティ設定を触らせる案内は事務局が反対しており、撤去した。置き場所の相談は
情シスへ回すのが正しい道である。）

### 6.8 ほかのExcelファイルを開いていると動きがおかしい

**対処**: 本製品を使うときは**ほかのExcelファイルを全て閉じてから**、`リスク提案ナビ.xlsm` だけを開く。

### 6.9 赤帯（デモ／開発経路で動作中です）が消えない

**原因**: 練習用ファイル（`リスク提案ナビ_dev.xlsm`）を開いている。

**対処**: `_dev` が付かない `リスク提案ナビ.xlsm` を開く。それでも消えないときは開発担当へ連絡する。

### 6.10 §4の自動テストが不合格だった

**対処**: §4.3のとおり、テスト結果欄の写真かコピーを開発担当へ送る。**自分で直そうとしない。**

### 6.11 英語で `Trust the VBA project, then reopen.` と出る

**原因**: **v6.0（裁定書27 W9-A）以降の配布物では、このメッセージは出ない。** 部品は最初からファイルに入っており（§8.1b）、ブックが自分でVBAへ書き込むことはもう無いためである。出たときは、**旧方式（v5.x以前）の古いファイルを受け取っている**か、ファイルが壊れている合図である。

**対処**: **まず開発担当へ連絡する**（「`Trust the VBA project, then reopen.` と出た」とそのまま伝えればよい）。新しいファイルを送り直してもらうのが正しい直し方である。

**利用者が行う対処はこれだけである。** 設定を自分で変える必要は無い。

（v5.1・裁定書27 W9-C1: ここには以前「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」を
自分で入れる予備手順を載せていたが、**利用者へ配る文書から物理的に外した**。開発担当だけが使う手順は
`docs/28_開発担当専用_検証PCの設定.md` にある。）

## 8. 開発側だけが使う手順（利用者は読まなくてよい）

**この章より下は、この文書の読者が実行する必要は無い。** 開発担当がLinux環境でブックを組み立て、出荷前の検問を回すときに使う手順を要約として残してある（詳細は姉妹文書・開発リポジトリを参照）。

### 8.1 ブックの組み立て（ビルド）

Python・git を使う開発環境で、次の順にリポジトリを取得しブックを組み立てる。

1. `git clone` でリポジトリを取得する。
2. `python -m pip install openpyxl olefile oletools` で部品を入れる。
3. `python build/build_rpn.py --dev` / `--prod` / `--kb` で3つのファイル（開発版・本番版・ナレッジブック）を組み立てる（`dist` フォルダにできる）。
4. できたファイルは**そのまま配れる**。開いて閉じるなどの下ごしらえは要らない（v3.4・裁定書27 W9-A）。§8.2 の検問を回してから配る。

### 8.1c 配り方＝OneDrive の配布フォルダを差し替えるだけ（v3.5・裁定書28）

発行者（小島さん）の手順は**OneDrive の配布フォルダに置いた3つ（`リスク提案ナビ.xlsm` / `ナレッジブック.xlsx` / `リスク提案ナビを起動.bat`）を、新しいビルドのもので差し替える**——これだけである。利用者側は次に起動ボタンを押した時点で、`xcopy /D`（新しければコピー）が新版を `D:` へ写す。利用者に配り直す作業も、利用者側の操作も無い。

- 3つとも `python3 build/build_rpn.py --prod` / `--kb` の出力（`dist/`）から取る。`.bat` はビルドが生成するので**手で書き換えない**（値源は `build/build_rpn.py` の `LAUNCHER_TEXT`。形は `tools/ship_check.py` ⑦が毎回検問する）。
- `データ` フォルダ（案件・レポート・ログ・設定.txt）は**触らない**。利用者の書きためたものが入っている。

#### 8.1c-1 起動batを会社PCへ持ち込む（最初の1回・v6.1・裁定書31 裁定2＋司令塔追補）

**メールでは持ち込めない。** 会社のメールは `.bat` も `.bat.txt` も**受信時に削除**し、圧縮ファイル（zip）は Gmail 側が送信を拒否する（2026-09-05 実測）。したがってメール経路は**使えない**。持ち込みは次の2段構えで行う。

**(a) 主経路＝zip を SharePoint（または OneDrive の配布フォルダ）に置いて取りに行く**

1. 発行者の手元（Linux／私物PC）で、`dist/` の3つ（`リスク提案ナビ.xlsm` / `ナレッジブック.xlsx` / `リスク提案ナビを起動.bat`）を**手で1つの zip にまとめる**（ビルドは zip を作らない。まとめるのは人の作業である）。
2. その zip を **SharePoint（または OneDrive の配布フォルダ）へアップロード**する。
3. 会社PCでその zip を**ダウンロードして展開**し、中身3つを OneDrive の配布フォルダへ置く。

この経路は MyBookshelf で実績がある（zip をSharePointに置いて取りに行く形）。**`.bat` を単体でアップロードできるかは未確認**なので、確認できるまでは zip でまとめて置くこと。

**(b) 保険＝主経路が塞がれたとき、会社PCのメモ帳で作る**

SharePoint の設定変更などで (a) が使えなくなったときは、下の枠から**会社PCのメモ帳で作る**。

1. 会社PCで**メモ帳**を開く。
2. 下の枠の中を**すべて**コピーして、メモ帳へ貼り付ける（1行目の `@echo off` から最終行の `endlocal` まで）。
3. [ファイル] → [名前を付けて保存]。
4. **ファイルの種類**を「**すべてのファイル**」にする（「テキスト文書」のままだと `.txt` が付く）。
5. **ファイル名**に `リスク提案ナビを起動.bat` と**拡張子まで**入力する。
6. **文字コード**を「**ANSI**」にする（UTF-8 で保存すると日本語のフォルダ名が化けて起動しない）。
7. 保存先を **OneDrive の配布フォルダ**（`リスク提案ナビ.xlsm` と同じ場所）にして保存する。

作ったあとは、利用者はこの `.bat` をダブルクリックするだけである（§1.1b。初回の SmartScreen 解除も §1.1b）。**2回目以降は作り直さない**（更新は `dist/` の3ファイルを差し替えるだけ。§8.1c）。

**この枠の中身は `build/build_rpn.py` の `LAUNCHER_TEXT`（＝`dist/リスク提案ナビを起動.bat`）と一字一句同じでなければならない。** 手で書き換えないこと。ずれたら `tools/ship_check.py` ⑧ が赤になる（改行の違い＝CRLF/LF は無視して比較する）。

```bat
@echo off
rem ==========================================================
rem  Risk Teian Navi launcher - generated by build/build_rpn.py
rem  Do NOT edit by hand. Source: build/build_rpn.py
rem  1) SRC = this folder (OneDrive)   2) DST = D:\<app folder>
rem  3) copy newer files  4) write data_dir.txt  5) start Excel
rem ==========================================================
setlocal
set "SRC=%~dp0"
set "DST=D:\リスク提案ナビ"
if not exist "D:\" (
  set "DST=%TEMP%\リスク提案ナビ"
  echo [警告] Dドライブが見つかりません。一時フォルダで起動します。
  echo [警告] このフォルダは信頼された場所ではありません。
)
if not exist "%DST%" mkdir "%DST%"
xcopy /D /Y "%SRC%リスク提案ナビ.xlsm" "%DST%\" >nul
xcopy /D /Y "%SRC%ナレッジブック.xlsx" "%DST%\" >nul
> "%DST%\data_dir.txt" echo %SRC%データ
start "" excel.exe /x "%DST%\リスク提案ナビ.xlsm"
endlocal
```

### 8.1b 焼き付けは無くなった（v3.4・裁定書27 W9-A）

**以前あった「配る前に開発側が会社PCで1回開いて閉じる」作業（焼き付け）は廃止した。いまは置くだけである。**

**なぜ無くなったか**: 旧方式のブックは、部品（VBAモジュール）を `vba_src` という隠しシートに文字として持っているだけで、開いた1回目にブック自身がそれをVBAプロジェクトへ書き込んでいた。この「自分で自分にコードを書き込む」動きが **2026-09-02 に社内のウイルス対策ソフト（AMSI）に検知され、端末が強制停止して情シスのチケットになった**（姉妹プロジェクトでの実測。当プロジェクトの配布物も同じ方式だった）。焼き付け作業でも同じ検知が走る。

そこで**ビルドの段階で、部品が最初から入った正規のVBAプロジェクトを作る**方式へ切り替えた（12章§2「配布方式B」）。配布物には隠しシートも書き込み処理も無いので、

- 焼き付け（開いて閉じる）は**不要**。
- 利用者にも開発側にも「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」の設定は**不要**（開発担当が検証PCで使う設定は `docs/28_開発担当専用_検証PCの設定.md` へ物理分離した。利用者には配らない。v5.1・裁定書27 W9-C1）。
- Windowsで焼く／Macで焼かない、という区別も**不要**（ビルドはLinuxで完結する）。

**当面の運用**: 会社PCでの焼き付けは**行わない**（そもそも作業自体が無くなった）。新方式のファイルが実Excelで正しく開くかは、まず利用者の私物Mac（会社のウイルス対策ソフトの外）で確認し、そのうえで会社PCへ持ち込む。

> **Macは製品としては非対応**である（17章 Z-20）。v3.4・裁定書27 W9-B でWindows前提の部品（クリップボードの遅延バインド・メモ帳の起動・`ADODB.Stream`・`Declare`）はすべて撤去したが、動作を確かめているのはWindowsだけである。私物Macでの確認は「VBAプロジェクトが壊れずに読み込めるか・画面が出るか」を見るためのものであり、機能の検証ではない。

### 8.3 Windows実機での自動テスト（開発側のPowerShell実行）

開発オーナーが自分のWindows PC上で `wintest\run_excel_tests.ps1` を実行し、`modTestsPure` と `modTestsExcel`（層(b)）を自動で回す。本文書§4の[テストを実行]ボタンは、**この検問とまったく同じ4条件（FAIL0/SKIP0/純層=期待/層(b)≧1）を、利用者がターミナル無しでブックの中から回せるようにしたもの**である。両者は互いの代わりにならず、どちらも出荷前に緑が要る。詳しくは `wintest/README.md` を参照する。

### 8.5 ニセリボンちゃん（T-14b・**開発側**が個人のWindowsパソコンで行う）

**これは開発側の検証であり、利用者は行わなくてよい**。会社PCではなく、個人のWindowsパソコンで行う。ターミナルは使わないが、VBE（VBAの編集画面）を手で操作する必要があり、社内の情報を扱わない検証用の作業だからである。**練習用の `リスク提案ナビ_dev.xlsm` を使うのもこの検証のときだけ**である。

#### 8.5.1 これは何を確かめるのか

本製品は、社内のAI「リボンちゃん」へ**12個の情報を決まった順番で**渡して答えをもらう。会社のPCでないとリボンちゃんは動かないので、**同じ形をした偽物（ニセリボンちゃん）**を個人PCに入れ、「渡す形そのもの」が正しいかを確かめる。AIの答えの良し悪しではなく、**渡し方**を確かめる検証である。

> **注意**: ニセリボンちゃんは**会社のパソコンに入れてはならない**。本物と名前が一部一致するため、取り違える原因になる。

#### 8.5.2 ニセリボンちゃんを作る（1回だけ・5分・VBE手動インポート＝ターミナル不要）

1. 個人PCでExcelを起動し、**空のブック**を開く。
2. `Alt` を押しながら `F11` を押す（VBEという編集画面が開く）。
3. 上のメニューから **ファイル → ファイルのインポート** を選ぶ。
4. 開発リポジトリの次のファイルを選ぶ（開発担当からチャットで個別に受け取る）。

   ```
   wintest\mock_ribbon\modMockRibbon.bas
   ```

5. `Alt` + `F11` でExcelの画面へ戻り、`F12`（名前を付けて保存）を押す。
6. **ファイルの種類**を「**Excel アドイン (\*.xlam)**」に変える。
7. **ファイル名**を次のとおりにする（「**リボンちゃん**」の6文字を必ず含める）。

   ```
   リボンちゃん(検証用).xlam
   ```

8. 保存先は既定のまま（`%APPDATA%\Microsoft\AddIns`）でよい。[保存] を押す。

#### 8.5.3 アドインを有効化する

1. Excelで [ファイル] → [オプション] → [アドイン] → 下の「管理: Excel アドイン」で [設定] を押す。
2. 一覧に出た **`リボンちゃん(検証用)`** にチェックを入れて [OK]。

#### 8.5.4 本番版を開いて確かめる

1. 個人PCへ持ってきた `リスク提案ナビ.xlsm`（本番版）を開く（§2の設定だけ済ませておけばよい。**焼き付けは v6.0・裁定書27 W9-A で廃止**したので、個人PCでも下ごしらえは要らない。§8.1b）。
2. `ナビ` の帯の案件プルダウンで何も選ばず（新規モード。`(新規)` と出る）、区画①に企業名などを適当に埋めて区画②の[貼ったものを保存する]を押す。
3. 区画③の[**まとめて作る**]を押す（またはシートタブを再表示して `S1_企業プロファイル` の[S1から再実行]を押す）。
4. 実行後、画面いちばん下のタブから **`run_log`** シートを開く（最初から見えている）。

**見るところ**:

| 列 | 期待する値 | 意味 |
|---|---|---|
| `transport` | `ribbon` | ニセリボンちゃん経由で呼べた（アドイン名の部分一致で見つけた） |
| `model` | config の `recommended_model` の値（既定 `gpt-5.5`） | モデル名が正しく渡っている |
| `latency_ms` | 0より大きい数 | 実際に呼び出しが往復した |

5. 続いて `case_data` シート（非表示。タブを右クリック → [再表示]）を開き、`data_key` が `s1_json_failed` の行の `content` を見る。ニセリボンちゃんはJSONを返さないので検証には落ちるが、**受け取った引数がそのまま書き戻されている**ので、渡した中身が正しいかを次の文字で確かめられる。

| 応答の中の文字 | 確認すること |
|---|---|
| `model=gpt-5.5` | モデル名が届いた |
| `tool=リスク提案ナビ:s1` | 呼び出しの名札が届いた |
| `temp=` / `maxTokens=` / `wait=` | 数値が届いた |
| `systemLen=` / `userLen=` | 文章の長さが届いた |
| `effort=` / `verbosity=` | 推論の調整値が届いた |

6. **AI利用枠が上限に達したとき（True側）の確認**:

   1. Excelで空のブックを開き、`Alt` + `F11` でVBEを開く。
   2. 左のツリーで `リボンちゃん(検証用).xlam` の下の `modMockRibbon` をダブルクリックする。
   3. `LimitCheck = False` と書かれた1行を `LimitCheck = True` に**書き換える**。
   4. `Ctrl` + `S` で保存し、Excelをいったん全部閉じる。
   5. `リスク提案ナビ.xlsm` を開き直す。

   **成功の合図**: ブックは**普通に開き**、`ナビ` 画面が出る。そのうえで「お知らせ」欄に「本日のAI利用枠の上限です」のようなAI利用枠の案内が出る。**「開かない」「エラーで止まる」は不合格**である。

   6. 確認できたら **必ず `LimitCheck = False` に戻して保存する**。

**結果の残し方**: 上の表の「期待する値」と「実際に見えた文字」を並べたメモを作り、開発担当へ送る。
