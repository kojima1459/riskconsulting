# 24. 実機テスト手順書（Windows・実Excel）v1.0

## この文書は誰のためのものか

**発注者ご本人が、ご自分のWindowsパソコンと本物のExcelで「リスク提案ナビ」を動かし、合格・不合格をご自分の目で確かめるための手順書**である。プログラミングの知識は不要である。

書いてあるのは次の3つだけである。

1. **打つ文字**（そのままコピーして貼り付ければよい）
2. **何が出たら成功か**（画面に出る文字を1字単位で示す）
3. **うまくいかないときの対処**（§6）

分からない言葉は §7 の用語の言い換えに載せた。**判断に迷ったら先へ進まず、その画面のまま開発担当へ連絡する**のが正しい。

対象タスク: 17章 **T-46④⑤**（出荷前検問の実機分）・**T-14b**（ニセリボンちゃん配管検証）・**T-41**（実機2社完走）。

## 1. 準備（初回だけ・所要60分ほど）

### 1.1 必要なもの

| もの | 条件 | 補足 |
|---|---|---|
| Windows パソコン | Windows 10 または 11（64bit）・メモリ8GB以上 | Mac は使えない |
| Excel | **デスクトップ版**（Microsoft 365 または Office Home & Business） | ブラウザ版・スマホ版は動かない |
| インターネット接続 | 準備のときだけ必要 | テスト自体はネット無しでも動く |

### 1.2 手順1: Python を入れる

1. ブラウザで `https://www.python.org/downloads/windows/` を開く。
2. 「Latest Python 3 Release」を選び、Windows installer (64-bit) をダウンロードする。
3. インストーラを起動したら、最初の画面の下にある **「Add python.exe to PATH」に必ずチェックを入れて**から [Install Now] を押す。

**成功の合図**: スタートメニューで「PowerShell」と打って **Windows PowerShell** を開き、次を貼り付けて Enter を押す。

```
python --version
```

画面に `Python 3.11.9` のように **Python 3.9 以上**の番号が出れば成功である。`python は認識されていません` と出たら、上の「Add python.exe to PATH」のチェックを入れ忘れているので、インストーラをもう一度起動して [Modify] から入れ直す。

### 1.3 手順2: Git を入れる

1. ブラウザで `https://git-scm.com/download/win` を開き、64-bit Git for Windows Setup をダウンロードする。
2. 設定はすべて既定のままで [Next] を押し続けてよい。

**成功の合図**: PowerShell で次を打って、`git version 2.` から始まる行が出れば成功である。

```
git --version
```

### 1.4 手順3: リポジトリ（設計と部品の一式）を取ってくる

PowerShell に**1行ずつ**貼り付けて Enter を押す。

```
cd $env:USERPROFILE
```

```
git clone https://github.com/kojima1459/riskconsulting.git
```

```
cd riskconsulting
```

**成功の合図**: 次を打つと `build` `docs` `src` `tools` `wintest` などのフォルダ名が並ぶ。

```
dir
```

> 開発中の枝（ブランチ）を指定するよう開発担当から言われている場合は、`git checkout <言われた名前>` を続けて打つ。

### 1.5 手順4: Python の部品を2つ入れる

```
python -m pip install --upgrade pip
```

```
python -m pip install openpyxl olefile
```

**成功の合図**: 最後に `Successfully installed openpyxl-3.x.x olefile-0.4x` のような行、または `Requirement already satisfied` が出る。`ERROR` の文字が出ていなければよい。

- `openpyxl` はExcelブックを組み立てるために使う。
- `olefile` はブックに「自分でマクロを組み込む仕掛け」を焼き込むために使う。**入っていないとブックは作れるがマクロが入らない**ので、必ず両方入れる。

### 1.6 手順5: ブックを作る（ビルド）

`cd $env:USERPROFILE\riskconsulting` の状態で、次を1行ずつ打つ。

```
python build\build_rpn.py --dev
```

```
python build\build_rpn.py --prod
```

```
python build\build_rpn.py --kb
```

**成功の合図**: それぞれの最後に「自己検証」の結果が並び、`dist` フォルダに次の3つのファイルができる。

```
dir dist
```

| ファイル名 | 中身 |
|---|---|
| `リスク提案ナビ_dev.xlsm` | 開発版（AIを呼ばずに決まった答えを返す「mock」で動く） |
| `リスク提案ナビ.xlsm` | 本番版（本物のAIリボンを呼ぶ） |
| `ナレッジブック.xlsx` | 知識の台帳（マクロ無し） |

`ERROR:` で始まる行が出て止まった場合は、そのメッセージをそのまま開発担当へ送る。**失敗したビルドは前回の良品を壊さない**設計なので、慌てて消さなくてよい。

> **開発担当からブックを受け取っている場合**: 手順4・5は飛ばしてよい。ただし `wintest` フォルダと `dist` フォルダが**同じ1つのフォルダの中に並んでいる**必要があるので、受け取ったブックを `dist` フォルダに置く。

## 2. T-46④⑤: 自動テストを流して合否を読む

これが**出荷してよいかどうかの本番の検問**である。ここが通らない版は配ってはならない。

### 2.1 打つコマンド

PowerShell で `cd $env:USERPROFILE\riskconsulting` の状態にしてから、次の1行を貼り付ける。

```
powershell -ExecutionPolicy Bypass -File wintest\run_excel_tests.ps1
```

打つと**Excelが自動で立ち上がって勝手に動く**。触らずに待つ。1分から3分ほどで終わり、Excelは自動で閉じる。

### 2.2 何が起きているのか（読まなくても実行できる）

1. Excelの「マクロを使ってよい」という設定を、**この実行のあいだだけ**入れる（終わると元に戻す）。
2. `dist\リスク提案ナビ_dev.xlsm` を開く。ブックが自分でマクロ部品を組み上げる。
3. `wintest\tests_expected.txt` に書いてある**期待テスト本数**を読み込んでExcelへ渡す。
4. テストを全部流す。
5. 結果を `wintest\result_<日付>_<時刻>.log` に保存する。

### 2.3 合格の読み方

画面の最後のほうに、次の形の行が出る。

```
[HH:MM:SS] 実機テスト: 全PASS(FAIL 0 / SKIP 0 / 実行本数 570 = tests_expected 570)
```

**合格はこの3つが同時に成立したときだけ**である。

| 見るところ | 合格の値 | 意味 |
|---|---|---|
| FAIL | **0** | 失敗したテストが1本も無い |
| SKIP | **0** | 飛ばしたテストが1本も無い |
| 実行本数 = tests_expected | **570 = 570** | 流したテストの本数が、あらかじめ決めた本数とぴったり一致する |

つまり **「PASS 570 / FAIL 0 / SKIP 0」が合格**である。

> **なぜ本数まで見るのか**: テストを1本も流さなければ「失敗ゼロ」になってしまう。本数を突き合わせることで「そもそも走っていない」を合格に見せない。数字の `570` は `wintest\tests_expected.txt` の1行目に書いてあり、テストを増やしたときは開発担当が同時に書き換える約束になっている。

### 2.4 不合格の読み方

```
[HH:MM:SS] 実機テスト: NG (FAIL=3 / SKIP=0 / 実行本数=570 / tests_expected=570)
```

このように出たら**不合格**である。次を行う。

1. その上の「---- テスト結果 ----」以降に、失敗したテストの名前が並んでいる。
2. `wintest` フォルダにできた `result_<日付>_<時刻>.log` を**そのまま**開発担当へ送る。
3. **自分で直そうとしない**。ログを送るところまでが仕事である。

### 2.5 本番版でも同じことをする

配布するのは本番版なので、本番版でも1回流す。

```
powershell -ExecutionPolicy Bypass -File wintest\run_excel_tests.ps1 -Target prod
```

読み方は §2.3 と同じである。

### 2.6 いま時点の制限（重要）

17章 T-46④ は「`modTestsPure` と `modTestsExcel` の**両方**が実Excelで全PASS」を求めているが、**`modTestsExcel`（T-47）はまだ作られていない**。したがって現時点で確認できるのは `modTestsPure` の分だけである。

- `run_excel_tests.ps1` は `-ExcelLayerEntry` を渡さなかったとき、ログに次の1行を出す。

```
[HH:MM:SS] 層(b)未指定: -ExcelLayerEntry を渡していないため modTestsExcel は実行していません(T-47)
```

- この行が出ている実行は、**T-46④を満たしていない**（合格扱いにしない）。
- T-47 が完成したら、次の形で流し直す。

```
powershell -ExecutionPolicy Bypass -File wintest\run_excel_tests.ps1 -ExcelLayerEntry "modTestsExcel.RunAllExcelTests"
```

## 3. T-14b: ニセリボンちゃんを登録して「配管」を確かめる

### 3.1 これは何を確かめるのか

本製品は、社内のAI「リボンちゃん」へ**12個の情報を決まった順番で**渡して答えをもらう。会社のPCでないとリボンちゃんは動かないので、**同じ形をした偽物（ニセリボンちゃん）**を自分のPCに入れ、「渡す形そのもの」が正しいかを確かめる。

確かめるのは**AIの答えの良し悪しではなく、渡し方**である。確認するのは次の4点である。

1. 12個の情報が、決めた順番・決めた型どおりに渡ること
2. アドインの名前が**一部でも一致**すればリボンを見つけられること
3. `LimitCheck`（利用上限の確認）が True でも False でも仕様どおりに扱われること（**True でも起動を止めない**）
4. 送った `toolN`（呼び出しの名札）の中身が答えに反映されること

> **注意**: ニセリボンちゃんは**会社のパソコンに入れてはならない**。本物と名前が一部一致するため、本物と取り違える原因になる。個人PCでのみ使う。

### 3.2 ニセリボンちゃんを作る（1回だけ・5分）

1. Excelを起動し、**空のブック**を開く。
2. キーボードで `Alt` を押しながら `F11` を押す（VBEという編集画面が開く）。
3. 上のメニューから **ファイル → ファイルのインポート** を選ぶ。
4. 次のファイルを選ぶ。

```
%USERPROFILE%\riskconsulting\wintest\mock_ribbon\modMockRibbon.bas
```

5. `Alt` + `F11` でExcelの画面へ戻り、`F12`（名前を付けて保存）を押す。
6. **ファイルの種類**を「**Excel アドイン (\*.xlam)**」に変える。
7. **ファイル名**を次のとおりにする（**「リボンちゃん」の6文字を必ず含める**）。

```
リボンちゃん(検証用).xlam
```

8. 保存先は既定のまま（`%APPDATA%\Microsoft\AddIns`）でよい。[保存] を押す。

**成功の合図**: エクスプローラのアドレス欄に `%APPDATA%\Microsoft\AddIns` と打って開くと、`リボンちゃん(検証用).xlam` がある。

> ファイル名に「リボンちゃん」を含めるのは、本製品が config の `ribbon_addin_name`（既定「リボンちゃん」）と**名前の一部が一致するか**でリボンを探すためである。別の名前で保存すると見つけられない。

### 3.3 ニセリボンちゃんを使ってテストする

PowerShell で `cd $env:USERPROFILE\riskconsulting` の状態にしてから、次の1行を貼り付ける（**折り返さず1行で**打つ）。

```
powershell -ExecutionPolicy Bypass -File wintest\run_excel_tests.ps1 -Target prod -MockAddinPath "$env:APPDATA\Microsoft\AddIns\リボンちゃん(検証用).xlam"
```

**成功の合図**: ログの早い段階に次の行が出る。

```
[HH:MM:SS] ニセリボンちゃんを有効化: C:\Users\<あなた>\AppData\Roaming\Microsoft\AddIns\リボンちゃん(検証用).xlam
```

続けて §2.3 と同じ「実機テスト: 全PASS(...)」が出れば、テスト自体は合格である。

**アドインが見つかりません: ...** と出て止まった場合は、§3.2 の保存先とファイル名を見直す。

### 3.4 4点を目で確かめる（配管の確認）

自動テストは「落ちないこと」までしか見ない。**渡した中身**は次の手順で目視する。

0. Excel を開き、[ファイル] → [オプション] → [アドイン] → 下の「管理: Excel アドイン」で [設定] を押し、**`リボンちゃん(検証用)` にチェックが入っている**ことを確認する（§3.3 の実行で有効化されているが、消えていたらここで入れる）。
1. Excel で `dist\リスク提案ナビ.xlsm`（本番版）を開く。
2. `HOME` シートで [＋新規案件] を押し、企業名などを適当に埋めて [保存して戻る]。
3. `HOME` で Step個別の [S1] を押す。
4. 実行後、シート見出しを右クリック → 「再表示」で **`run_log`** シートを開く。

**見るところ**:

| 列 | 期待する値 | 意味 |
|---|---|---|
| `transport` | `ribbon` | ニセリボンちゃん経由で呼べた（=アドイン名の部分一致で見つけた。確認点2） |
| `model` | config の `recommended_model` の値（既定 `gpt-5.5`） | モデル名が6番目の引数として渡っている（確認点1） |
| `latency_ms` | 0より大きい数 | 実際に呼び出しが往復した |

5. 続いて `case_data` シートを開き、`data_key` が `s1_json_failed` の行の `content` を見る。ニセリボンちゃんはJSONを返さないので検証には落ちるが、**受け取った引数がそのまま書き戻されている**ので、次が読める。

| 応答の中の文字 | 確認すること |
|---|---|
| `model=gpt-5.5` | 6番目の `optModel` が届いた |
| `tool=リスク提案ナビ:s1` | 9番目の `toolN` の中身が届いた（**確認点4**）。`リスク提案ナビ:` の部分は config の `app_tool_prefix` である |
| `temp=` / `maxTokens=` / `wait=` | 3・4・5番目の数値が届いた（**確認点1**） |
| `systemLen=` / `userLen=` | 1・2番目の文字列が届いた |
| `effort=` / `verbosity=` | 10・11番目が届いた |

6. **確認点3（LimitCheck の True / False 両方）**: ニセリボンちゃんの `LimitCheck` は既定で `False`（続行可）を返す。**False側**は、いまブックが普通に開けて `HOME` が出ていることがそのまま合格である。**True側**は次の手順で確かめる。

   1. Excel で空のブックを開き、`Alt` + `F11` でVBEを開く。
   2. 左のツリーで `リボンちゃん(検証用).xlam` の下の `modMockRibbon` をダブルクリックする。
   3. `LimitCheck = False` と書かれた1行を `LimitCheck = True` に**書き換える**。
   4. `Ctrl` + `S` で保存し、Excelをいったん全部閉じる。
   5. `dist\リスク提案ナビ.xlsm` を開き直す。

   **成功の合図**: ブックは**普通に開き**、`HOME` 画面が出る。そのうえで `HOME` の警告欄（`hm_warning`）にAI利用枠の案内が出る。**「開かない」「エラーで止まる」は不合格**である。仕様上、`LimitCheck` が `True`（上限に達した）でも起動は止めず案内だけを出す（12章§2.1 手順⑦）。

   6. 確認できたら **必ず `LimitCheck = False` に戻して保存する**。

7. `config` シートの `limit_check` を `FALSE` にすると、`LimitCheck` を**呼ばずに** False 扱いで通す（`usage_log` に記録は残らない）。この動作も1回確認したら、**`limit_check` を `TRUE` に戻す**。

**結果の残し方**: 上の表の「期待する値」と「実際に見えた文字」を並べた1枚の表を作り、開発担当へ送る。

## 4. T-41: 本物のAIで実在2社を通す（会社のパソコンで行う）

**この章だけは会社のパソコン（本物のリボンちゃんが入っているPC）で行う。** 個人PCでは本物のAIを呼べない。

### 4.1 準備

1. `dist\リスク提案ナビ.xlsm`（**本番版**）を会社PCの作業フォルダへコピーする。
2. `dist\ナレッジブック.xlsx` を、社内の共有フォルダへ置く。
3. ブックを開き、シート見出しの右クリック →「再表示」で `config` シートを開き、次を確認・修正する。

| `name` | あるべき `value` |
|---|---|

6. `HOME` の**赤帯が消えていること**を確認する。赤帯（「デモ／開発経路で動作中です」）が出ている間は本物のAIを使っていない。

### 4.4 最後に: 検証結果の集計（T-41のDoD）

シート見出しを右クリック →「再表示」で **`run_log`** シートを開き、**`validate_result` 列**の値を数える。

| 値 | 意味 | 目安 |
|---|---|---|
| `ok` | 1回目の答えがそのまま合格した | 多いほどよい |
| `repaired` | 1回作り直させて合格した | 数件なら正常 |
| `failed` | 作り直しても合格しなかった | **0が望ましい**。あれば開発担当へ報告 |

**数え方**（ブックに数式を書き足さない方法）:

1. `run_log` シートの見出し行を選び、[データ] タブの [フィルター] を押す。
2. `validate_result` 列の矢印を押し、`ok` だけにチェックを入れる。
3. 画面**右下のステータスバー**に「N レコード中 M 個が見つかりました」と出る。その M が件数である。
4. 同じ手順で `repaired` と `failed` も数える。
5. 数え終わったら**フィルターを解除**し、`run_log` シートを非表示に戻す。

> **ブックのセルに数式を書き込まない。** この製品はセルへの数式書込を避ける設計（16章 E-46）であり、手で足した数式が残ると後の検査を惑わせる。

**報告する内容**: 2社ぶんの `ok` / `repaired` / `failed` の件数と、`err_log` シートに増えた行（`err_code` と `logged_at` だけでよい。**本文は記録されない**設計である）。

## 6. うまくいかないときの対処

### 6.1 ブックを開いたら「はじめにお読みください」だけが見えて、他の画面が無い

**原因**: マクロが動いていない。

**対処**:

1. 画面の上のほうに黄色い帯で「セキュリティの警告 マクロが無効にされました」と出ていないか見る。出ていれば [**コンテンツの有効化**] を押す。
2. 押すとこのシートは自動で隠れ、`HOME` が出る。これが正常である。

### 6.2 黄色い帯ではなく、赤い帯で「信頼できないソース」と出て開けない

**原因**: インターネットや他のPCから受け取ったファイルに、Windowsが「危険かもしれない」という印（ブロック）を付けている。

**対処（ブロックの解除）**:

1. エクスプローラでブックのファイルを**右クリック** → [プロパティ]。
2. 「全般」タブの一番下に **[許可する]** または **[ブロックの解除]** のチェックボックスがあるので、チェックを入れる。
3. [OK] を押してからブックを開き直す。

### 6.3 開くたびに毎回マクロの確認が出るのが煩わしい

**対処（信頼できる場所の登録）**: ブックを置くフォルダを1つ決めて登録する。

1. Excelを開き、[ファイル] → [オプション] → [トラスト センター] → [トラスト センターの設定] を押す。
2. 左の [**信頼できる場所**] を選び、[新しい場所の追加] を押す。
3. [参照] でブックを置いているフォルダ（例: `C:\Users\<あなた>\riskconsulting\dist`）を選ぶ。
4. 「この場所のサブフォルダーも信頼する」にチェックを入れて [OK]。

> **注意**: 信頼できる場所に登録したフォルダのマクロは確認なしで動く。**そこには自分が中身を知っているファイルだけを置く**。

### 6.4 `HOME` の警告欄に「本日のAI利用枠上限です」と出た

**原因**: 社内AIリボンの1日の利用上限（LimitCheck）に達した。

**対処**:

- **起動も画面操作も止まらない**設計である。翌日以降にやり直す。
- 途中まで通ったStepの結果は残っている。`案件一覧` の `status` と `last_ok_step` を見て、続きのStepから押し直せばよい。
- 壁打ちで上限に当たった場合は、`config` の `sparring_max_turns` を小さくして往復数を減らしてから再開する。

### 6.5 `HOME` の赤帯（デモ／開発経路で動作中です）が消えない

**原因**: 開発版のブックを開いている、または `config` の `mock_llm` が `TRUE` になっている。

**対処**: `dist\リスク提案ナビ.xlsm`（`_dev` が付かないほう）を開く。それでも消えないときは `config` の `mock_llm` を `FALSE`、`llm_transport` を `ribbon` にしてブックを開き直す。

### 6.6 `HOME` に「ナレッジが読めていません（管理者にご連絡ください）」と出る

**原因**: `config` の `kb_path` が実際のナレッジブックの場所と違う、または共有フォルダにつながっていない。

**対処**:

1. エクスプローラでナレッジブックの場所を開き、アドレス欄のパスをコピーする。
2. `config` シートの `kb_path` の `value` に貼り付ける。
3. `HOME` の [ナレッジ再読込] を押す。「読込OK（メニューN/型N/事例N）」が出れば直っている。

> 一度でも読めたことがあれば、次からはブック内の退避（スナップショット）で「前回の知識」で動き続ける。読めていないまま実行すると提案の質が落ちるので、必ず直してから使う。

### 6.7 PowerShell で「このシステムではスクリプトの実行が無効になっています」と出る

**対処**: §2.1 のコマンドは `-ExecutionPolicy Bypass` を含んでいるのでこの1回だけ許可される。**コマンドを一部だけ切り取って貼らず、行ごとまるごと**貼り付ける。

### 6.8 テストの途中でExcelが固まった／閉じない

**対処**:

1. 5分待っても動かないときは、Ctrl+Shift+Esc でタスクマネージャーを開き、`Microsoft Excel` を選んで [タスクの終了]。
2. `wintest` フォルダの `result_<日付>_<時刻>.log` を開発担当へ送る。
3. もう一度 §2.1 から流し直す。ブックは壊れていない。

### 6.9 `ビルド成果物が見つかりません: ...` と出る

**原因**: §1.6 のビルドがまだ済んでいない、またはブックの置き場所が違う。

**対処**: `dir dist` で `リスク提案ナビ_dev.xlsm` があるか見る。無ければ §1.6 をやり直す。

### 6.10 `wintest\tests_expected.txt がありません` と出る

**原因**: リポジトリの一部しかコピーされていない。

**対処**: §1.4 からやり直し、`wintest` フォルダごと揃った状態にする。

## 7. 用語の言い換え

| 出てくる言葉 | 意味 |
|---|---|
| PowerShell | Windows に最初から入っている「文字で命令する画面」 |
| リポジトリ | 設計書とプログラムの部品が入った一式のフォルダ |
| クローン（clone） | そのフォルダ一式を自分のPCへ丸ごと持ってくること |
| ビルド | 部品からExcelブックを組み立てること |
| 成果物 | 組み上がったExcelブック（`dist` フォルダに出る） |
| マクロ | Excelの中で動くプログラム。本製品はこれで動く |
| アドイン（.xlam） | Excelに機能を足す部品ファイル |
| mock（モック） | AIを呼ばずに、あらかじめ決めた答えを返す練習用の仕組み |
| ニセリボンちゃん | 本物のAIリボンと同じ形をした偽物。渡し方だけを確かめる |
| 層(a) / 層(b) | (a)=中身の計算のテスト、(b)=本物のExcelでしか確かめられないテスト。**出荷の条件は(b)** |
| PASS / FAIL / SKIP | 合格 / 不合格 / 飛ばした |
| run_log | AIを1回呼ぶごとに1行残る記録シート |
| err_log | 異常があったときだけ行が増える記録シート |
| validate_result | AIの答えが検査に通ったかの結果（ok / repaired / failed） |
