# 25. リスク提案ナビ 利用ガイド v5.0

v5.0変更概要（W12-A・裁定書34「HTML画面の正式採用と統合」）: **利用者が触る画面をHTML画面（モードレスの1枚窓）へ切り替えた**。**第0部**を新設し、HTML画面での起動・画面の作り・操作を1枚にまとめた（呼び名の対応は「区画」①〜④＝会社情報／資料登録／分析／出力で不変、コーチ帯のSTEP表記はHTML画面には無い＝区画番号だけで進む）。「クリップボードから取り込む」ボタンは無く、貼付欄は「ここをクリックして Ctrl+V」。従来の第1部（シート画面`ナビ`の説明）は**削除せず**、「**第1部（予備: `ui_mode=sheet`）**」として残す（ActiveXが無効化された端末・`ui`フォルダ欠損時の逃げ道）。第2部（管理者向け）は変更なし。

v4.0変更概要（W6第1弾: ナビ画面への統合を反映）: v3.1までの `HOME`／`案件入力`／`操作ガイド` の3タブは廃止され、**`ナビ`（帯＋4区画）＋`使い方`の2タブへ統合**された。本書の全ボタン名・シート名を実装（`src/ui/modUINav.bas` の配置表・`src/ui/modUINavDraw.bas`・`build/build_rpn.py` の使い方タブ）から1字単位で引用し直した。旧①〜⑤の5本キャプションは廃止され、区画の見出しが番号（①〜④）を持つ。第2部の配布・検問手順は宛先タブ名だけを更新し、内容は不変。

**過去版の変更概要は当時の記録（履歴）であり、現行のボタン名へは同期しない**（現行の名前は本v4.0変更概要と §1〜§7 が正である）。

本書は2部構成である。**第1部は営業担当者向けの1枚**（これだけ読めば使える）、**第2部は管理者向け**（ナレッジブックの更新・配布・15分スモークチェック）である。ブックを開いたあとは、緑色の「使い方」タブにも同じ内容の早見表がある。

対象タスク: 17章 **T-44**（利用ガイド1枚＋15分スモークチェックリスト＋配布パッケージ）。

# 第0部 営業担当者向け（HTML画面・1枚。v5.0正）

## 0. これは何をする道具か

会社のホームページや調べた文章を貼ると、AIが **①企業プロファイル → ②リスク仮説 → ③提案 → ④提案骨子** の4段階で下書きを作る。**下書きであり、確認と修正は人が行う**。

出るもの: **リスクレポート（HTML・ブラウザで開く）** と **ヒアリングシート（A4 1枚・訪問で使う）**。

操作の起点は常に1つの画面である。**Excelを開くと、モードレスの別窓（HTML画面）が「準備完了です」の表示で開く**。左ペインの「ナビ」タブに①〜④の区画が並び、右ペインには会社の中身（登録資料・S1〜S4・レポート等）を見るビューがある。左ペインには「案件チャット」「壁打ち」のタブもある。

## 1. 起動

1. `リスク提案ナビ.xlsm` をダブルクリックで開く（起動bat経由が既定。docs/24§1参照）。
2. 上に黄色い帯で「セキュリティの警告」が出たら [**コンテンツの有効化**] を押す。
3. **HTML画面（モードレスの別窓）が開き「準備完了です」と出れば準備完了である。** Excel本体のシートは開かなくてよい。

**赤い帯が出ていたら**: 「デモ／開発経路で動作中です（本番の判断に使わないでください）」と出ている間は練習用の応答が返る。**その結果をお客様に見せてはならない**。管理者へ連絡する。

**この画面が出ないとき**: 従来のシート画面`ナビ`が出た場合は、`ui`フォルダが本体と同じ場所に無いか、この端末のセキュリティ設定でActiveXが無効化されている（第1部・予備画面を参照して操作を続けられる）。

## 2. 画面の作り: 5領域＋4区画

HTML画面は次の領域からなる。

| 領域 | 内容 |
|---|---|
| 上段 | ブランド表示・[新規案件][案件を取り込む][設定][終了] |
| 案件バー | 案件セレクト・[名前を変更][エクスポート][案件を削除]・AI接続表示 |
| 左ペイン | タブ3枚: **ナビ**（下表の4区画）／**案件チャット**（この案件についてAIに質問できる）／**壁打ち**（お客様役との予行演習） |
| 右ペイン | 概要／登録資料／S1企業／S2リスク／S3提案／S4骨子／ヒアリング／レポート／ログの各ビュー |
| 下段 | 状態文・保存先 |

「ナビ」タブの中の4区画は次のとおり。

| 区画 | 見出し | 中身 |
|---|---|---|
| ① | 会社情報 | 種別・会社名・業種名・本社の場所を入れると、社内ディープリサーチに貼る文が並ぶ |
| ② | 資料登録 | 6つの登録欄と[登録内容を保存] |
| ③ | 分析 | [まとめて分析] |
| ④ | 出力 | [レポート出力][ヒアリングシート出力][下書きを見る] |

**新しい案件の作り方**: 上段の[新規案件]、または案件セレクトを空のままにすると案件IDの欄に自動で **`(新規)`** と出る（採番は②の[登録内容を保存]を押したときに自動で行われる）。

## 3. ① 会社情報（社内ディープリサーチに投げる文を作る）

区画①へ、種別・会社名・業種名・本社の場所の4つを入れる。詳細な使い方（調べる文の内容・投げる順番）は第1部§3と同じである（区画の呼び名だけが「会社のこと」→「会社情報」に変わった）。

## 4. ② 資料登録

区画②の各欄には「ここをクリックして Ctrl+V」のラベルが出ている（**クリップボードから取り込むボタンは無い**。裁定書34 §0-5）。欄をクリックしてCtrl+Vで貼り付けると、その場で字数と時刻が出て自動保存される。欄の内容・貼るものは第1部§4の表と同じである（「貼る」という区画名は「資料登録」に変わり、ボタン名は[登録][中身を見る][消す][登録内容を保存]）。

## 5. ③ 分析・④ 出力・案件チャット・壁打ち

[まとめて分析]（区画③）・[レポート出力][ヒアリングシート出力](区画④)は第1部§5・§6と同じ手順である。**案件チャット**（左ペインの新タブ）では、選択中の案件の内容についてAIに質問できる（例:「いちばんのリスクは何か」「このギャップを1分で説明して」）。会話によって案件のデータは変更されない。伏字（お名前など）はAIに渡る前に置き換える。

## 6. 訪問後・やってはいけないこと・困ったとき

第1部§【6】・「やってはいけないこと」・「困ったとき」と同じ内容を、区画の呼び名（①〜④）を読み替えて適用する。

# 第1部（予備: `ui_mode=sheet`）営業担当者向け（1枚）

## 0. これは何をする道具か

会社のホームページや調べた文章を貼ると、AIが **①企業プロファイル → ②リスク仮説 → ③提案 → ④提案骨子** の4段階で下書きを作る。**下書きであり、確認と修正は人が行う**。

出るもの: **リスクレポート（HTML・ブラウザで開く）** と **ヒアリングシート（A4 1枚・訪問で使う）**。

操作の起点は常に1つの画面 **`ナビ`** である。最上段の帯（コーチ帯）に、いま何をすべきかが1文で常に出ている。迷ったときは帯の[**使い方を開く**]を押す。

## 1. 起動

1. `リスク提案ナビ.xlsm` をダブルクリックで開く。
2. 上に黄色い帯で「セキュリティの警告」が出たら [**コンテンツの有効化**] を押す。
3. `はじめにお読みください` のシートが自動で隠れ、**`ナビ`** が出れば準備完了である。初めて開いたときは画面の真ん中に案内カードが3枚出るので、[次へ]で読み進める（あとから帯の[使い方を開く]→「使い方」タブの[ツアーをもう一度見る]で見返せる）。

**赤い帯が出ていたら**: 「デモ／開発経路で動作中です（本番の判断に使わないでください）」と出ている間は練習用の応答が返る。**その結果をお客様に見せてはならない**。管理者へ連絡する。

## 2. 画面の作り: 帯＋4区画

`ナビ` は最上段の**帯**（`STEP n/6`・進捗ドット・いま何をするかの1文・案件のプルダウン・[← 戻る][次へ →][ナレッジを読み直す][使い方を開く]）と、その下に縦に並ぶ**4つの区画**からなる。

| 区画 | 見出し | 中身 |
|---|---|---|
| ① | 会社のこと | 種別・会社名・業種名・本社の場所を入れると、社内ディープリサーチに貼る文が並ぶ |
| ② | 貼る | 6つの貼付欄と[貼ったものを保存する] |
| ③ | 作る | [まとめて作る] |
| ④ | 出す | [レポートを出す][ヒアリングシートを出す][下書きを見る] |

**新しい案件の作り方**: 帯の案件プルダウンで**何も選ばない（空のまま）**と、案件IDの欄に自動で **`(新規)`** と出る（この時点ではまだ案件は作られていない。採番は②の[貼ったものを保存する]を押したときに自動で行われる）。

## 3. ① 会社のこと（社内ディープリサーチに投げる文を作る）

区画①へ、種別・会社名・業種名・本社の場所の4つを入れる。

| 埋めるもの | 説明 |
|---|---|
| 種別 | **新規開拓** か **更新**。更新のときは区画②に「いまの契約」の欄が現れる |
| 企業名・業種 | 業種コードと業種名は**業種マスタ由来の一覧から選ぶ**（ナレッジに接続できていないときは一覧が出ないので手入力する） |
| 本社の場所 | 必須。似た名前の別会社が混ざるのを防ぐ |

4つを入れると、すぐ下に社内ディープリサーチに貼る文が**標準3本**（1本目 会社の基本／2本目 リスクの兆候／3本目 調達・仕入れの構造）並ぶ。さらに調べたいときは[**＋ もっと調べる（あと5本）**]を押すと補助5本（業界と競合／世の中の動きとの関係／前回の更新からの変化／拠点の災害リスク／決算のハイライト）が出る。

1. 文の右の[**コピー**]を押すと、その1本ぶんが写る。社内のディープリサーチに貼って投げる。
2. **1本ずつしか投げられません。返ってきてから次を投げてください。**（各10分ほど）
3. 返ってきた文章は、②の`調べた結果`へ貼る。

## 4. ② 貼る（6つの欄）

上から順に貼る。**空でよい欄もある**。**1つの欄は約32,000字(A4で約20枚)まで**。

| 欄 | 必須 | 何を貼るか |
|---|---|---|
| 調べた結果 | 任意 | 社内のディープリサーチから返ってきた文章。**3本ぶんを続けて貼れる** |
| 会社のホームページ | **必須** | 会社概要・事業内容・沿革のページ |
| 有価証券報告書のリスクの章 | 任意 | 上場していない会社なら空のままでよい |
| いまの契約 | 更新のときだけ表示 | いま入っている保険の一覧。証券や更新案内の文章のまま |
| 現場メモ | 任意 | 【営業メモ】【前回更新メモ】【付保の見立て】【そのほか】の4見出しが先置きされている。見出しの下に書き足す |
| ヒアリング回答 | 任意 | 訪問して聞いてきたこと。第2ラウンド用 |

**押すと何が起きる**: [**ここに貼る**]を押すと、表の線や画像が入らずに文だけが入り、状態行に「貼り付け済み　9,812字　（14:03 に貼りました）」と出る。**この時刻は貼ったときの時刻であり、画面を開き直しても書き換わらない**。枠には `┈┈┈ 先頭だけお見せします ┈┈┈` の1行に続けて先頭の5行だけが出る（途中で切れて保存されたわけではない）。既知フッター（役職コード等）が付いていたら、成功の案内に「（末尾のシステムの表示は取り除きました）」が添えられる。

**うまくいかないとき**:

| 出る文 | すること |
|---|---|
| 「貼り付けられませんでした。…」 | もう一度コピーしてから[ここに貼る]を押す |
| 「画面を正しく開けませんでした。いちばん上の帯の[ナレッジを読み直す]を押すか、ブックを開き直してください。」 | 書いてあるとおりにする（画面が途中までしか描けていないので、そのまま貼らせない） |
| 「現場メモが枠に入りきりませんでした。いちばん下の余った行を切り取って、別の見出しの下へ貼ってください。」 | 現場メモは60行までである。**1行も書かれていない**ので、余った行を切り取ってから貼り直す |
| 「〈欄名〉が枠に入りきりませんでした。…」（Ctrl+V で直に貼ったとき） | その欄だけが保存されていない。[ここに貼る]で貼り直すと長さを気にせず入る |
| 「〈欄名〉の枠の中に、貼り付けで入った表の線や画像があります。…」 | 枠の中の表や画像を消してから、[ここに貼る]で貼り直す |

貼り終えたら区画②の [**貼ったものを保存する**] を押す。

## 5. ③ 作る

区画③の[**まとめて作る**]を押す。

- **画面が白くなっても触らない。閉じない。** 処理は続いている。
- 終わると**画面の右上に白いカード（トースト）**が出て、次にやることが出る（「できました。④の[レポートを出す]を押してください」）。カードは文の長さに応じて3〜9秒ほどで自分で消える（長い案内ほど長く残る）。

**途中で止まったら**: 帯の下の「お知らせ」欄に理由が出る。「本日のAI利用枠の上限です」なら翌日に続きから押し直す。**すでに通った段の結果は消えない。**

## 6. 中身を直す

出来上がった `S1_企業プロファイル` `S2_リスク仮説` `S3_提案` `S4_骨子` のシートは、区画④の[**下書きを見る**]で開き、**直接書き換えてよい**。

- 直したら、そのシートの次へ進むボタンを押す。ボタンの名前はシートごとに違い、`S1_企業プロファイル` は [**S2へ進む**]、`S2_リスク仮説` は [**S3へ進む**]、`S3_提案` は [**S4へ進む**]、`S4_骨子` は [**ヒアリングシート生成**] である（各シートには [**S1から再実行**] のように、その段をやり直すボタンも並んでいる）。押すと**その先の段だけ**作り直される（確認のダイアログが出る）。
- 決まった選択肢の欄は一覧から選ぶ。一覧に無い言葉を手で書くと保存が止まる。
- 直した内容は次の段に必ず反映される。

## 7. ④ 出す

### レポートを出す

区画④の [**レポートを出す**] を押す。

- 「お知らせ」欄に「リスクレポートを出力しました: <パス>」が出る。そのファイルをダブルクリックするとブラウザで開く。
- あわせて**画面の右上に白いカード（トースト）**が出て、次にやることが出る（「レポートを出しました。次は④の[ヒアリングシートを出す]です」）。
- ファイル名には出力日が入る（`<会社名>_<8桁>_リスクレポート_<yyyymmdd>.html`）。同じ日にもう一度出しても**前のファイルは上書きされず** `_2` `_3` と別ファイルが増える。
- **5×5のリスクマップ**と**カバレッジ表**が絵で出る。1つのファイルで完結しているのでメール添付でも崩れない。
- 末尾の「出典と根拠」に**出典の表**（出典 / URL / 観点）が出る。**貼り付けた資料の中にそのまま書かれていたURLだけ**が並ぶ（アプリがURLを作ることはない）。URLは文字として載せてあるので、確かめるときはコピーしてブラウザへ貼る（リンクにはしていない）。
- 貼った資料の中で**同じ項目に違う値**があったときは、「企業理解」と「入力の充足度」の先頭に「**資料間で値が食い違っています**」として分けて出る。どちらかを正としては書かないので、一次資料でご確認いただきたい。
- **S1が終わっていないと出せない**。「先にStep1を実行してください。」が出たら③の[まとめて作る]を押すか、④の[下書きを見る]から `S1_企業プロファイル` の[S1から再実行]を押す。
- レポートの末尾に「本資料はAI支援により作成した骨子を人が確認・編集したものです」が自動で入る。**消さない。**

### ヒアリングシートを出す

区画④の [**ヒアリングシートを出す**] を押す（`S4_骨子` シートの [ヒアリングシート生成] でも同じ）。

- `ヒアリングシート` シートに質問が並ぶ。**回答欄は空**である。
- 押すと**画面の右上に白いカード（トースト）**が出て、次にやることが出る（「ヒアリングシートができました。Ctrl+Pで印刷できます」）。
- Ctrl+P で **A4縦1枚**に印刷し、訪問先で手書きで埋める使い方を想定している。
- このシートに書いた回答は自動では取り込まれない。次の§8で自分で貼る。

### 保存先（作ったものはどこに置かれるか）

**レポートと企業ファイルは、会社の OneDrive の中の `リスク提案ナビ\データ` に置かれる**（v3.4・裁定書27 W9-C2）。
OneDrive に置くのは、**会社PCの `D:` ドライブはシャットダウンで中身が消える**からである。作ったものが
消えると、翌日にもう一度AIを回すことになる（利用枠も時間も無駄になる）。

置き場所は次の順で自動的に決まる（v6.1・裁定書31）。**利用者が設定する必要は無い。**

1. **起動ボタン（`リスク提案ナビを起動`）が書いた `data_dir.txt`** が指す OneDrive のフォルダ
2. 管理者が `config` の `data_dir` に書いた場所（ふつうは空。`%…%` のような環境変数は使えない）
3. どちらも無ければ、本体と同じフォルダの `データ`（＝ふつうは `D:\リスク提案ナビ\データ`）

**3番目になったときは、ナビの「お知らせ」欄に**
「保存先が確認できません。『リスク提案ナビを起動』から開き直してください。
このまま使うと、保存したものはこのパソコンの再起動で消えることがあります。」
**と出る。** これは `.xlsm` を直接ダブルクリックして開いたときに出る案内である。いったん閉じて、
OneDrive の配布フォルダにある**起動ボタンから開き直す**こと。それでも出るなら情シス（端末サポート）へ相談する。

保存先を変えたいときは管理者が `config` シートの `data_dir` を書き換える（§14.4）。

## 8. 訪問後の第2ラウンド

1. `ナビ` の帯で対象案件を選び、区画②の `ヒアリング回答` に聞いてきた内容を貼って[貼ったものを保存する]を押す。
2. 区画③の[**まとめて作る**]を押すか、④の[下書きを見る]から `S2_リスク仮説` の[S2から再実行]を押す（Step2から作り直す）。
3. §7 でレポートとヒアリングシートを出し直す。

**前回のS2を残してから始めたいとき**は、1. の前に [**使い方を開く**] → 「使い方」タブ「⑦ 上級」の [**第2ラウンドを始める**] を押す。確認のダイアログで[はい]を選ぶと、いまのS2が「前のラウンド」として控えられ、何巡目かが1つ進む。**この操作をしないでS2を作り直すと、前のラウンドの内容は残らない**（上書きされる）ので、比べたいときは先に押しておく。

⑦ 上級の1行の説明（画面に出る文）: 「訪問して聞いてきたことを②へ貼り、もう一度作り直したいときに使います。」

## 9. 座組を考えたいとき（壁打ち）

`ナビ` の帯の [**使い方を開く**] → 「使い方」タブ「⑦ 上級」の[**表示する**]で `壁打ち` シートを出す。

1. [**壁打ちを開始/再開**] を押す（案件の材料・S1～S3・型・機構がAIへ渡る）。押した時点でその案件の**調査の深さ**が自動で **壁打ち** に上がる。
2. 入力欄に書いて [**送信**]。何往復でもできる。
3. よい気づきが出たら、その発話を選んで [**受信箱へ**] を押す。商品部の受信箱へ「現場の声」として届く。
4. 結論は自分で `S2` / `S3` シートへ反映する（[**S3を開く**] ボタンがある）。
5. 履歴は案件に保存される。次に [壁打ちを開始/再開] を押せば続きから話せる。

## 11. やってはいけないこと

- **赤帯が出た状態の出力をお客様に見せない。**
- **個人名を入力しない。** 顧客の発言に個人名が混ざると確認のダイアログが出る。伏字にして保存する。
- **AIの出力をそのまま提出しない。** 必ず読んで直す。
- **実行中にブックを閉じない。**

# 第2部 管理者向け

## 13. ナレッジブックの更新

ナレッジブック（`ナレッジブック.xlsx`）は**マクロ無しのExcelファイル**で、共有フォルダ（社内の共有が使えない環境では利用者のPC内の1か所）に1つだけ置く。**本体ブックを配り直さずに知識だけ更新できる**のが要点である。

### 13.1 更新できるシート

| シート | 中身 |
|---|---|
| `業種マスタ` / `リスクライブラリ` / `メニュー一覧` / `種目マスタ` / `メニュー種目対応` / `成功事例` | 基礎の6シート |
| `判断基準` | 保険原理・生存文法・棄却類型のルール行 |
| `パターンマスタ` | 汎用座組パターン P1～P15 |
| `型ライブラリ` | 具体の型（実績・候補・他社実績） |
| `機構ライブラリ` | 掛け合わせ用の部品（Phase 1.5） |
| `適用先候補` | 裏受け・バンドル先企業 |
| `巡回リスト` / `ウォッチログ` | ウォッチ用（Phase 1.5） |
| `研究テーマ一覧` | プリフライト診断の重複照合用 |
| `新サービス候補` | **本体が自動で追記する**。管理者は読むだけでよい |

### 13.2 更新の手順

1. ナレッジブックを開く（**誰かが本体ブックを使っている最中でも読み取りは競合しない**。書き込みは1人ずつ行う）。
2. 行を足す・直す。**列の見出しは変えない**。
3. 決まった選択肢の列は19章の値だけを使う。特に `リスクライブラリ` の `category` は **リスクユニバース10分類**のいずれかでなければならない。旧6分類の行は 13章§3.1 の読替表で変換してから入れる。
4. 保存して閉じる。
5. 利用者は `ナビ` の帯の [**ナレッジを読み直す**] を押すだけで新しい知識に切り替わる。押さなくても次回起動時に読み込まれる。

### 13.3 更新後の確認

| 見るところ | 期待 |
|---|---|
| `ナビ` のナレッジ欄 | 「読込OK（メニューN/型N/事例N）」の N が増えている |
| 案件を1本流す | S3の提案に新しいメニュー・型が現れる |
| `err_log` | E0401（ナレッジブック接続不可）・E0402（ナレッジブック検査不合格）が増えていない |

**注意**: 存在しないIDを本体が返すと E0301 で止まる仕組みなので、**IDの綴りを間違えると提案が落ちる**。ID列は必ず既存の書式（`M-0012` `L-03` `S-0004` `K-0003` `P9` `MC-0107` の形）に揃える。

### 13.4 新サービス候補の回収

「該当メニュー・型なし」と判定されたリスクは、本体が `新サービス候補` シートへ自動で追記する。共有フォルダにつながらなかった分はローカルに退避され、次回起動時に無音で再送される。**月次の編集会でこのシートを棚卸しする**のが運用である。

## 14. 配布

### 14.1 配布経路（会社PCはターミナル・インストーラを使えない前提）

配布はチャットから**メール添付**で行う。手順の詳細は24章§1を見る。要点だけ書く。

1. 開発担当がチャットで**2つ**のExcelファイル（`リスク提案ナビ.xlsm`・`ナレッジブック.xlsx`）を渡す（開発版 `リスク提案ナビ_dev.xlsm` は**開発専用**であり利用者へは渡さない）。
2. 利用者が私物PCのGmailから、会社アドレスへ**xlsmのまま添付**して送る。**zipにはしない**（社内メールがzip添付をはじくため、実機で確認済み）。
3. 会社PCで受け取り、デスクトップなど1か所に保存する。

| ファイル | 置き場所 |
|---|---|
| `リスク提案ナビ.xlsm`（本番版） | 利用者のPC（メールで受け取った場所） |
| `ナレッジブック.xlsx` | **本体ブックと同じフォルダ**（推奨。起動時に自動で見つかる＝`kb_path` を触らなくてよい）。共有フォルダに置く運用のときは §14.4 の `kb_path` を書く |
| 本書（25章 第1部） | 印刷またはPDFで配る |

**`リスク提案ナビ_dev.xlsm`（開発版・練習用）は利用者へ配らない＝開発専用である。** 練習用の応答を返すため、実案件に使われると事故になる（開発側の配管検証＝24章§8.5 ニセリボンちゃんのときだけ、開発担当が個人PCで使う）。

Phase 1は「案件使い切り」運用である。**利用者は旧版を自分で新版に置き換える**（案件データの移行機能は持たない）。したがって、

- 新版を配るのは**案件の切れ目**を狙う。
- 旧版で走っている案件は、旧版のまま完了させてよい。
- ナレッジブックの更新は本体の再配布を伴わない（§13）。

| S-21 | `err_log` | 行が増えていない（増えていたら `err_code` を控えて開発担当へ） | [ ] |
| S-22 | 確認が終わったら | `config` など**再表示した非表示シートだけ**を非表示に戻す（`err_log` / `run_log` / `usage_log` は見えたままでよい） | [ ] |

### 15.5 判定

**S-1 から S-22 のすべてに印が付いたときだけ**、その版を使ってよい。1つでも欠けたら使い始めず、欠けた番号を添えて開発担当へ連絡する。

## 16. 運用の定例

| 頻度 | やること |
|---|---|
| 随時 | ナレッジブックの更新（§13）。本体の再配布は不要 |
| 月次 | 編集会で受信箱と型候補を採択・却下 → ナレッジブックへ反映。`新サービス候補` の棚卸し |
| 月次 | `run_log` の集計（`repaired` / `failed` の率、所要時間、警告率）。`failed` が増え続けるならプロンプトの見直しを検討する |
| 四半期 | `recommended_model` の追随。型生成バッチと勝ち筋仮説のレビュー |
