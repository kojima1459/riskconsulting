# 25. リスク提案ナビ 利用ガイド v3.0

v3.0変更概要（裁定書14: W5「社内環境対応+UI/UX改善」）: HOME画面が「番号つき動線」（上段の主要ボタン4つ [① 案件を作る][② 一括実行][③ レポートを出す][④ ヒアリングシート] と、その下の「くわしい操作」区画）へ改修されたのに合わせ、第1部を①～④の順番で読めるように全面書き直した。用語も平易化した（収集ティア→**調査の深さ**／クイック→**かんたん調査**／フルドシエ→**しっかり調査**／追加ドシエ→**追加調査の結果**）。第2部（管理者向け）は用語を同期し、配布経路をメール添付（zip不可）に更新した。

本書は2部構成である。**第1部は営業担当者向けの1枚**（これだけ読めば使える）、**第2部は管理者向け**（ナレッジブックの更新・配布・15分スモークチェック）である。ブックを開いたあとは、緑色の「操作ガイド」タブにも同じ内容の早見表がある。

# 第1部 営業担当者向け（1枚）

## 0. これは何をする道具か

会社のホームページや調べた文章を貼ると、AIが **①企業プロファイル → ②リスク仮説 → ③提案 → ④提案骨子** の4段階で下書きを作る。**下書きであり、確認と修正は人が行う**。

出るもの: **リスクレポート（HTML・ブラウザで開く）** と **ヒアリングシート（A4 1枚・訪問で使う）**。

操作の起点は常に2つ: **`HOME` の①～④のボタン**と、迷ったときの**「操作ガイド」タブ**である。

## 1. 起動

1. `リスク提案ナビ.xlsm` をダブルクリックで開く。
2. 上に黄色い帯で「セキュリティの警告」が出たら [**コンテンツの有効化**] を押す。
3. `はじめにお読みください` のシートが自動で隠れ、**HOME** が出れば準備完了である。初めて開いたときは画面の真ん中に案内カードが3枚出るので、[次へ]で読み進める（あとから「操作ガイド」タブの[ツアーをもう一度見る]で見返せる）。

**赤い帯が出ていたら**: 「デモ／開発経路で動作中です（本番の判断に使わないでください）」と出ている間は練習用の応答が返る。**その結果をお客様に見せてはならない**。管理者へ連絡する。

## 2. ① 案件を作る

`HOME` 上段の [**① 案件を作る**] を押すと `案件入力` シートが開き、案件IDの欄に **`(新規)`** と表示される（この時点ではまだ案件は作られていない。案件IDは[保存して戻る]を押したときに自動で入る）。上から順に埋める。

| 埋めるもの | 説明 |
|---|---|
| 種別 | **新規開拓** か **更新**。更新のときは現契約サマリが必須になる |
| 企業名・業種 | 業種コードと業種名は**業種マスタ由来の一覧から選ぶ**（ナレッジに接続できていないときは一覧が出ないので手入力する）。業種名は一覧の名前をそのまま使う（例: コード09は「食料品製造業」。「菓子製造」はその別名であり欄には入れない） |
| **調査の深さ** | **かんたん調査**（HP中心・手早く）/ **しっかり調査**（追加調査あり・重要案件）/ **壁打ち** |
| 案件コンテキスト | 取引・幹事・BID・再保-キャプティブ・S4出力を選ぶ |

## 3. 材料を貼る（9つの欄）

上から順に貼る。**空でよい欄もある**。**1つの欄は約32,000字(A4で約20枚)まで。超えたら「続き1」へ**（「続き1」でも足りなければ「続き2」へ）。

| # | 欄 | 必須 | 何を貼るか |
|---|---|---|---|
| 1 | HPテキスト | **必須** | 会社概要・事業内容・拠点のページ本文 |
| 2 | 有報リスク章 | 任意 | 有価証券報告書の「事業等のリスク」 |
| 3 | 営業メモ | 任意 | これまでの経緯 |
| 4 | 現契約サマリ | **更新時必須** | 現在の付保内容。[匿名化の切替] で伏字にできる |
| 5 | 前回更新メモ | 任意 | |
| 6 | 追加調査の結果 | 任意 | しっかり調査でAIに追加で調べさせた結果 |
| 7 | 現場メモ（何でも欄） | 任意 | **きれいに書かなくてよい。思い出した順でよい**（例「社長はワンマン・決裁は即断」「工場の裏の川が気になる」） |
| 8 | 付保の見立て | 任意 | 分かる範囲・伝聞可（例「たぶん火災は他社」「PLは付いていないと聞いた」） |
| 9 | ヒアリング回答 | 任意 | **訪問後**に使う。第2ラウンド用（§8） |

**収集レシピ**（何をどこから貼るかの目安。チェックは自己確認用で、入れなくても保存できる）

- かんたん調査（8項目）: 会社概要 / 事業・製品 / 拠点・設備 / 沿革 / 直近の動き / 採用・人員 / 有報・財務リスク / 営業情報
- しっかり調査（上記＋6観点）: SNS評判 / 競合・業界事故 / 市況・マクロ / 財務状態 / 付保・提案の経緯 / 拠点ハザード

貼り終えたら [**字数を数える**] で各欄と合計を確認し、[**保存して戻る**] を押す。

## 4. ② 一括実行

`HOME` で対象案件が選ばれていることを確かめ、上段の [**② 一括実行**] を押す。

- 進捗欄の4行が埋まる。左の見出しが「実行中のStep」「開始時刻」「最大待ち時間」「案内」で、右の値がそれぞれ「一括実行（Step1～Step4）」「時刻（`hh:mm:ss`）」「最大◯分（1Stepあたり ◯ 秒）」「画面が白くなっても処理は続いています」である。
- **画面が白くなっても触らない。閉じない。** 処理は続いている。
- 品質は `HOME` の**品質欄（ドロップダウン）**で選べる。**標準**（1回で作る）/ **入念**（作る → AIが自分で批判する → 直す。時間は延びるが精度が上がる）。しっかり調査は既定で入念になる。
- やり直したい段だけ動かすときは「くわしい操作」区画の [S1] [S2] [S3] [S4] を使う。

**途中で止まったら**: `HOME` の警告欄に理由が出る。「本日のAI利用枠の上限です」なら翌日に続きから押し直す。**すでに通った段の結果は消えない。**

## 5. 中身を直す

出来上がった `S1_企業プロファイル` `S2_リスク仮説` `S3_提案` `S4_骨子` のシートは**直接書き換えてよい**。

- 直したら、そのシートの次へ進むボタンを押す。ボタンの名前はシートごとに違い、`S1_企業プロファイル` は [**S2へ進む**]、`S2_リスク仮説` は [**S3へ進む**]、`S3_提案` は [**S4へ進む**]、`S4_骨子` は [**ヒアリングシート生成**] である（各シートには [**S1から再実行**] のように、その段をやり直すボタンも並んでいる）。押すと**その先の段だけ**作り直される（確認のダイアログが出る）。
- 決まった選択肢の欄は一覧から選ぶ。一覧に無い言葉を手で書くと保存が止まる。
- 直した内容は次の段に必ず反映される。

## 6. ③ レポートを出す

`HOME` の [**③ レポートを出す**] を押す。

- 警告欄に「リスクレポートを出力しました: <パス>」が出る。そのファイルをダブルクリックするとブラウザで開く。
- ファイル名には出力日が入る（`<会社名>_<8桁>_リスクレポート_<yyyymmdd>.html`）。同じ日にもう一度出しても**前のファイルは上書きされず** `_2` `_3` と別ファイルが増える。手で書き足した前回のレポートは消えない。
- **5×5のリスクマップ**と**カバレッジ表**が絵で出る。1つのファイルで完結しているのでメール添付でも崩れない。
- **S1が終わっていないと出せない**。「先にStep1を実行してください。」が出たら「くわしい操作」区画の [S1] を押してからやり直す。S2・S3が空でも出力はできる。
- レポートの末尾に「本資料はAI支援により作成した骨子を人が確認・編集したものです」が自動で入る。**消さない。**

## 7. ④ ヒアリングシート

`HOME` の [**④ ヒアリングシート**] を押す（`S4_骨子` シートの [ヒアリングシート生成] でも同じ）。

- `ヒアリングシート` シートに質問が並ぶ。**回答欄は空**である。
- Ctrl+P で **A4縦1枚**に印刷し、訪問先で手書きで埋める使い方を想定している。
- このシートに書いた回答は自動では取り込まれない。次の§8で自分で貼る。
- **回答を書き込んだ後にもう一度[④ ヒアリングシート]を押すと、確認のダイアログが出る**（作り直すと手書きの回答が消えるため）。[いいえ]を選べば何も起きない。消したくない回答は先に§8のとおり `案件入力` の貼付欄⑨へ貼っておく。残っている回答が**いま開いている案件とは別の案件**のものだった場合も確認が出る（「別案件（<id>）の手書き回答がN行残っています。作り直すとこの回答は消えます。」の文言。<id> は前の案件の案件ID、N は残っている行数が入る。別の案件に切り替えた後でも、前の案件の回答は黙って消えない）。

## 8. 訪問後の第2ラウンド

1. `案件入力` を開き、貼付欄⑨「**ヒアリング回答**」に聞いてきた内容を貼る。
2. [保存して戻る] を押す。
3. `HOME` の「くわしい操作」区画にある [**第2ラウンド開始**] を押す。「現在のS2を前ラウンドとして確定し、第2ラウンドを開始します。よろしいですか」と確認が出るので [はい] を選ぶ。ラウンド表示が「第2回」になり、いまのS2が前回ぶんとして保管される（次のS2はそれを踏まえて作られる）。
4. `HOME` の「くわしい操作」区画にある [**S2**] を押す（Step2から作り直す）。
5. 続けて [S3] [S4] を押すか、[② 一括実行] で通す。
6. §6・§7 でレポートとヒアリングシートを出し直す。

## 9. 座組を考えたいとき（壁打ち）

`HOME` の「くわしい操作」区画にある [**壁打ち**] を押すと対話シートが開く。

1. [壁打ちを開始/再開] を押す（案件の材料・S1～S3・型・機構がAIへ渡る）。押した時点でその案件の**調査の深さ**が自動で **壁打ち** に上がる。
2. 入力欄に書いて [送信]。何往復でもできる。
3. よい気づきが出たら、その発話を選んで [**受信箱へ**] を押す。商品部の受信箱へ「現場の声」として届く。
4. 結論は自分で `S2` / `S3` シートへ反映する（[S3を開く] ボタンがある）。
5. 履歴は案件に保存される。次に [壁打ちを開始/再開] を押せば続きから話せる。

## 10. その他のボタン（「くわしい操作」区画）

| ボタン | 何をするか |
|---|---|
| [案件入力を開く] | いま選んでいる案件の入力画面を開く |
| [商談の記録] | 商談の**事実**（展開・顧客の発言・結果）を選択式で残す。5分で終わる |
| [判断台帳] | UW判断（増率・謝絶・限定・維持・改善）とその決め手を1行で残す |
| [受信箱を開く] | ネタの投函と、AIによる下見（プリフライト診断）。投函は、表の**いちばん上の下書き行**（ID欄に「(下書き)」とある行）の本文欄に記入して [＋投函] を押す（成功すると下書き行は空に戻り、その下に新しい行が増える。下書き行は診断や集計の対象にならない）。診断のあとの判定は **`judge_to` 列**のドロップダウンで「採択／条件付き保留／却下」を**日本語のまま**選び、却下なら却下類型（T0～T10）、条件付き保留なら見直しのきっかけと期日を埋めて [判定を保存] を押す。**`status` 列は自動で更新される列なので手で書き換えない** |
| [企業ファイルへ保存] / [企業ファイルを開く] | 1社1ファイルの記録。次のラウンドで前回分を引き継げる |
| [ナレッジ再読込] | 商品部が知識を更新したときに押す |
| [プリフライト診断] | 受信箱にたまった投稿をまとめて診断する |

## 11. やってはいけないこと

- **赤帯が出た状態の出力をお客様に見せない。**
- **個人名を入力しない。** 顧客の発言に個人名が混ざると確認のダイアログが出る。伏字にして保存する。
- **AIの出力をそのまま提出しない。** 必ず読んで直す。
- **実行中にブックを閉じない。**

## 12. 困ったときの1行対処

| 症状 | 対処 |
|---|---|
| 画面が白い | 触らずに待つ。処理中である |
| 「対象案件が選ばれていません」 | `HOME` の対象案件を選び直す |
| 「先にStep1を実行してください。」 | [S1] を押してから出力する |
| 「本日のAI利用枠の上限です」 | 翌日に続きの段から押し直す |
| 「入念モードの審査を省略しました（生成版で続行）」／「入念モードの改訂を破棄しました（改訂前で続行）」 | 異常ではない。その段は成功しているが、AIの自己批判・自己修正を通していない内容である。提案に使う前にひと通り読み直す |
| 「画面の案件と保存先が一致しません。再描画してください」 | 別の案件の画面が残っている。`HOME` で対象案件を選び直してから、その段のシートを開き直す |
| 「ナレッジブック.xlsx を本体と同じフォルダに置いて[ナレッジ再読込]を押してください」 | `ナレッジブック.xlsx` を本体ブックと同じフォルダへ置いて [ナレッジ再読込] を押す（起動時は自動でも探す）。直らなければ管理者へ連絡する（提案の質が落ちるので直してから使う） |
| 「ナレッジブックが見つかりません。管理者にご連絡ください」 | 本体ブックと同じフォルダへ `ナレッジブック.xlsx` を置いて開き直す（起動時に自動で探す）。共有フォルダ運用のときは管理者が §14.4 を見て `kb_path` を直す |
| ボタンを押しても何も起きない | 他の処理が動いている。終わるまで待つ |
| 出力が明らかにおかしい | シートを直して当該段から作り直す。直らなければ管理者へ |

困ったときは、緑色の「操作ガイド」タブの「④ 困ったとき」にも同じ表がある。

# 第2部 管理者向け

## 13. ナレッジブックの更新

ナレッジブック（`ナレッジブック.xlsx`）は**マクロ無しのExcelファイル**で、共有フォルダ（社内の共有が使えない環境では利用者のPC内の1か所）に1つだけ置く。**本体ブックを配り直さずに知識だけ更新できる**のが要点である。

### 13.1 更新できるシート

| シート | 中身 |
|---|---|
| `業種マスタ` / `リスクライブラリ` / `メニュー一覧` / `種目マスタ` / `メニュー種目対応` / `成功事例` | 基礎の6シート |
| `判断基準` | 保険原理・生存文法・棄却類型のルール行 |
| `パターンマスタ` | 汎用座組パターン P1～P15 |
| `型ライブラリ` | 具体の型（実績・候補・他社実績） |
| `機構ライブラリ` | 掛け合わせ用の部品（Phase 1.5） |
| `適用先候補` | 裏受け・バンドル先企業 |
| `巡回リスト` / `ウォッチログ` | ウォッチ用（Phase 1.5） |
| `研究テーマ一覧` | プリフライト診断の重複照合用 |
| `新サービス候補` | **本体が自動で追記する**。管理者は読むだけでよい |

### 13.2 更新の手順

1. ナレッジブックを開く（**誰かが本体ブックを使っている最中でも読み取りは競合しない**。書き込みは1人ずつ行う）。
2. 行を足す・直す。**列の見出しは変えない**。
3. 決まった選択肢の列は19章の値だけを使う。特に `リスクライブラリ` の `category` は **リスクユニバース10分類**のいずれかでなければならない。旧6分類の行は 13章§3.1 の読替表で変換してから入れる。
4. 保存して閉じる。
5. 利用者は `HOME` の [**ナレッジ再読込**] を押すだけで新しい知識に切り替わる。押さなくても次回起動時に読み込まれる。

### 13.3 更新後の確認

| 見るところ | 期待 |
|---|---|
| `HOME` の ナレッジ欄 | 「読込OK（メニューN/型N/事例N）」の N が増えている |
| 案件を1本流す | S3の提案に新しいメニュー・型が現れる |
| `err_log` | E0401（ナレッジブック接続不可）・E0402（ナレッジブック検査不合格）が増えていない |

**注意**: 存在しないIDを本体が返すと E0301 で止まる仕組みなので、**IDの綴りを間違えると提案が落ちる**。ID列は必ず既存の書式（`M-0012` `L-03` `S-0004` `K-0003` `P9` `MC-0107` の形）に揃える。

### 13.4 新サービス候補の回収

「該当メニュー・型なし」と判定されたリスクは、本体が `新サービス候補` シートへ自動で追記する。共有フォルダにつながらなかった分はローカルに退避され、次回起動時に無音で再送される。**月次の編集会でこのシートを棚卸しする**のが運用である。

## 14. 配布

### 14.1 配布経路（会社PCはターミナル・インストーラを使えない前提）

配布はチャットから**メール添付**で行う。手順の詳細は24章§1を見る。要点だけ書く。

1. 開発担当がチャットで3つのExcelファイル（`リスク提案ナビ.xlsm`・`リスク提案ナビ_dev.xlsm`・`ナレッジブック.xlsx`）を渡す。
2. 利用者が私物PCのGmailから、会社アドレスへ**xlsmのまま添付**して送る。**zipにはしない**（社内メールがzip添付をはじくため、実機で確認済み）。
3. 会社PCで受け取り、デスクトップなど1か所に保存する。

| ファイル | 置き場所 |
|---|---|
| `リスク提案ナビ.xlsm`（本番版） | 利用者のPC（メールで受け取った場所） |
| `ナレッジブック.xlsx` | 共有フォルダに**1つだけ**（無ければ利用者PC内の1か所に固定） |
| 本書（25章 第1部） | 印刷またはPDFで配る |

**`リスク提案ナビ_dev.xlsm`（開発版・練習用）は普段の営業には配らない。** 練習用の応答を返すため、実案件に使われると事故になる（24章§5のニセリボンちゃん検証のときだけ使う）。

### 14.2 配布前に必ず通す検問（17章§5-1）

**1つでも飛ばした版は配らない。** これは姉妹プロジェクトが34ラウンドの手戻りを出して確立した決まりである。

### 14.3 版の入れ替え

Phase 1は「案件使い切り」運用である。**利用者は旧版を自分で新版に置き換える**（案件データの移行機能は持たない）。したがって、

- 新版を配るのは**案件の切れ目**を狙う。
- 旧版で走っている案件は、旧版のまま完了させてよい。
- ナレッジブックの更新は本体の再配布を伴わない（§13）。

## 16. 運用の定例

| 頻度 | やること |
|---|---|
| 随時 | ナレッジブックの更新（§13）。本体の再配布は不要 |

| 月次 | `run_log` の集計（`repaired` / `failed` の率、所要時間、警告率）。`failed` が増え続けるならプロンプトの見直しを検討する |
| 四半期 | `recommended_model` の追随。型生成バッチと勝ち筋仮説のレビュー |
