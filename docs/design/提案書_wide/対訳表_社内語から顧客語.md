### 4.1 削り損ねたときに機械が当てる代替語（`modValidate5.TabooPairList`〔委譲元 `modValidate4.TabooPairs`〕の3行）

## 6. 置換してよい文脈（閉じた規則。白名簿を増やさない）

**W15 最後の実装波（裁定書43 §1）で設計を変えた**。前の設計は「置換を見送る語尾」を印ごとの白名簿（`V4_SURU_TAILS` / `V4_VERB_TAILS`）で列挙していたため、3ラウンドにわたって「3件直すと同じ型が3件残る」を繰り返した（「整理ている」を直すと「整理ながら」「整理やすい」「整理直す」が残り、「会社役員賠償責任保険保険」を直すと「額額」「力力」「策策」が残った）。形態素解析が無い以上、日本語の活用・複合・表記ゆれは**列挙では閉じない**。

そこで**置換してよい文脈のほうを閉じた集合で定義し、それ以外では置換しない**ことにした。

- 社内語 W を顧客語 C に置換してよいのは、**W の直後の1文字が下の終端集合に入るとき、または W が文字列の末尾のとき**だけ。
- それ以外（直後が漢字・ひらがな・カタカナ・英数）は**置換しない**。壊れた日本語を顧客提示物に出すことは、社内語が1語残ることより重いからである。置換しなかった語は §6.6 のとおり警告に載せる。
- 終端集合は**これだけ**。増やさない。増やしたくなったら、それは終端集合の欠けではなく **`mode` を `warn` にすべき対**である。

### 終端集合（値源。実装 `modValidate4.TermChars()` と1文字ずつ突き合わせる＝§7-1）

```
助詞 をにはがのへとでもやかねよら
記号 、。，．・…「」『』()（）【】[]〈〉《》:：;；/／|｜-－~～!！?？"'
コード U+2014 U+2015 U+0020 U+3000 U+0009 U+000A U+000D
```

- 「コード」行は、CP932 のソースへ直接書けない字（em ダッシュ U+2014。`tools/vba_lint.py` の CP932 検査が弾く）と、見ただけでは判別できない字（半角空白・全角空白・タブ・LF・CR）をコードポイントで宣言する行である。`―`（U+2015）は CP932 側のダッシュで、Windows では `—` のつもりでこちらが入ることがあるため両方を終端にする。
- 実装は `modValidate4` の `V4_TERM_JOSHI` / `V4_TERM_MARK1` / `V4_TERM_MARK2` / `V4_TERM_SPACE` と `TermChars()` の `ChrW`。宣言と実装のどちらか一方を1文字でも削ると `check_glossary_impl` が赤くなる（実装の語尾リストを半分に削っても全ゲートが緑だった前波の死角は、ここを突き合わせていなかったことが原因である）。
- この1本で構造的に消える型（**白名簿を1語も足していない**）:
  - 「仕分けている／仕分けながら／仕分けやすい／仕分け直す」… 直後が `て` `な` `や` `直` → 置換しない（活用語尾を列挙する必要が無い）。
  - 「PML額」「D&O保険」「BCP計画」「与信力」「打ち手策」… 直後が漢字 → 置換しない（「額額」「保険保険」「策策」が出ない。顧客語の末尾の重なりを吸収する特別規則は要らなくなったので撤去した）。
  - 「ニューリスクリスク」… 直後がカタカナ → 置換しない。
  - 「付保の方針」「付保を進める」「付保。」「…付保」（末尾）… 置換する。

## 6.1 `mode`（2区分。印を増やさない）

旧 `general` / `suru` / `verb` の3印は**2区分へ集約した**。対を書く表（§1〜§3・§4.1・§6.4）の第3列 `mode` が値源で、**全対に必ず値がある**（空欄を許さない）。

| mode | 意味 | 置換 | 例 |
|---|---|---|---|
| `replace` | 名詞→名詞句で、終端集合の文脈なら置換して日本語が自然になる対 | §6 の文脈でだけ置換する | 付保 → 保険のご加入／座組 → ご提案の構成 |
| `warn` | 置換すると不自然になりうる対 | **一切置換しない**（V-S5-12 の警告だけ） | ヒアリング → お伺いしたい事項／移転・保有などの一般語 |

- `mode` の付け方（**列挙ではなく4つの質問**。上から順に当てはめ、最初に当たったところで決まる）:
  1. 一般語（保険の社内語であると同時に日常語）か → `warn`
  2. 顧客語が**述語**（用言で終わる節）か、または社内語が**用言の連用形**（活用語尾が続きうる語。仕分け／引受け）か → `warn`
  3. 社内語が**動作性名詞**（「W を行う」と書ける）で、顧客語が**静的名詞句**（物・事項・状態を指し、動作を指さない）か → `warn`
  4. どれでもない → `replace`
  5.（裁定書46 班F・F-6で追加）業界の定型句・法的な精度を要する語で、置換すると意味の精度が落ちる懸念があるか → `warn`
- 3 の見分け方は置き換えて読むだけでよい。「付保を行う」→「保険のご加入を行う」は成立する（`ご加入` は動作）ので `replace`。「ヒアリングを行う」→「お伺いしたい事項を行う」は成立しない（`事項` は物）ので `warn`。「与信を行う」→「取引先の支払い能力を行う」も成立しないので `warn`。
- 「〜する」に続く位置（旧 `suru`）と、活用語尾に続く位置（旧 `verb`）の**大半**は、**§6 の終端集合が構造的に弾く**ので印が要らない（`し` `す` `さ` `せ` `て` `た` `な` `ま` はどれも終端集合に入っていない）。
- ただし **`に` `よ` `ら` は助詞であると同時に活用語尾の頭**でもある（「仕分けにくい」「仕分けよう」「仕分けられる」）。終端集合からこの3字を削ると「付保により」「付保に関する」のような正当な置換まで止まるので、**終端集合は削らず、用言の連用形である語のほうを `warn` にする**（質問2）。実測: `仕分け` を `replace` のままにすると実物の `SoftenTaboo` が「仕分けられる項目」→「整理られる項目」を出した。

## 6.3 廃止: 用言の連用形の白名簿（旧 `verb`）

W15 最終是正（裁定書42 §1）で `V4_VERB_TAILS`（`る` `た` `て` `ない` `なく` `なかっ` …16個）を置いた節。**裁定書43 §1 で撤去した**。

- 撤去の理由: この白名簿は「仕分けている」を直したが「仕分けながら」「仕分けやすい」「仕分け直す」を取りこぼした。活用語尾は開いた集合であり、列挙では閉じない。
- 代わりに §6 の終端集合が「直後が終端でなければ置換しない」と定めるので、**活用語尾を1つも列挙せずに**同じ型が大半消える。
- ただし `仕分け` `引受け` の `mode` は **`warn`**（§6.1 の質問2）である。終端集合の `に` `よ` `ら` は助詞であると同時に活用語尾の頭でもあり（「仕分けられる」）、この2語だけは終端集合では弾けないからである。§6.1 の `warn` の対の表が値源で、本節は白名簿の撤去だけを述べる（撤去の直後は `replace` のままと書いていたが、実測で「整理られる項目」が出たため §6.1 で `warn` へ移した。裁定書43 §2 の司令塔手直し）。

## 6.4 表記ゆれ（送り仮名）

W15 最終是正（裁定書42 §1）。社内語の**送り仮名ありの書き方**が未登録だと、最長一致が短いほうで止まり、余った送り仮名が顧客語のうしろに残る（「保険のお引き受け**け**の方針」）。次の2語を `modValidate4.TabooPairs()` へ足してある。

| 表記ゆれ | 代表形（表の番号） | 顧客語 | mode |
|---|---|---|---|
| 引受け | 引受（16） | 保険のお引き受け | warn |
| 座組み | 座組（23） | ご提案の構成 | replace |

- **番号付きの表には足さない**（§4.1 と同じ理由）。AI へ渡す15章§5.6 の対訳行は代表形の46語のままにし、表記ゆれは機械置換だけが知っている。
- 「引き受ける」（`き` を送る一般的な書き方）は**登録しない**。「保険で引き受ける」は社内語ではなくふつうの日本語であり、登録すると通常の文に警告が出る。
- 「引受けている」は §6 の終端集合が弾く（直後が `て`）。表記ゆれの登録は「引受けの方針」のような**終端の文脈**で最長一致を正しく止めるために要る。

## 6.5 取り消し規則（二重の安全網）

裁定書43 §1-3。§6 の終端集合でほぼ起きないが、**置換した結果が壊れて見えるなら、その置換を取り消す**（元に戻し、§6.6 の警告へ回す）。

- (a) 置換の継ぎ目で**同じ文字が3つ以上連続**したら取り消す（`V4_RUN_MAX = 3`）。
- (b) **顧客語の末尾1〜3文字が、直後の本文と重複**したら取り消す（`V4_UNDO_TAIL_MAX = 3`）。
- 実装は `modValidate4.UndoNeeded`（判定は1箇所だけ）。取り消した位置は「置換しなかった出現」として扱う。
- 旧 §6.5（`未充足 → 保険の手当てが無い` は顧客語が述語で壊れる）は、**`mode` を `warn` にして解消した**（§6.1 の質問2）。旧 §6.6（顧客語の末尾と本文の重なりを吸収する `TailOverlap`）は、終端集合が「直後が漢字なら置換しない」と定めたことで**不要になったので撤去した**（「D&O保険」はそもそも置換されない）。
