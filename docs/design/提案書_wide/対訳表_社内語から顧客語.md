## 6. 一般語（警告は出すが、機械置換はしない）

W15 Round 2（裁定書39 R2-02）。次の3語は §1 の表に残す（顧客向け提案書の本文に**書かない**ことは変わらず、残っていれば `modValidate4.CheckS5` の V-S5-12 が警告する）が、**`modValidate4.SoftenTaboo` の機械置換の対象からは外す**。

| 社内語 | 表の番号 | 外す理由（機械が潰すと壊れる実例） |
|---|---|---|
| 移転 | 5 | 「本社を移転する計画があります」→「本社を保険で備えるする計画があります」 |
| 保有 | 6 | 「現金を保有しています」→「現金を自社で負担するしています」 |
| 抜け | 18 | 「抜け漏れがないか確認します」→「補償されない部分漏れがないか確認します」 |

- いずれも保険の社内語であると同時に**日常語**であり、文脈を見ない1対1の置換では日本語が壊れる。**人が書き直す**のが正しく、機械は警告までにとどめる。
- 印の持ち方: `modValidate4.TabooPairs()` が返す行の**第3列に `general`** を置く（行は `社内語<TAB>顧客語<TAB>general`）。**本ファイルの §1〜§3 の番号付き表は3列のまま**にする——`tools/render_proposal.py` の `check_glossary` が `| n | 社内語 | 顧客語 |` の形で本表を読み、15章§5.6 の system 本文の `社内語 -> 顧客語` と突き合わせているため、列を増やすとその突合が静かに効かなくなる。
- S5 のプロンプト（15章§5.6 system）の対訳行は**46語すべてそのまま**。AI には「書かないでほしい」と伝え続け、機械置換の可否だけを当方が分けている。
- S5 の経路では**続行しない**（W15 Round 2 検収・裁定書40 S-M4）。`modPipeline5.SoftenOrFail` は機械置換のあと `CheckS5` に掛け直し、**1件でも発火が残れば失敗**として扱う（16章 E-71③「機械置換してから再検証し、**通れば**成功として続行する」の逐語）。一般語やサ変語幹が S5 の本文に残ったときは、修復1回を掛けてもなお残ったということであり、利用者には16章 E-71 の①②（案件は壊さず、提案骨子で商談へ）を案内する。前波はここが「残りが一般語だけなら不合格でも通す」に緩んでおり、**検証に不合格の S5 が顧客向け提案書の材料になっていた**。

## 6.1 サ変語幹（「〜する」の直前だけ機械置換しない）

W15 Round 2 の検収（裁定書40 S-M2）。次の10語は「〜する」に続けて使う社内語であり、顧客語が名詞句なので、その位置で置換すると日本語が壊れる。§1 の表には残し（警告は出す）、**直後が `し` / `す` / `さ` / `せ` のときだけ**置換を見送る。名詞として使われている位置（「保険化の検討」「付保の状況」）は**従来どおり置換する**ので、顧客資料に社内語をそのまま残すことにはならない。

| 社内語 | 表の番号 | 外す理由（「〜する」に続けたときの壊れ方） |
|---|---|---|
| 付保 | 1 | 「付保する」→「保険のご加入する」 |
| 保険化 | 10 | 「保険化する」→「保険での備え方の設計する」 |
| 特約開発 | 11 | 「特約開発する」→「補償内容の新しい設計する」 |
| 組成 | 12 | 「組成する」→「仕組みづくりする」 |
| 引受 | 16 | 「引受する」→「保険のお引き受けする」 |
| ヒアリング | 24 | 「ヒアリングする」→「お伺いしたい事項する」 |
| 攻めの保険活用 | 26 | 「攻めの保険活用する」→「成長を後押しする保険の活用する」 |
| 顕在化 | 29 | 「顕在化する」→「実際に起きることする」 |
| 与信 | 33 | 「与信する」→「取引先の支払い能力する」 |
| クロスセル | §4（番号なし） | 「クロスセルする」→「追加でご検討いただける備えする」 |

- 選び方の規準: **「社内語＋する」が日本語として成立し、かつ「顧客語＋する」が成立しない**行だけを印付けた。顧客語がサ変名詞である対（「仕分け → 整理」＝「仕分けする」→「整理する」）は印を付けない（過剰に外すと社内語が顧客資料に残る）。「トリガー」「座組」「打ち手」などは「〜する」の形で使わないため対象外。
- 印の持ち方は §6 と同じで、`modValidate4.TabooPairs()` の**第3列に `suru`**（行は `社内語<TAB>顧客語<TAB>suru`）。判定は `modValidate4.SuruFollows`。
- `modValidate4.TabooHitStrict`（＝機械置換が責任を持つ語）は、`general` と `suru` の**どちらの印がある行も外す**。提案書の出力経路はこれを使って「警告で済む残り」と「置換の取りこぼし（実装の欠陥）」を分けて usage_log に残す。
