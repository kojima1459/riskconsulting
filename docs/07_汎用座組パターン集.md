# 07. 汎用座組パターン集（座組の文法書・シードv0）

**位置づけ**: 型ライブラリの上位語彙。個別の型（ヤモリ型、STUDIO裏受け型…）は、この汎用パターンの具体例として登録する。「ジャパン21の座組しか知らない」を「文法は15個しかない。当てはめは機械がやる」に変えるための文書。
**注意**: 代表例はAIの一般知識に基づく参考情報（要裏取り）。社内実績の紐づけは棚卸しで確定させる。

## 使い方（製品内での役割）

1. **ウォッチプレイの仕分け軸**: ニュース1本を「どのパターンの新しい実例か？」で分類する（STUDIOの例 → P4）。パターンが付いた瞬間に、社内実績・成立条件・過去の類似検討が芋づるで参照できる
2. **型生成プレイの探索軸**: 「未解決リスク × 15パターン」の総当たりで座組候補を生成させる（第3弾の掛け合わせの探索空間を、機構795件からこの15枠に構造化して効率化）
3. **座組開発プレイ（対話型）の共通言語**: 商品部と営業が「これはP2で行くかP4で行くか」と話せる語彙になる
4. **判断基準との接続**: ドロップの壁を越える3手（加入経路/給付形態/引受主体）は、P1・P8・P9・P10（経路）、P6・P7（給付）、P13（主体）に対応する——落ちた投稿の再設計は「どのパターンに乗せ替えるか」の問題に還元される

## ウォッチプレイ実演記録（2026-08-24）

- 入力: STUDIO「災害支援プログラム」リリース（令和8年熊本地震・有料プラン無償提供・「全員への提供は約束しない」と明記）
- 仕分け: 適用先候補（P4 サービス裏受け型）
- 提案仮説: STUDIOを契約者とする災害時サブスク継続の費用保険（トリガー=災害救助法適用、給付=プラン料金免除相当＋復旧支援実費）。売り文句は「約束できない支援を、約束できる支援に変える」
- 横展開: 「SaaS事業者の災害支援プログラム」はジャンルとして存在 → 1社提案でなく新しい型（災害時サブスク継続型）として登録し、同種プログラムを持つSaaSを適用先候補として収集する
