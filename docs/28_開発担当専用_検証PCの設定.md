## 0. 先に読むこと: この設定は当面使わない

**2026-09-02、同じ社内環境で「隠しシートの文字列をVBAプロジェクトへ注入するループ」が社内AVのAMSIに
検知され、VDIが強制停止して情シスチケットになった。** 本製品の自己インストーラ（焼き付け）は同じ方式であり、
**開発PCで焼き付けを1回行うだけでも同じループが走る**。したがって:

- **当面、焼き付け（`docs/24` §8.1b）は実施しない。**
- 実施する必要が生じたときは、**必ず事前に情シス（端末サポート）へ一報する。**
- 配布方式は「ビルドが完成品の `vbaProject.bin` を作る」方式へ切り替え中である（裁定書27 W9-A）。
  切り替えが済めば、この文書の設定も焼き付けそのものも要らなくなる。

以下は、切り替えが済むまでの記録である。

## 1. VBAプロジェクト オブジェクト モデルへのアクセスを信頼する（検証PCで1回だけ）

**何のための設定か**: 焼き付け前のブックは、部品（VBAモジュール）を `vba_src` シートの中に文字として
持っているだけで、ブック本体にはまだ入っていない。初回に開いた1回でその部品を書き込む。
その書き込みにこの設定が要る。**焼き付け済みのファイルを開く利用者には要らない。**

**この設定を入れてよいPC**: 開発担当が使う検証PCだけ。共有PC・利用者のPCには入れない。

1. Excelを開く（空のブックでよい）。
2. [ファイル] → [オプション] → [トラストセンター] → [トラストセンターの設定] → [マクロの設定] と進む。
3. **「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」** にチェックを入れて [OK] を押す。
4. Excelをいったん全部閉じてから、`リスク提案ナビ.xlsm` を開き直す。

> **注意**: この設定を入れたPCでは、どのブックのマクロもVBAプロジェクトを書き換えられるようになる。
> **中身を知らないファイルを開かないこと。** 検証が終わったらチェックを外して戻すのが望ましい。

**入っていないとどうなるか**: 英語で `Trust the VBA project, then reopen.` が出る。利用者側にこれが出たら、
それは**焼き付け前のファイルを配ってしまった**という開発側の事故であり、利用者に設定させて解決しない
（`docs/24` §6.11 は「開発担当へ連絡する」だけを案内する）。

---

## 2. 「信頼できる場所」の自己登録について

`docs/24` §6.7 にあった「利用者が自分でフォルダを信頼できる場所に登録する」予備手順も撤去した
（裁定書27 W9-C1）。**`D` ドライブ以外に置く必要があるときは、設定を変えずに情シス（端末サポート）へ
相談する** のが正しい道である。

なお、`D:` が免除しているのは「マクロの設定」だけであり、**VBAプロジェクトへのアクセス（VBOM）は
免除されない**（裁定書27 事実）。「`D:` に置けば §1 の設定が要らなくなる」わけではない。

## 3. 検証PCで測ること

**（v6.1・裁定書31 裁定1 で更新）** 以前ここにあった「`%USERPROFILE%\Documents` が一晩で残るか」の
測定は**不要になった**。保存先の解決から環境変数の参照を全部撤去し（会社PCでは `%OneDrive%` が
**別の利用者のフォルダ**を指し、`%OneDriveCommercial%` は未定義だった＝2026-09-05 実測）、
`Documents` は候補ですらなくなったためである。いま測るのは
**起動bat が書く `D:\リスク提案ナビ\data_dir.txt` に、OneDrive のデータフォルダが1行書かれているか**
の1点で、手順は `docs/24` §7 の観察メモ「`data_dir.txt` に保存先が書かれているか」にある。
