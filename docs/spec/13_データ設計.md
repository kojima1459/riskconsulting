### 2.8 企業ドシエファイル `【会社名】_リスクドシエ.xlsx`（v2.3.1・FR-45。1社1ファイル）

**思想**: ツール本体（xlsm）はエンジン、企業ファイルは蓄積。担当15社なら15ファイルを営業が持ち、面談・提案のたびに追記して育てる（常務FB「NotebookLMの企業版・推論ありリスクマネジメント」）。マクロ無し.xlsxなので配布・共有・保管が軽い。I/OはPoC modPack/modPackExportの骨格（新規xlsx書き出し・2段検証・重複排除・PII走査）を転用した modCompanyFile が担う。

| シート | 内容 |
|---|---|
| `dossier_meta` | company_id / 会社名 / 業種 / スキーマ版 / 作成・最終更新 / PII走査結果 / 担当者 |
| `dossier_profile` | 最新の S1 JSON（s1_edited優先）と strategy_outlook。開くと「前回までの理解」が即座に戻る |
| `dossier_rounds` | 1行=1ラウンド: round_no / case_id / 実施日 / dossier_tier / s1〜s3 JSON（32,000字分割は case_data と同方式） / HTMLレポートのファイル名 / 出力時の要約 |
| `dossier_facts` | フィードバック（事実記録）の累積（2.5と同列構成＋round_no） |
| `dossier_notes` | 現場メモ・ヒアリング回答の原文累積（field_insights タグつき） |

**運用**: 案件開始時にツールから企業ファイルを「開く」→ 前回ラウンドの s1/s2 と notes が案件に読み込まれ、S2の status 更新（confirmed/rejected/new）の材料になる。案件完了時に「保存」で追記書き出し。ツール外への共有前に modPii の走査結果を dossier_meta に記録（警告であり停止ではない）。本体ブックの case_data は作業中の一時領域という位置づけになる（完了時に企業ファイルへ確定）。

## 4. データ保全・ライフサイクル

- `sN_json`（LLM生出力）と `pf_json` は不変（監査・プロンプト改善の一次データ）
- 案件削除はHOMEからのみ（案件一覧＋case_data＋フィードバックの同時削除・確認必須）。受信箱・判断台帳・run_logは削除しない（累積が資産）
- ナレッジブック編集は管理者1名運用。本体からの追記失敗時はローカル退避→次回起動時再送（16章 E-13）
- 個人名の保存禁止（owner/recorded_by はWindowsユーザー名までとし、顧客側個人名は全シートで入力禁止の注記＋E-05チェック）
