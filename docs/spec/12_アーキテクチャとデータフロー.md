### 2.1 起動シーケンス（modBoot。`Workbook_Open` から呼ぶ唯一の入口。17章 T-16）

「起動時に必ずやること」を複数の章に散らさず、**順序と失敗時挙動を1箇所で固定する**。modBoot 以外に起動処理を書かない。

| 順 | 手順 | 失敗したら |
|---|---|---|
| ① | ガードシート（`はじめにお読みください`。**可視・先頭・保護なし**の状態で配布ビルドに焼き込む）を非表示にする | 起動継続。本手順が走った＝マクロは有効。逆にマクロを無効化して開かれると `Workbook_Open` 自体が発火せず本手順も走らないため、利用者にはこのガードシートだけが見え（他シートは非表示のまま）、マクロ有効化の案内が伝わる |
| ② | config読込（13章§2.3の既定値表を登録してからconfigシートの値で上書き） | 既定値のみで続行し、**E0608**（config読込失敗・既定値で続行・警告。16章§1）をerr_logに記録して起動は続ける（configシートの欠損で製品を止めない） |

- **1手順の失敗で起動全体を止めない**（v2.5・裁定書9 B21）: 各手順は**個別のエラーハンドラ**で包み、実行時エラーが起きても err_log へ記録して次の手順へ進む。7手順（＋⑤b）のどれか1つの想定外エラーで、以降の保護方針の適用・ボタン配線・`ParkFocus` が未実行のまま利用者にVBAのエラーダイアログが出る状態を作らない
- シート保護は使わない。編集モード対策は `ws.EnableSelection = xlUnlockedCells` ＋ Locked 設定で行う（16章 E-51）
- 各手順は失敗注入テストで規定挙動を検査する（T-16のDoD）

## 4. 依存規則

- 依存方向: ui → app → core の一方向。core は app/ui を参照しない
- **core層のコードに製品固有の語彙を書かない**: 製品名・シート名・ドメインenum・ドメイン型（TCaseCtx等）はcoreに置かず、app層から注入する。具体的には (a) TCaseCtx は app層の `modAppTypes` が持つ（core `modTypes` は汎用型のみ） (b) toolN の製品名は config `app_tool_prefix` から読む (c) 製品固有のconfig既定値は modBoot が起動時に登録する。受入条件は「core層の全ファイルを grep して製品名・シート名の出現がゼロ」（17章 T-10）
- ナレッジブックへの接続は modKnowledge のみ。書込は「新サービス候補」追記のみ（＋関心度集計は本体側シートで保持し書込まない）
- PowerPoint COM は modExportPpt のみ。COM失敗が案件状態を壊さない
- **外部へ出る前に必ずPII走査**: `modSparring`（壁打ちの送信）・`modJudgeStore`（判断台帳の保存）を含め、保存・外部送信・レポート出力の直前に `modPii` を通す（16章 E-05／E-31）
- modSchemas/modPrompts* および **modHtmlTemplate1..n / modHtmlTheme** は純文字列（設定参照のみ可）。Excelトークン・Run呼出し禁止（R4）。HTMLテンプレをmodExportHtml内に直書きしない（30,000字契約に抵触するため）
- **R4のExcelトークン許可モジュール（明示列挙。ここに無いモジュールは ui 層・test 層を除きExcelトークン禁止）**: ui層・test層に加え、`modGatewayRPN`（**R3の `Application.Run` のみ**）/ `modConfig` / `modLog` / `modCaseStore` / `modCaseRead`（**案件一覧の読取のみ**。裁定書7 B-7。書込は一切持たない＝状態遷移・採番・case_data は `modCaseStore` が唯一の口）/ `modInboxStore` / `modJudgeStore` / `modKnowledge` / `modCompanyFile` / `modCompanyFile2`（`modCompanyFile` の分割先。許可の幅は同じ「企業ドシエファイルのシートI/O」）/ `modCaseStore2`（`modCaseStore` の分割先。裁定書8 A-2。許可の幅は同じ「本体ブックの案件2枚のシートI/O」）/ `modExportHearing` / `modUtilText`（**`SetCellSafe` 内のセル書込に限る**。16章NFR-S7①が「セルへの書込口はこの1関数」と定めており、その関数本体だけはセルに触れざるを得ない。純変換部は `SanitizeForCell` として分離し、そちらはExcel非依存＝層(a)でテストする）の**13本**は、自身の責務範囲でのみExcelトークンを使ってよい。`modExportHtml` / `modExportPpt` / `modHtmlTemplate1..n` / `modHtmlTheme` / `modPipeline2` は**不可**（案件データはstore経由で受け取る）
