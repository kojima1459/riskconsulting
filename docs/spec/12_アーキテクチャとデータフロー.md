### 2.1 起動シーケンス（modBoot。`Workbook_Open` から呼ぶ唯一の入口。17章 T-16）

「起動時に必ずやること」を複数の章に散らさず、**順序と失敗時挙動を1箇所で固定する**。modBoot 以外に起動処理を書かない。

| 順 | 手順 | 失敗したら |
|---|---|---|
| ① | ガードシート（`はじめにお読みください`。**可視・先頭・保護なし**の状態で配布ビルドに焼き込む）を非表示にする | 起動継続。本手順が走った＝マクロは有効。逆にマクロを無効化して開かれると `Workbook_Open` 自体が発火せず本手順も走らないため、利用者にはこのガードシートだけが見え（他シートは非表示のまま）、マクロ有効化の案内が伝わる |
| ② | config読込（13章§2.3の既定値表を登録してからconfigシートの値で上書き） | 既定値のみで続行し、**E0608**（config読込失敗・既定値で続行・警告。16章§1）をerr_logに記録して起動は続ける（configシートの欠損で製品を止めない） |
| ③ | `modCaseStore.RepairStates()`（案件状態の整合修復） | 修復件数0として続行。E0603記録（16章E-12） |
| ④ | enum入力規則の隠しレンジ複製（11章§5） | **ナレッジブック未接続でも止めない**。19章レジストリの内蔵定数から復元して続行 |
| ⑤ | `modKnowledge.LoadKnowledge()`＋スナップショット保存 | 失敗はE0401警告のみで続行し、前回スナップショット（本体内隠しシート）を使う（16章E-08） |
| ⑤b | **業種マスタの入力規則（ドロップダウン）の複製**（v2.5・裁定書9 §4）。ナレッジスナップショットの業種マスタ30行から隠しレンジへ `industry_code` / `industry_name` を複製し、案件入力の `ci_industry_code` / `ci_industry_name` の2セルへその範囲を参照する入力規則を張る（`RestoreDataKeyHiddenRange` と同作法。13章§2.11・16章 E-24） | **入力規則を張らずに続行**（手入力のまま使える）。ナレッジ未接続かつスナップショット無しの場合が該当し、E-08 準拠で警告のみ。入力規則が張れないことを理由に起動を止めない |
| ⑥ | 新サービス候補のローカル退避分をナレッジブックへ再送 | 無音で次回起動へ持越し（利用者に見せない。13章§4） |
| ⑦ | `modGatewayRPN.RunLimitCheck()` | **Trueでも起動は止めない**。HOMEに案内を出し、実行時に再案内する（14章§2） |

- 順序は固定。②より前にconfigを読む処理を置かない、③より前に案件シートへ書く処理を置かない。⑤bは⑤（ナレッジ読込・スナップショット保存）の**後**に置く（値源がスナップショットのため）。丸数字は他章から参照されているので振り直さず、追加は枝番（⑤b）で行う
- **1手順の失敗で起動全体を止めない**（v2.5・裁定書9 B21）: 各手順は**個別のエラーハンドラ**で包み、実行時エラーが起きても err_log へ記録して次の手順へ進む。7手順（＋⑤b）のどれか1つの想定外エラーで、以降の保護方針の適用・ボタン配線・`ParkFocus` が未実行のまま利用者にVBAのエラーダイアログが出る状態を作らない
- シート保護は使わない。編集モード対策は `ws.EnableSelection = xlUnlockedCells` ＋ Locked 設定で行う（16章 E-51）
- 各手順は失敗注入テストで規定挙動を検査する（T-16のDoD）

### モジュールの ship / dev の別（W11-a・裁定書30 裁定1）

`build/modules.json` は「そのモジュールを**どの配布物に載せるか**」を2つの印で表す。**唯一の値源は台帳であり、コード側で決めない**。

| 印 | 意味 | 現在の対象 |
|---|---|---|
| `ship: false` | dev ビルドには載せるが、**prod の配布物（`vbaProject.bin` と PROJECT）から外す** | `modGatewayDirect`（direct経路の実体）／`modTestsPureDev`（dev専用の純層テスト17本） |
| `dev_src` | 同じモジュール名で、**dev ビルドのときだけ別のソースを使う**（`path`=prod／`dev_src`=dev） | `modGatewayLink`（`src/core/modGatewayLink.bas` / `src/core/dev/modGatewayLink.bas`）／`modTestsPureHook`（`src/test/modTestsPureHook.bas` / `src/test/dev/modTestsPureHook.bas`） |

- VBAは**プロジェクト全体**をコンパイルするので、`ship:false` のモジュールを配布物側の1行でも名前で参照していると実機でコンパイルエラーになる。参照の有無は `build_rpn._check_dropped_module_references` が毎ビルド機械で見る。
- `dev_src` の2ソースは **両方とも `.bas` として存在**し、`lo-compile` が1本ずつ隔離してコンパイルする（prod 版だけが未検証、という状態を作らない）。
- 実行時に名前でモジュールを選ぶ形（`Application.Run` や文字列ディスパッチ）は**禁止**である。その形自体が社内AVの見る形であり、静的な参照検査も効かなくなる。
- 純層テストの本数は配布集合と dev 専用で別々に数える。`wintest/tests_expected.txt` の `prod=` / `dev_only=` の2行が値源で、ゲートは `lo-pure`（配布集合）と `lo-pure-dev`（dev専用）の2本。

## 4. 依存規則

- 依存方向: ui → app → core の一方向。core は app/ui を参照しない
- **core層のコードに製品固有の語彙を書かない**: 製品名・シート名・ドメインenum・ドメイン型（TCaseCtx等）はcoreに置かず、app層から注入する。具体的には (a) TCaseCtx は app層の `modAppTypes` が持つ（core `modTypes` は汎用型のみ） (b) toolN の製品名は config `app_tool_prefix` から読む (c) 製品固有のconfig既定値は modBoot が起動時に登録する。受入条件は「core層の全ファイルを grep して製品名・シート名の出現がゼロ」（17章 T-10）
- **パスの連結は `modUtilPath.JoinPath` のみ**（裁定書29 W10.1）。区切り文字（`\` / `/`）の決め打ち連結（`& "\" &` の形）と `Environ$("TEMP")` の決め打ちは `tools/vba_lint.py` が ERROR で止める（除外は連結規則の実装本体である `modUtil` / `modUtilPath`、JSONエスケープの `modJsonLite`、および `src/test` 配下のみ）。一時フォルダは `modUtilPath.TempDir()`（TEMP → TMP → TMPDIR → 本体と同じフォルダ）に寄せる。理由: Windowsでは同じ文字列になるため決め打ちがどのゲートでも赤くならず、Mac の実Excel（区切りが `/`・TEMP を持たない）でだけ壊れる
- ナレッジブックへの接続は modKnowledge のみ。書込は「新サービス候補」追記のみ（＋関心度集計は本体側シートで保持し書込まない）
- PowerPoint COM は modExportPpt のみ。COM失敗が案件状態を壊さない
- **外部へ出る前に必ずPII走査**: `modSparring`（壁打ちの送信）・`modJudgeStore`（判断台帳の保存）を含め、保存・外部送信・レポート出力の直前に `modPii` を通す（16章 E-05／E-31）
- modSchemas/modPrompts* および **modHtmlTemplate1..n / modHtmlTheme** は純文字列（設定参照のみ可）。Excelトークン・Run呼出し禁止（R4）。HTMLテンプレをmodExportHtml内に直書きしない（30,000字契約に抵触するため）
- **R4のExcelトークン許可モジュール（明示列挙。ここに無いモジュールは ui 層・test 層を除きExcelトークン禁止）**: ui層・test層に加え、`modGatewayRPN`（**R3の `Application.Run` のみ**）/ `modConfig` / `modLog` / `modCaseStore` / `modCaseRead`（**案件一覧の読取のみ**。裁定書7 B-7。書込は一切持たない＝状態遷移・採番・case_data は `modCaseStore` が唯一の口）/ `modInboxStore` / `modJudgeStore` / `modKnowledge` / `modCompanyFile` / `modCompanyFile2`（`modCompanyFile` の分割先。許可の幅は同じ「企業ドシエファイルのシートI/O」）/ `modCaseStore2`（`modCaseStore` の分割先。裁定書8 A-2。許可の幅は同じ「本体ブックの案件2枚のシートI/O」） / `modCaseStore3`（同じ分割の3本目。v2.6・T-56。許可の幅は同じ「本体ブックの案件一覧とフィードバック」）/ `modExportHearing` / `modUtilText`（**`SetCellSafe` 内のセル書込に限る**。16章NFR-S7①が「セルへの書込口はこの1関数」と定めており、その関数本体だけはセルに触れざるを得ない。純変換部は `SanitizeForCell` として分離し、そちらはExcel非依存＝層(a)でテストする）の**14本**は、自身の責務範囲でのみExcelトークンを使ってよい。`modExportHtml` / `modHtmlTemplate1..n` / `modHtmlTheme` / `modPipeline2` は**不可**（案件データはstore経由で受け取る）。**`modExportPpt` は Phase 1 に実体を持たないため本列挙から外した**（v2.6・裁定書25 S9。Phase 1.5 で実装する際は、`modExportHtml` と同じく不可の側に置く）
