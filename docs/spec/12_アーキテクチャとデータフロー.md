### Step入出力契約（詳細は15章）

| Step | 入力（VBAが組立） | 注入ナレッジ（上限config） | 出力 | 後検証の要点 |
|---|---|---|---|---|
| S1 | 企業名/業種/コンテキスト/HP/有報/営業メモ/(renewal)現契約/前回更新メモ | なし | Schema-S1 | 必須キー・enum・(renewal)coverage非空 |
| S2 | S1結果(edited優先)＋コンテキスト | リスクライブラリ `kb_risk_rows`=20＋メニュー一覧(preventions用) | Schema-S2 | 件数5〜20・enum・根拠非空・preventions ID実在・(renewal)gaps整合 |
| S3 | S2結果＋コンテキスト | メニュー`kb_menu_rows`=60・種目・成功事例`kb_case_rows`=5・型ライブラリ`kb_scheme_rows`=10 | Schema-S3 | **ID実在（menu/line/型）**・3本・kind enum |
| S4 | S1+S2+S3結果 | なし | Schema-S4 | 5枚・質問≤10 |
| PF | 投函本文 | 判断基準・カタログ要約・型/パターン一覧・研究中テーマ | Schema-PF | enum・類型T妥当 |
| WT | 収集テキスト貼付 | パターンマスタ・型ライブラリ要約 | Schema-WT | 分類enum・パターンID実在 |
| FG | 未解決リスク群＋機構抜粋＋パターン | 機構`kb_mech_rows`=40・パターン全15・判断基準 | Schema-FG | 格付enum・文法チェック4値・パターンID実在 |

### ナレッジ注入方式（v1.0から不変）
ベクトル検索は使わない。業種コード完全一致＋`00 共通`行の決定的フィルタ→`priority`昇順で上限行数まで。該当0行は「登録なし」を明示して続行（E-09）。型ライブラリのS3注入は `対象業種` タグ一致＋`状態` が実績/採択のもののみ（候補・他社実績は座組開発PL-04でのみ注入）。

## 4. 依存規則

- 依存方向: ui → app → core の一方向。core は app/ui を参照しない
- ナレッジブックへの接続は modKnowledge のみ。書込は「新サービス候補」追記のみ（＋関心度集計は本体側シートで保持し書込まない）
- PowerPoint COM は modExportPpt のみ。COM失敗が案件状態を壊さない
- modSchemas/modPrompts* は純文字列（設定参照のみ可）。Excelトークン・Run呼出し禁止

## 5. 配置・配布

```
共有フォルダ \\...\リスク提案ナビ\
 ├ リスク提案ナビ_v2.0.xlsm   ← 利用者はローカルへコピーして使用
 ├ ナレッジブック.xlsx        ← 共有1本（管理者編集・利用者参照）
 └ 出力\                      ← PPT既定保存先（config ppt_out_dir で個人フォルダ可）
```
- config `kb_path` にUNCパス。起動時読込→切断時は前回スナップショット（本体内隠しシート）で続行可（E-08）
- 版番号は config `app_version` とHOME表示。更新は本体差替（案件データ移行はPhase 1では「案件は使い切り」割り切り、v2.1でインポート機能検討）
