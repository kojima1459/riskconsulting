# 16. エッジケースとセキュリティ設計 v2.0

エラーコード体系: E01xx=入力／E02xx=LLM経路／E03xx=JSON・検証／E04xx=ナレッジ／E05xx=出力／E06xx=環境・状態／E07xx=受信箱・ウォッチ。全て err_log 記録＋非エンジニア向け日本語メッセージ（対処つき）。

## 1. エッジケース一覧

## 2. セキュリティ設計

### NFR-S1: データ分類と投入可否マトリクス

| 分類 | 例 | ribbon投入 | 備考 |
|---|---|---|---|
| 公開情報 | HP・有報・プレスリリース | **可** | 本製品の基本入力 |
| 社内作成・顧客固有でないナレッジ | メニュー・型・判断基準・匿名化済み事例 | **可** | 登録要件: 顧客名・個人名を書かない |
| 自社保有の契約情報（現契約サマリ） | 種目・限度額・特約・保険料 | **条件付き（OQ-6）** | 確定まで**匿名化を既定**（E-31）。匿名化後は「どの企業か特定できない契約構造情報」として扱う |
| 顧客の非公開情報（商談で得た内部情報） | 財務詳細・工程・見積 | **不可（Phase 1）** | OQ-1確定まで。営業メモ欄に注意書き常設 |
| 個人情報 | 氏名・連絡先 | **恒久不可** | E-05で機械ブロック |

### NFR-S2: 認証情報
ribbon=キー概念なし。direct=キーは `%APPDATA%\RPN\api_key.txt`（ブック・config・ログ・画面への出力禁止）。ナレッジブック・本体に埋め込み秘密なし（PoCのOBF1焼き込み方式も使わない）。

### NFR-S3: ログとマスキング
err/usage/run_log に入力・生成本文を記録しない（detailは最大400字のメタのみ）。本文は case_data / pf_json のみ＝利用者ローカルのブック内。共有フォルダに置くのはナレッジ（顧客固有情報なし）と成果物PPT（利用者判断）のみ。個人名は全シート入力禁止（13章§4）。

### NFR-S4: マクロ配布統制
配布前に社内ルールに従い署名（OQ-2）。AI生成コードを利用者に実行させる仕組みは持たない（PPTは固定VBA）。

### NFR-S5: 監査可能性
全LLM呼び出しが run_log に残る（誰が・いつ・どの案件・経路・モデル・注入ナレッジ・検証結果）。LLM生出力は不変保存。PPT最終ページに「本資料はAI支援により作成した骨子を人が確認・編集したものです」を自動挿入。リボンtoolN=`リスク提案ナビ:step` で管理側ログとも突合可能。

### NFR-S6: 外部コンテンツの扱い
ウォッチで収集した記事は要約＋出典のみ保存（全文の恒久複製をしない）。生成物への他社商標の使用は「出典として言及」に限定し、提案書には自社名義の記述のみを載せる。
