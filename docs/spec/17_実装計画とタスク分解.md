## 1. 開発体制（PoC「開発憲法」踏襲）

- 司令塔（Fable）: 仕様裁定・発注・検収。実装しない
- 実装: Opus（ゲートウェイ・検証・パイプライン・COM等の難所）／Sonnet（移植・シートI/O・UI・定数化・テスト）
- 検問方式: タスク着手時に空コミット→受入条件ごとに即コミット。停止時は最後の検問から再投入
- 各実装波の完了後に敵対的レビュー1周＋Fix後もう1周
- 実装エージェント必読: docs/spec/10～17＋19、docs/06/07、PoCの移植元ファイル（12章の対応表）。**仕様との食い違いは勝手に直さず司令塔へ報告**（裁量は変数名・文言字数のみ）
- **開発憲法の正典（追随先・2026-08-28実物確定）**: 対コード規約は `product/nexus-agent:docs/dev/CONTRIBUTING.md`（§2.1 レイヤリングR1／§2.5 1モジュール約30,000字上限＝30,000字契約の正／§3 変更後に必ず通す3ゲート＝検問方式の正）。対人の作法は別レイヤー（nexus系の `CLAUDE.md` 相当）に置き、コード規約と混ぜない。B6BE7の `.claude/skills/final-gates/SKILL.md` は検問の実装形。本製品はCONTRIBUTING.md準拠。

## 4. テスト計画

1. **ユニット（modTestsPure）**: JSON抽出・検証（分岐網羅）・分割保存・整形・打切り・enum変換・採番。`run_excel_tests.ps1` で一括実行（実行と集計は `modTestRunner.RunAllPureTests`）

   **テストランナー要件（PoC modTestRunner が実害から作り直した仕様。移植後もこの3点を落とさない）**
   - ① `ReportText` は **PASS / FAIL / SKIP を別集計**で出す。**SKIPをPASSにも総本数にも数えない**（移植元では「実行環境の制限で本体を1行も実行できないテスト群」が `Check "…スキップ", True` としてPASSに計上され、件数が水増しされていた）
   - ② **期待テスト総本数 `tests_expected`** を `wintest/tests_expected.txt`（1行目に10進整数のみ）へ記録し、実行本数がそれと一致しなければ**ランナー自身がFAILを返す**（0件実行の「全緑」を成立させない）。テストを増減したコミットで同ファイルを更新するのは実装者の義務とし、更新漏れは即FAILとして現れる
     - **実装形**: ランナーは `modTestRunner.SetExpectedCount(n)` を公開し、**ハーネス（`run_excel_tests.ps1` / `tools/run_lo_tests.py`）が `wintest/tests_expected.txt` を読んで注入する**（VBA側からファイルI/Oを行わないため。W0実装済みの形を承認する）。**未設定のまま実行した場合はランナー自身がFAILを返す**（期待本数の注入漏れを「全緑」に見せない）
   - ③ SKIPが1件でもあれば、**レポートの冒頭と末尾に理由込みで全件列挙**する（何が走らなかったかがレポートだけで分かる）
   - 以後、本書で「modTestsPure全緑」とは **FAIL 0件 かつ SKIP 0件 かつ 実行本数=`tests_expected`** を指す（T-40・T-46⑤・§5-1の出荷手順と同一定義）
2. **一致検査**: 15章⇔modPrompts*/modSchemas のdiffゼロ検査（`tools/prompt_diff.py`。T-23）。13章⇔シート実体の照合スクリプト（T-02/03）。**19章⇔enum変換表の照合**（`tools/enum_check.py`。T-31。19章§3の全行を「変換表に載せる行／載せない行＋理由」へ**漏れなく分類**できることと、載せる行が `modUICase.EnumPairsCsv()` と機械値・日本語ラベル・**並び順**まで一致することを検査する。同関数の本体は静的に評価するので、表をループや条件分岐で組み立て直すと照合が落ちる＝骨抜きにできない）。**15章§11の検証ルール表⇔modValidate の照合**=表の**全ケースID（V-S1/S2/S3/S4/PF/S2C/S3C・計64件）に対して `modTestsPure` にテストが1本ずつ存在し、テスト名にケースIDを含み、ケース数と実装テスト数が一致すること**を照合スクリプトで検査する（modValidate の戻り値は各行が `[ケースID] ` で始まるため機械照合できる。実装者がケースを選ぶ余地をなくす）
3. **結合（mock）**: UC単位のシナリオ回帰（対象=**UC1～UC5・UC7・UC8・UC9**。T-40と同一集合）。決定的応答のため毎リリース実施。異常系は config `mock_fault`（15章§8.2の8値）で注入する
4. **実機（ribbon）**: new/renewal各1社完走＋validate_result集計
5. **品質評価**: ベテラン3軸ルーブリック。評価入力セットで改訂時回帰
