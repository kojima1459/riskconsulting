**この文書は、「リスク提案ナビ」を初めて使う人が、1社ぶんの提案準備を最初から最後まで通すための説明書**である。詳しい根拠や例外は 25章（利用ガイド）と、アプリ内の「使い方」タブ⑦「AIに調べさせる指示文（社内ディープリサーチ用）」にあり、本書はその2つを「作業の順番」に並べ直したものである。食い違いがあれば25章・使い方⑦が正である。

## 今日やることチェックリスト（STEP 1〜6・まずこれだけ見れば動ける）

`ナビ` を開くと、最上段の帯（コーチ帯）に `STEP n/6` といま何をすべきかの1文が常に出ている。チェックリストはこのSTEPの並びと同じである。

```
□ STEP 1: 区画①に種別・会社名・業種名・本社の場所を入れる
□ STEP 2: 区画①の標準3本（D-1・D-3・D-9）の[コピー]を1本ずつ順に押し、社内ディープリサーチへ投げる
　　　　　（各10分ほど。【1】参照。しっかり調査のときだけ）
□ STEP 3: 返ってきた文章を区画②の`調べた結果`へ[ここに貼る]。他の貼付欄も埋め、[貼ったものを保存する]
□ STEP 4: 区画③の[まとめて作る]を押して待つ
□ （待つあいだ）S1〜S4を読んで、違うところを手で直す
□ STEP 6: 区画④の[レポートを出す]と[ヒアリングシートを出す]を押す
```

かんたん調査（軽い案件）のときはSTEP 2を飛ばし、会社のホームページのコピペだけでSTEP 1・3から始めてよい。

## 全体像（5つの段階・人の作業は合計30分ほど）

```
【1】材料を集める      … 指示文を1本ずつ順に投げる（各10分ほど・人の作業5分）
【2】ナビに貼る        … 返ってきた文章をナビ区画②の貼付欄へコピペ（10分）
【3】実行する          … 区画③の[まとめて作る]を押して待つ（5分から）
【4】中身を直す        … S1〜S4のシートを読んで手で直す（ここが人の仕事）
【5】出力する          … リスクレポートHTML と ヒアリングシート（1分）
```

## 【1】材料を集める — ディープリサーチに何を打ち込むか

社内のディープリサーチアプリ（外部検索できるほう）を開き、下の指示文を**そのままコピペ**して `{{ }}` の中だけ埋める。**社内ディープリサーチは1本ずつしか動かない。1本ずつ順に投げ、各10分ほど待つ**のが正しい使い方である（同時に何本も投げられない）。

指示文の全文は**アプリの中**にある。`ナビ` の区画①に種別・会社名・業種名・本社の場所を入れると、標準3本（D-1／D-3／D-9）がすぐ下に並ぶ。[**＋ もっと調べる（あと5本）**]を押すと補助5本（D-2／D-4／D-6／D-7／D-8）も出る。文の右の[**コピー**]を押すとその1本ぶんが写る（緑色の「使い方」タブの目次の **⑦ AIに調べさせる指示文（社内ディープリサーチ用）** にも同じ雛形の全文が並んでいる）。

### 1-1. どれを投げるか（早見表）

| 案件の種類 | 投げるもの |
|---|---|
| かんたん調査（手早く） | ディープリサーチは使わなくてよい。会社HPの本文コピペだけで動く |
| しっかり調査（重要案件） | **まずD-1・D-3・D-9の3本**（使い方⑦の「まずこの3本」）。工場・倉庫・店舗のある先はD-7の地域概況も、上場企業はD-8も、業界を広く見たいときはD-2・D-4も（「必要なときだけ」） |
| 更新案件 | 上に加えて **D-6**（前回からの変化検知） |

（D-1～D-9の全文は**使い方⑦**にある。代表の3本を下にも載せる。）

### 1-2. 代表プロンプト①: D-1 企業の基礎調査（基本）

```
「{{企業名}}」({{本社所在地・業種}})について、公開情報から以下を調査して整理してください。
各項目に出典(URL)を付けてください。
1. 事業内容・主力製品・サービスと、直近の売上・利益の傾向(有価証券報告書・決算公告・信用調査系の公開記事)
2. 拠点・工場・店舗の一覧と、設備投資・新設・閉鎖の動き
3. 直近2年のプレスリリース・ニュースの要点(新規事業、提携、認証、事故・不祥事、リコール)
4. 経営体制の変化(社長交代、事業承継、M&A)
5. 採用動向(募集職種・人数から読める事業実態・人手状況)
```

### 1-3. 代表プロンプト②: D-3 リスク兆候スキャン

```
「{{企業名}}」について、リスクの兆候となりうる公開情報を探してください。
無ければ「見当たらない」と明記してください。各項目に出典を付けてください。
1. 事故・労災・行政処分・訴訟・リコールの報道
2. SNS・口コミでの評判(製品品質、労働環境、炎上の有無。傾向だけでよい)
3. 有価証券報告書「事業等のリスク」章の要点(上場時)
4. 自然災害リスクに関わる立地情報(拠点のハザード情報が公開されている場合)
```

### 1-4. 代表プロンプト③: D-9 調達・供給網（しっかり調査で必須）

```
「{{企業名}}」({{本社所在地}}・証券コード{{コード}})の調達・供給網について、公開情報から
事実のみを整理してください。
1. 主要な原材料・部品・仕入品と、その調達先地域(国・地域名まで)
2. 公表されている主要取引先・サプライヤ(有価証券報告書の「主要な設備」「関係会社の状況」、
   公式サイトの取引先紹介、プレスリリース)
3. 外注・OEM・委託製造の有無と、対象となる工程
4. 物流・倉庫の委託先、輸出入の有無(仕向地・調達元の国)
5. 直近2年の調達に関する発表(値上げ、調達先の変更・分散、内製化、供給停止・部材不足)
各項目に出典URLを付け、確認できない項目は「取得できず」、該当する事実が無い項目は
「見当たらない」と明記してください(推定による補完は禁止)。
まとめサイト・就活情報サイト・個人ブログ(note等)は情報源に使わないでください。
```

### 1-5. ディープリサーチの注意（実験で確定した限界）

| 注意 | 理由・対処 |
|---|---|
| **企業名には必ず本社所在地か証券コードを添える** | 似た名前の別会社の情報が混ざった実例がある |
| **1本ずつ順に投げる（各10分ほど）** | 社内ディープリサーチは1本ずつしか動かない。まとめて投げて放置はできない |
| 指示文は**2,000字以内** | 超えると明示エラーになる（使い方⑦の指示文は全部収まっている） |
| モードは**集中（1観点）**が既定 | 「総合」はエッセイ化して事実が薄まる。広く拾うD-2・D-4だけ標準〜総合 |
| **有価証券報告書の中身は取りに行かせない** | PDFの深部を読めず、それらしい数値を**創作する**ことが実験で確定している。有報の「事業等のリスク」章は**EDINETをブラウザで開いて該当章を自分でコピペ**する（1〜2分。体裁が崩れてもナビ側が整理する） |
| **拠点ごとの浸水深は取れない** | 重ねるハザードマップ（disaportal.gsi.go.jp）で自分で調べ、「◯◯工場: 浸水想定3〜5m」と現場メモ欄へ転記する（1拠点1分）。この一手間で提案の根拠が「一般論」から「貴社◯◯倉庫は床上浸水3m想定」に変わる |
| 返答内の重要数値は出典URLを1クリックして確認 | 「非開示」「記載なし」という説明も鵜呑みにしない |

### 1-6. 2巡目からは自動生成プロンプトを使う

一度【3】まで実行すると、S1の充足度診断が**その案件の足りない観点に合わせた調査プロンプト（research_requests）を自動で生成する**（企業名入り・コピーして投げるだけ）。D-1～D-9（使い方⑦）は初回用、自動生成は2巡目以降の穴埋め用である。これも**1本ずつ順に**投げる。

## 【2】ナビに貼る — どの返答をどの欄へ

`リスク提案ナビ.xlsm` を開き（黄色い帯が出たら[コンテンツの有効化]）、`ナビ` の帯の案件プルダウンで**何も選ばない（空のまま）**でよい。区画①を入力すると、案件IDの欄に自動で `(新規)` と出る。

まず区画①の属性欄を埋める: **種別**（新規開拓／更新）・**企業名**・**業種**（一覧から選ぶ）・本社の場所。**調べる深さ**（かんたん調査／しっかり調査）は「調べた結果」の有無で自動的に決まる（選ぶ欄ではない）。保存すると欄に「しっかり調査（貼った内容から自動で決まります）」のように出る。

次に区画②の貼付欄へ。**出典URLごとそのまま貼ってよい**（体裁の整形は不要。ナビ側のAIが構造化する）。

| 貼付欄 | 何を貼るか | 出どころ |
|---|---|---|
| 調べた結果 | **D-1～D-9の返答をここへまとめて貼る**（使い方⑦） | ディープリサーチ |
| 会社のホームページ（**必須**） | 会社概要・事業内容・拠点のページ本文 | 会社HPからコピペ |
| 有価証券報告書のリスクの章 | 「事業等のリスク」の章 | **EDINETから自分でコピペ**（ディープリサーチに頼まない） |
| いまの契約（更新時のみ表示） | 現在の付保内容 | 更新案件で区画①の種別を「更新」にすると欄が現れる |
| 現場メモ | 【営業メモ】【前回更新メモ】【付保の見立て】【そのほか】の4見出しが先置きされている。思い出した順でよい（「社長はワンマン」「工場の裏の川が気になる」）。**ハザードマップの転記もここ** | 自分 |
| ヒアリング回答 | **訪問後**に使う（【6】参照） | 訪問の手書きメモ |

- **1つの欄は約32,000字(A4で約20枚)まで**。
- [**ここに貼る**]を押すたびに字数と貼った時刻がその場で出る。貼り終えたら区画②の [**貼ったものを保存する**] を押す。案件IDがここで採番される。

## 【3】実行する

`ナビ` の帯で対象案件を確かめて 区画③の [**まとめて作る**] を押す。AIが **①企業プロファイル → ②リスク仮説 → ③提案 → ④提案骨子** の4段階で下書きを作る。

- **画面が白くなっても触らない・閉じない。** 処理は続いている。
- 終わると**画面の右上に白いカード（トースト）**が出て、次にやることが出る（「できました。④の[レポートを出す]を押してください」）。カードは文の長さに応じて3〜9秒ほどで自分で消える（長い案内ほど長く残る）。
- 品質（標準／入念）は自動で決まる: **標準**（1回で作る）／**入念**（AIが自分で批判して直す。時間は延びるが精度が上がる。しっかり調査は既定で入念）。
- 途中で止まったら「お知らせ」欄に理由が出る。「本日のAI利用枠の上限です」なら翌日に続きから。**通った段の結果は消えない。**

## 【4】中身を直す — ここが人の仕事

出来上がった `S1_企業プロファイル` `S2_リスク仮説` `S3_提案` `S4_骨子` は、区画④の[**下書きを見る**]で開き、**直接書き換えてよい**。直したら、そのシートの [S2へ進む] [S3へ進む] [S4へ進む] を押すと**その先の段だけ**作り直される。

- S1の充足度診断が「材料不足」を指摘したら、【1-6】の自動生成プロンプトで追い足して再実行する。
- 重要案件では緑色の「使い方」タブ「⑦ 上級」の[表示する]で `壁打ち` シートを出し、座組を練る（「この仮説は弱くない?」「幹事がやってない切り口は?」）。良い気づきは [受信箱へ] で商品部に届く。**ここを飛ばすとAIのポン出しになる。**

## 【5】出力する

| 出力 | 押すボタン | 出るもの |
|---|---|---|
| リスクレポート | 区画④の [**レポートを出す**] | 「お知らせ」欄に出たパスのHTMLファイルをダブルクリック。**5×5のリスクマップとカバレッジ表**が絵で出る。1ファイル完結なのでメール添付でも崩れない。同じ日に出し直しても前のファイルは消えない（`_2` `_3` と別ファイルになる） |
| ヒアリングシート | 区画④の [**ヒアリングシートを出す**] | 質問一覧（回答欄は空）。**Ctrl+P でA4縦1枚**に印刷し、訪問先で手書きで埋める |

どちらのボタンも、押すと**画面の右上に白いカード（トースト）**が出て次にやることが出る（レポートは「レポートを出しました。次は④の[ヒアリングシートを出す]です」、ヒアリングシートは「ヒアリングシートができました。Ctrl+Pで印刷できます」）。カードは文の長さに応じて3〜9秒ほどで自分で消える（長い案内ほど長く残る）。

レポート末尾の「本資料はAI支援により作成した骨子を人が確認・編集したものです」の注記は**消さない**。

## 【6】訪問後 — 聞いてきたことを返して精度を上げる

1. `ナビ` の帯で対象案件を選び、区画②の「ヒアリング回答」に聞いてきた内容を貼り、[貼ったものを保存する]。
2. 区画④の[下書きを見る]から `S2_リスク仮説` の[S2から再実行]を押す（区画③の[まとめて作る]でもよい）。
3. レポートとヒアリングシートを出し直す。
4. 商談の結果は、緑色の「使い方」タブ「⑦ 上級」の[表示する]から `フィードバック` シートを出して[商談の記録を保存]（5分）、`判断台帳` シートで[判断を起票]に残す。**ここに残した事実が月次で「型」に昇格し、翌月から全員の提案が賢くなる。**

> **前のラウンドを残したいとき**: 上の手順に入る前に、帯の[使い方を開く]→「使い方」タブ「⑦ 上級」の[**第2ラウンドを始める**]を押す。確認で[はい]を選ぶと、いまのS2が「前のラウンド」として控えられ、何巡目かが1つ進む。押さずにS2を作り直すと前の内容は残らない（上書きされる）。

## やってはいけないこと（4つだけ）

1. **赤い帯**（「デモ／開発経路で動作中です」）が出た状態の出力をお客様に見せない。
2. **個人名を入力しない**（混ざると確認が出る。伏字にして保存する）。
3. **AIの出力をそのまま提出しない**。必ず読んで直す。
4. **実行中にブックを閉じない**。

## 困ったとき

25章§12「困ったときの1行対処」を見る。それでも分からなければ、**その画面のまま**開発担当へ連絡する（自分で直そうとしなくてよい）。緑色の「使い方」タブにも同じ内容がある（⑤ 困ったとき）。警告に「（err_logタブの最後の行を開発担当へ送ってください）」と出たときは、`err_log` タブの最後の行をそのままコピーして送る。
