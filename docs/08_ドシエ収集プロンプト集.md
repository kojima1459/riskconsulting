# 08. ドシエ収集プロンプト集（T2フルドシエ用・ディープリサーチ社内アプリ向け）

**用途**: 重要案件（T2フルドシエ）の情報収集を、人手のコピペからAI収集に変える定型プロンプト集。外部検索可能なディープリサーチ社内アプリに投げ、返答をリスク提案ナビの貼付欄へコピペする。**公開情報のみを対象とし、顧客の非公開情報・個人情報は扱わない**（アプリの利用規約準拠）。
**位置づけ**: 製品同梱ナレッジ（利用ガイドに転載）。プロンプトは運用で改良し、良い版をここに還流する。

## 使い方

0. **v2.3から**: S1実行後に「追加収集」欄へ、この案件の不足観点に合わせた**調査プロンプト（research_requests）が自動生成される**（企業名・拠点名を埋め込み済み・コピーして投げるだけ）。D-1〜D-7は初回収集用の雛形、research_requests は2巡目以降の穴埋め用——という使い分け
1. 対象企業を決めたら、下のD-1〜D-8を必要な分だけディープリサーチに投げる（遅いので**まとめて投げて放置**が正しい使い方）
1x. **実UI確認済み（2026-08-28スクリーンショット）**: 入力は「指示文」欄＋「調査の広がり」の3択（集中=1観点／標準=2観点・既定／総合=3観点）。**入力または出力に約2,000文字の制限あり**（伝聞・要確認）→ 本書のプロンプトとresearch_requestsは**2,000字以内**で設計する。**処理は最大約10分でタイムアウト**（超過するとレポートが出ずエラー）→ 1回の調査範囲を10分で終わる粒度に絞る。モデルはAIリボンと同一のAzure OpenAI系（GPT-5.5と推定・非公開）
1y. **モードの使い分け（2026-08-28検証済み）**: 「総合（3観点）」は複数の浅い調査を統合するため**エッセイ化して事実密度が下がる**。事実収集（D-1/D-8）は**集中（1観点）×1社1テーマに分割**を既定とし、広く拾う偵察（D-2/D-4）のみ標準〜総合。**分析・比較はディープリサーチにやらせない**（ナレッジと突合するのはナビ側S1/S2の仕事。ディープリサーチは事実の運び屋に徹させる）
1z. **信頼できる範囲の実測（三菱電機D-8実験の結果）**。プロンプトで強制しても直らない限界が3つある:
   - **○ 信頼可**: 決算短信サマリー・プレスリリース・公式ページの表層に載っている数値（連結売上・営業利益・自己資本比率の3期推移は完全一致）。「取得できず」も正直に言える（設備投資・工場一覧で確認）
   - **× 信頼不可**: 有報・短信PDFの**深部**（セグメント注記・リスク章全文・設備投資の内訳）。PDF深部を読めず、**それらしいセグメント名と数値を「概算」と称して創作**した（実物: インフラ/インダストリー・モビリティ/ライフ/ビジネスプラットフォーム/セミコンダクター・デバイス→出力: 旧名混じりの架空5区分・数値も架空・同一レポート内で営業利益516億/3,918億の自己矛盾）。**推定禁止と書いても破る**
   - **△ 部分的**: 情報源固定は効きが甘い（note.com・就活サイトが混入）。「はじめに/目次/結論」のエッセイ外装も禁止指定を貫通して残る（出力テンプレが固定）
   → **結論: 有報の中身はディープリサーチに取りに行かせない**。上場企業はEDINET/公式IRから営業が該当章をコピペ（1〜2分。S1が構造化するので体裁不要）またはPDF直接取込（FR-47・Phase 1.5）を正とする。ディープリサーチの担当は「ニュース・業界動向・拠点/ハザード・決算ハイライト」まで
   - **社名の同定ミスに注意**: 類似名の別会社（例: 三桜工業に対する三桜電気工業）の情報が混入した実例あり。**プロンプトには必ず本社所在地か証券コードを併記**する。S1側でも会社同定の矛盾チェックがかかるが、入口で防ぐのが安い
   - **事実が乏しいお題は危険**: 該当事実が無いテーマ（例: リコール事例が実在しない会社の「リコール対応」）を与えると、周辺の無関係な事実（会計システム導入等）を**お題に強引に紐付けた作文**を返す。「該当事実が無ければ『見当たらない』と書け」を必ず入れる（D-3は対応済み）
1a. **リテール先（未上場）の標準ルート**: 有報が無くても D-1〜D-4/D-7 はそのまま使える（ディープリサーチは信用調査系公開記事・地元紙・自治体・業界団体情報を拾ってくる）。財務は決算公告（公開情報・投入可）＋帝国DB要約で代替し、取れない情報は責めずにヒアリングシートへ回す。**リテールこそ初回は薄く・対話で育てる**（マルチラウンドが主戦場。FR-46）
1b. **未上場企業は帝国DB企業検索を併用**（社内業務利用可・OQ-8解決済み）: 財務概況・従業員数・取引先・代表者の要点を確認し、**人手で要約して**現場メモ/財務欄に転記（本文の直接貼付はOQ-9確認まで控える）。上場企業はEDINETの有報（ディープリサーチでも取得可だが遅いため、急ぎはブラウザでEDINET直行が速い）。決算公告・官報も同様に要点転記
2. 返答をそのまま案件入力の貼付欄へ（出典URLごと貼ってよい。S1が構造化時に整理する）
3. T2の目安: D-1〜D-4は必須、**D-7は工場・倉庫・店舗を持つ先なら必須**（財物・BCP提案の根拠になる）、D-5/D-6は案件性質次第。所要は放置時間込みで1〜2時間、人の作業は15分

## D-1. 企業ドシエ（基本）

```
「{{企業名}}」({{本社所在地・業種}})について、公開情報から以下を調査して整理してください。
各項目に出典(URL)を付けてください。
1. 事業内容・主力製品・サービスと、直近の売上・利益の傾向(有価証券報告書・決算公告・信用調査系の公開記事)
2. 拠点・工場・店舗の一覧と、設備投資・新設・閉鎖の動き
3. 直近2年のプレスリリース・ニュースの要点(新規事業、提携、認証、事故・不祥事、リコール)
4. 経営体制の変化(社長交代、事業承継、M&A)
5. 採用動向(募集職種・人数から読める事業実態・人手状況)
```

## D-2. 業界・競合

```
「{{企業名}}」が属する{{業界名}}業界について調査してください。各項目に出典を付けてください。
1. 業界の市況・需給・価格動向(直近1年)と中期の構造変化(規制、技術、需要側の変化)
2. 主要競合3〜5社と、対象企業のポジション(規模・強み・弱み)
3. この業界で直近2年に起きた重大事故・リコール・訴訟・炎上の事例
4. この業界に影響する法改正・制度変更(施行済み・予定)
```

## D-3. リスク兆候スキャン

```
「{{企業名}}」について、リスクの兆候となりうる公開情報を探してください。
無ければ「見当たらない」と明記してください。各項目に出典を付けてください。
1. 事故・労災・行政処分・訴訟・リコールの報道
2. SNS・口コミでの評判(製品品質、労働環境、炎上の有無。傾向だけでよい)
3. 有価証券報告書「事業等のリスク」章の要点(上場時)
4. 自然災害リスクに関わる立地情報(拠点のハザード情報が公開されている場合)
```

## D-4. マクロ・時事の接続

```
{{業種名}}の{{企業規模}}企業にいま影響しているマクロ環境・時事を整理してください。
1. 為替・金利・原材料価格・エネルギーコストの影響
2. 人手不足・賃上げ・労務規制の影響
3. サイバー攻撃の業種別動向(この業種が狙われている手口)
4. 直近3ヶ月の時事で、この業種の経営者が気にしているであろう話題を3つ
```

## D-5. 座組・パートナー探索（scheme提案・裏受け候補向け）

```
{{リスク/課題}}に対して、検知・予防・復旧のサービスを提供している日本の企業・スタートアップを
5社程度探してください。各社について: サービス内容/実績・導入例/保険会社との提携有無/
提携が公表されていない場合は「確認できず」と明記。出典を付けてください。
```

## D-7. 拠点ハザード調査（hazard観点。財物・BCP提案の根拠づくり）

```
「{{企業名}}」の以下の拠点について、公開されているハザード情報を拠点ごとに整理してください。
対象拠点: {{拠点リスト（名称・住所）}}
1. 洪水・内水氾濫の浸水想定（想定浸水深が何mか）— ハザードマップポータル・自治体ハザードマップ
2. 土砂災害警戒区域・特別警戒区域の該当有無
3. 地震の想定（想定震度・液状化リスク・近傍の活断層）と津波・高潮の想定
4. その地域の過去の被災履歴（水害・地震被害の報道）
各項目に出典(URL)を付け、確認できない拠点・項目は「情報なし」と明記してください。
```

**手動の代替/補完**: 重ねるハザードマップ（disaportal.gsi.go.jp）で拠点住所を検索し、「◯◯工場: 浸水想定3〜5m・土砂警戒区域外」のように要点を現場メモ欄へ転記する（1拠点1分）。この一手間で、S2の自然災害リスクが「一般論」から「貴社◯◯倉庫は床上浸水3m想定」という刺さる根拠に変わる。

## D-8. 決算ハイライト抽出（上場企業・集中モード・v2）

**狙い**: 一次情報（短信・公式IR）の**表層に載っている数値と事実だけ**を運ばせる。v1実験（三菱電機・2026-08-28）で有報深部（セグメント注記・リスク章全文・設備投資内訳）は**読めずに創作する**ことが確定したため、深部項目はD-8から**外した**——それらはEDINETコピペまたはPDF取込（FR-47）で取る（上の1z参照）。返答はそのままS1貼付欄へ。

```
「{{企業名}}」(証券コード{{コード}}・本社{{本社所在地}})について、{{直近決算期}}の決算短信・決算説明会資料・プレスリリース・公式サイト({{公式ドメイン}})だけを情報源として、以下を事実のみ抽出してください。
箇条書きと表のみで出力し、「はじめに」「目次」「結論」の文章は書かないでください。まとめサイト・就活情報サイト・個人ブログ(note等)は情報源に使わないでください。
1. 連結の売上高・営業利益・純利益・純資産・自己資本比率(直近3期の推移。単位と年度を明記)
2. 直近決算の会社発表ハイライト(増減の要因として会社自身が説明している事項)
3. 今期の会社予想(売上・利益)と、公表されている中期経営計画の骨子
4. 直近1年の大きな発表(М&A・事業譲渡・新工場・大型投資・提携・自社株買い等)を日付つきで列挙
5. 従業員数と平均年間給与(記載元の資料名を明記)
各数値に年度を付け、取得できない項目は「取得できず」、該当事実が無い項目は「見当たらない」と明記してください(概算・按分・推定による補完は禁止)。各項目に出典URLを付けてください。
```

**運用ルール**:
- 1回=1社・集中（1観点）モード。2社比較を1回で作らせるのは禁止（**比較・差分抽出はナビ側の仕事**）
- 証券コードと本社所在地は必ず埋める（類似社名の別会社混入の実例あり）
- セグメント別数値・「事業等のリスク」章・設備投資内訳が必要なとき（T2は通常必要）→ **EDINETか公式IRのPDFから該当章をそのままコピペ**して貼付欄へ（1〜2分。表が崩れてもS1が構造化するので体裁は不要）。ここをディープリサーチに頼むと創作が混ざる
- 返答内の数値は「短信の表層数値=信頼可／それ以外=要検証」として扱い、重要数値は営業が出典URLを1クリックして確認する

## D-6. 更新案件の変化検知（T2×renewal）

```
「{{企業名}}」について、直近{{前回更新からの期間}}の変化を調査してください。
新工場・新事業・M&A・海外展開・大型受注・人員増減・移転など、
保険の掛け方を見直すべき変化に該当しそうな事実を、出典付きで列挙してください。
```

## 重要案件の標準手順（T2×壁打ちのSOP）

```
前日〜数日前:
 ① ディープリサーチにD-1〜D-4を投げて放置(更新案件はD-6も)     …人の作業5分
 ② 返答を「追加ドシエ」欄へコピペ、HPレシピ8項目も貼る          …10分
 ③ 一括実行 → S1が蒸留(根拠つき構造化+充足度診断)              …放置5分
    充足度の指摘があれば足りない材料だけ追い足して再実行
 ④ S2リスク仮説・S3提案を眺めて、壁打ちを開始                   …30〜60分
    「この仮説は弱くない?」「ヤモリ型を当てられへん?」「幹事がやってない切り口は?」
    → 気づいたらS2/S3シートを直して当該Step以降を再実行(軌道修正)
    → 良い気づきは💡で受信箱へ
 ⑤ 納得したらS4→PPT生成、ヒアリングシートを印刷
訪問後:
 ⑥ フィードバックに事実を記録(5分) → 月次で型に昇格するかもしれない
```

ポイント: ③までは機械の仕事、④が人とAIの共同作業、⑥が組織の学習。**④を飛ばすとポン出しになる**——T2案件では④を必須の作法とする（利用ガイドに明記）。

## 運用メモ

- 返答の**鮮度と出典を必ず確認**する（アプリの検索結果は網羅的でない。重大案件は営業がブラウザで一次情報を確認）
- D-3/D-5の結果に他社の商標・記事が含まれる場合、提案書へは「出典として言及」に留める（16章 NFR-S6）
- ここで得た情報はすべて公開情報だが、**組み合わせた分析結果は社外秘**として扱う
