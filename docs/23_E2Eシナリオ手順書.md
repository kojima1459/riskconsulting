# 23. E2Eシナリオ手順書（mock結合・T-40）v1.0

対象タスク: 17章 T-40（E2E結合〔mock〕）。対象ユースケースは 10章§4 の **UC1・UC2・UC3・UC4・UC5・UC7・UC8・UC9** の8本であり、17章§4-3 の結合テスト対象と同一集合である。UC6（月次編集会）は PL-05/06 の Phase 1.5 タスクのため本書の対象外とする。

本書は「操作 → 期待される画面・データ → 確認点（run_log / validate_result / シート状態）」の3点セットで書く。確認点はすべて**シート上に残る事実**であり、実施者の印象ではない。1つでも不一致があればその場で記録し、シナリオを先へ進めない。

---

## 0. 前提

### 0.1 実行対象

| 項目 | 値 |
|---|---|
| ブック | `dist/リスク提案ナビ_dev.xlsm`（`python3 build/build_rpn.py --dev` で生成した開発ビルド） |

### 0.2 開始前チェック（1回だけ）

1. ブックを開き、`はじめにお読みください` シートが**自動的に非表示になり `HOME` が見えている**こと（12章§2.1 手順①が走った＝マクロが有効である証拠）。
2. `HOME` の `hm_transport_banner`（赤帯）に「デモ／開発経路で動作中です（本番の判断に使わないでください）（transport=mock）」が出ていること（16章 E-27）。**ここが空なら mock で走っていない**ので中止する。
3. `HOME` の `hm_kb_status` が「読込OK（メニューN/型N/事例N）」であること。「ナレッジが読めていません」なら `config` の `kb_path` を `dist/ナレッジブック.xlsx` の実パスへ直し、[ナレッジ再読込] を押す。
4. ナレッジブックに mock 応答が参照するID **M-0012 / L-03 / S-0004 / K-0003 / P9 / MC-0107** の行が存在すること（15章§8.1。無いと実在チェックが誤発火して UC1 が落ちる）。
5. `config` の `mock_fault` が空であること。

### 0.3 観測用シートの開き方

`case_data` / `config` / `err_log` / `usage_log` / `run_log` の5枚は非表示（hidden）である。確認のときだけ、Excelのシート見出しを右クリックして「再表示」から開き、確認が終わったら再び非表示へ戻す。

`vba_src` と `kb_snapshot` の2枚は **veryHidden**（「再表示」の一覧に出ない）であり、通常の操作では開けない。本書はこの2枚の中身を確認点にしない。

### 0.4 本書で使う観測点

| 観測対象 | 場所 | 見るもの |

| LLM呼び出しの記録 | `run_log` | 1行=1呼び出し。`step` / `transport` / `validate_result` / `injected_kb_ids` / `latency_ms` / `detail` |
